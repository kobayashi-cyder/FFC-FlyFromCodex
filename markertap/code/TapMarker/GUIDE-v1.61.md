# マーカー連打 v1.61：動画6651の遷移・復帰を修正

`MarkerTap-v1.61-video-recovery.apk` は従来と同じ署名で上書き更新できます。増えうさぎのミッション・報酬・ボーナスなどの判別と、表示が戻っても復帰要求が続く処理を修正しました。連打間隔の初期値は3msです。

## 使い始める手順

1. 「全停止」を押し、APKを上書きインストールしてください。
2. 増えうさぎを開いて「自動開始」を押してください。標準設定を使っている場合は今回の修正が反映されます。ミッション画面から開始しても、主画面の位置補正を先に済ませる必要はありません。
3. 独自編集した増えうさぎの設定を今回の標準設定に切り替える場合は、「展開」→「オートマトン編集」→「初期設定へ戻す」を使用してください。確認画面で実行すると現在の設定を退避して置き換えます。編集済みの設定は更新だけでは置き換えません。
4. 仮想画面の実行部が旧版と表示された場合は、「端末だけで接続」から接続し直し、仮想画面を開き直してください。今回の実行部の版は64です。

通常画面は「自動開始」、仮想画面は画面を開いたあとに「自動開始」または「表示中の対象を自律」を使います。「全停止」で遅延した復帰要求も取り消します。

## 動画で確認できた問題

- 50～57秒付近ではミッションが表示されているのに、主画面から判別へ進み、その後CMからの復帰処理に入っていました。
- 60～63秒付近では報酬の「獲得しました」と「閉じる」が表示されているのに、復帰要求が続いていました。61.35秒の画面はChromeへの切り替わりを示すため、報酬の一致画像には使用していません。
- 広告から別アプリの表示に移ったあと、パネルが「未登録アプリ」となり、自律OFFになる場面がありました。
- 72秒付近の停止はパネルに「全停止操作」と表示されています。この操作による停止は維持しています。

コードと動画画素の照合で、次の原因を確認しました。

1. 通常画面と仮想画面の座標差を、主画面の見出しとボタンで先に補正する構造でした。ミッションやダイアログからの開始では位置が決まらず、一致画像がある画面を未判別扱いにする場合がありました。
2. ミッション内の報酬ダイアログは、旧見出し領域の画素と一致しませんでした。閉じるボタンを単独で見つける場合があっても、報酬状態への入口を判定できませんでした。
3. 復帰要求の間隔待ち中に操作待機フラグを立てていたため、通常の画面確認が止まっていました。Chrome経由の起動や再試行にも、元の状態が現在も有効かの確認が不足していました。
4. 一度見つからなかった領域の探索間隔が、画面遷移直後の確認にも作用していました。

## 修正後の対応

| 実際に表示された画面 | 判定に使う目印 | 操作と次の状態 |
|---|---|---|
| デイリーミッション | 見出しとステージの項目名 | ミッション確認へ |
| ミッションのゲット | ミッション見出しとオレンジのゲット | そのボタンの中央をタップし、報酬表示を確認 |
| ミッションのプレイ | ミッション見出しと黄色のプレイ | そのボタンの中央をタップし、主画面の復帰を確認 |
| 獲得しました | 右側の見出しと閉じるの文字 | 閉じるの中央をタップし、表示を再判定 |
| コインアップチャンス | 見出しと「このままはじめる」 | 広告を使わず開始し、ミッションへ |
| オフラインボーナス | 見出しと通常の獲得 | 通常獲得の中央をタップし、復帰画面を確認 |
| 動画の期間告知 | 増えうさぎの告知見出しと閉じる印 | 告知の閉じるをタップし、下の画面を再判定 |

各画面の2つの目印を組にして位置を求めます。タップ座標は今回一致したボタンの位置から算出します。広告・Chrome・暗転や読込中の画面を、これらの操作ボタンの一致として扱いません。確認できないボタンの位置は推測してタップしません。

ミッション処理を始めたあとは、報酬を閉じただけでメインの連打へ戻りません。ミッションのプレイを押し、その後の主画面を確認してから戻ります。主画面のミッション通知は、位置補正したミッションボタン右側の赤い通知を小さな範囲で確認します。

復帰要求の待機中にも監視を続けます。登録アプリの画面や別の状態が確認できたら、保留中の復帰要求を取り消します。遅延した起動・再試行は、同じ実行・同じオートマトン・同じ状態への滞在が続いている場合だけ有効です。同じ状態名に入り直しても、以前の要求は復活しません。3回目の復帰でアプリのタスクを消す処理も外しています。

自律中に別アプリの表示へ移っても、未登録という理由で実行やプロフィールを破棄しません。標準設定では登録アプリへ復帰を進め、編集済みの設定ではその設定に記述された復帰処理または対象アプリの待機を続けます。

通常画面・仮想画面の既知の位置は毎回少数の候補だけを確認します。細かな位置探索だけに間隔を設け、遷移直後の見落としを防ぎます。各状態に必要な領域を使い、通常処理で全画面の位置を走査する方式にはしていません。
