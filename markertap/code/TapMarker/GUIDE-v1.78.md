# MarkerTap v1.78 — 通常連打を継続したまま強化操作を分離

パッケージ `jp.tapmarker.lite` / versionName `1.78` / versionCode `81`。
`MarkerTap-v1.78-independent-upgrades.apk` を上書きインストールしてください。v1.77以前の軽量版と署名・パッケージを維持し、マーカー、アプリ別の設定、保存済みオートマトンを引き継ぎます。仮想実行部の通信プロトコルは75を維持します。

## 操作別の動作

| イベント | 通常連打 | 専用処理 |
| --- | --- | --- |
| 通常プレイ | 最速で継続 | 通常タッパー |
| 農園うさぎのスコップ強化 | 実行状態を維持 | 強化ボタンを2画像で確認し、専用タッパーで1回送信 |
| 増えうさぎの「増える量」の増強 | 実行状態を維持 | 強化ボタンとレベル領域を確認し、専用タッパーで1回送信 |
| 強化後の表示確認待ち | 実行状態を維持 | 強化専用処理だけが結果表示を確認 |
| CM・報酬・確認画面・ミッション等の別イベント | 保留 | 対応する既存のオートマトンへ遷移 |
| 対象アプリ外・画像が1.5秒以上古い | 保留 | 新しい対象画面を確認 |
| 全停止 | 停止 | 強化の未送信指示も破棄 |

## 分離した構成

- **通常タッパー**：最速の連打を継続します。画面判定のたびに作り直さず、入力完了に合わせて次を送信します。
- **ロジカルエンジン**：CM・報酬・確認画面など、通常連打を保留するイベントを扱います。
- **強化専用エンジン／タッパー**：スコップ強化と「増える量」を独立して確認し、通常の連打対象へ混ぜずに単発入力します。

強化を通常の「強化待ち」状態への分岐から切り離したため、強化ボタンの検出・送信・結果待ちだけでは通常連打を保留しません。保存された編集用グラフは保持し、実行用のコピーで処理を分離します。既存プリセットのスコップ強化・増える量が対象です。独自に作成した別IDの強化操作は、従来の登録済みルールに従います。

同じ画面へのタッチ入力は通常タップと強化タップを順番に送ります。通常タッパーをOFFにせず、空いた入力枠に強化タップを1回差し込みます。Androidへ重なるジェスチャーを送り、互いを中断させる方式は使いません。別の仮想画面の通常連打は独立して継続します。

## 最速設定と使い方

1. 上書き後にパネルが出ない場合は、Androidのユーザー補助で「マーカー連打 軽量版」をOFF→ONにします。
2. 対象ゲームを開き、パネルの「展開」→「間隔」を押して表示を「最速」にします。旧3ms設定は最速に読み替え、明示的に保存した50/100/250/500/1000msは維持します。
3. 「自動開始」で通常連打・他イベントの判定・独立した強化操作を開始します。
4. 「状況」で、通常タッパーの送信速度と強化専用の状態を別々に確認できます。「コピー」で内容を取得できます。
5. 「全停止」で全て停止します。

最速の通常連打は1ms押下・1ms間隔を要求し、入力が完了したら追加の固定待ちを入れずに次を送ります。実際の速度はAndroid・端末・ゲーム・入力枠の使用状況によります。F-52A用の旧32ms下限は通常連打に適用しません。強化の単発入力と「タップ確認」は60msです。

「状況」の回数／秒は送信完了速度です。ゲーム内部で受け付けた回数・得点・報酬を測った値ではありません。

本体画面の「連打のみ」は判断処理を停止して通常タッパーだけを試す操作です。「タップ確認」は最初のマーカーへ60msの入力を1回送ります。通常運用では「自動開始」を使ってください。F-52Aの複数アプリ自律には、従来の仮想画面方式を使用します。

## 強化操作の確認範囲

新しい画像2枚で強化ボタンを確認してから、専用入力を1回送ります。送信完了だけで強化成功と扱わず、増える量はレベル領域、スコップは強化ボタン領域の表示変化を確認します。表示変化は効果量の増加を数値で証明するものではありません。変化が見つからない場合も、通常連打を止めずに強化専用処理で再確認します。

同じ強化を通常連打と同じ頻度で繰り返しません。表示変化を確認した後に1秒、変化が3秒間見つからなかった場合はさらに3秒の間隔を取り、改めて2枚の画像で判断します。これらは強化側だけの待ち時間です。入力中断・拒否の再試行間隔中も、強化側が入力枠を占有し続けないようにしています。

## 検証

配布APKと同じ縮小済みJavaランタイムに対し、既存回帰検査とUpgradeEngineTestを実行しました。

- 強化をメイン状態・分岐・履歴へ混ぜないこと。
- 強化の検出・送信・結果確認中に通常連打の許可を維持すること。
- 同一強化を重複送信せず、古い完了通知で復活させないこと。
- 別イベントでは通常連打を保留し、未送信の強化指示を取り消すこと。
- 最速通常タッパーへの単発入力の差し込み、同じ入力先での重複防止、他画面の独立継続。
- APKの署名、バージョン、DEXとビルドの一致、アセット、4種類のCPU向けライブラリ、16KB配置。

Android実機、とくにF-52A上の入力受付・ゲーム内の強化成立・実効速度は未検証です。仮想時間による模擬入力の速度を実機性能としては扱いません。旧4録画のfull検査には、従来通り別途のフィクスチャが必要です。
