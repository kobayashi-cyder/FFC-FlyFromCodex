# MP4保存と有限の品質改善 v7.6

PR #8 の v7.5 を継承し、同じブランチで追加する。生物データ、回路の符号仮説、伝播・系統分離は変更しない。

## MP4

動画要求は新しい意味シーンを作り、猫などの構成部品を同じ動きで移動させる。以前の画像や無関係なランダム形状を動画へ流用しない。O3パネルの手動生成・JSON取込もMP4保存できる。

`video-export.js` は生成したシーンとタイムラインを固定し、既定では768×512、24fps、4秒の96フレームをJPEGとして描く。フレームごとのJavaブリッジ応答を待って次を描く。Android `VideoExporter` はMediaCodecのH.264とMediaMuxerで実際のMP4を作る。JPEG、画素、入力バッファを動画全体分保持しない。フレーム間でUIへ処理を戻すが、従来型の同期ブリッジ呼出し中はJavaScriptが応答を待つ。

保存中・失敗・取消・完成を別の状態で表示する。代理人の処理完了はシーン生成と保存開始を指し、MP4完成とは区別する。完成と検証前に共有しない。「MP4共有」からAndroidの共有画面でファイルを渡せる。保存先はアプリcache/exports、content:// FileProvider URIで読み出す。直近5件程度を保持する一時ファイルで、長期保存は共有先で行う。

上限は同時1本、最大921,600画素・各辺1,280・偶数寸法、1〜30fps、15秒・450フレーム、JPEG 2MiB、MP4 16MiB。フレーム順、寸法、入力期限、EOSを検査する。取消・失敗は未完成ファイルを消し、放置された処理は監視タイマーで終了する。アプリ終了時の解放はUIを待たせない。

これは対応語彙の手続き的アニメーションをMP4にする機能。音声トラック、実写品質の動画合成、任意の動画素材の編集はこの変更の対象ではない。

## 候補を品質へ変える処理

コードと文書は、初回生成→検査→欠点に対応する修正→再検査を有限回で行う。同一文字列を重複して検査しない。修正が停滞すれば停止する。コード構成案を実装済みと受理せず、文書は提供された原文を保持し、資料なしの場合は確認が必要な構成案と明記する。

画像は4候補から始め、内部品質目標に届いた時点で停止する。不足時は検出した欠点から修正候補を作り、改善の停滞でも停止する。上限はfast 6 /通常10 /high14候補。最良候補の描画を再利用できる場合は最後の描画も省く。処理回数・停止理由・品質値を結果のsearchとvalidationに記録する。画像品質値はこのアプリの内部検査であり、人間による総合評価ではない。

完全一致の要求・文脈・IRをキーとする小さなLRUキャッシュを使う。文字列と描画パラメータのみを保持し、最大12件・UTF-16換算96KiB。画素や活動ログは保持しない。キャッシュでも再検査し、回路の出力ゲートを通す。接続切断時に過去の合格結果を返すことはない。本文抽出は重複を除き、質問に対応する根拠がない場合は受理しない。

## 検証

全20個のJavaScript検査ファイル、構文、manifestを検査する。ブラウザーでは6課題を実行し、MP4の96フレーム送信・絵の変化・完成/共有/取消/失敗の状態を検査する。ブラウザーのエンコーダー代替はフレーム経路の検査で、H.264検証とは区別する。

Androidの`VideoExportIntegrationTest`は実際のAVC MP4をMediaExtractor/MediaMetadataRetrieverで読み直す。フレーム数・順序・時刻・色・寸法・不完全ファイルの拒否を検査し、さらに実際のWebView→回路→動画要求→96フレーム→MP4復号を検査する。結果はPRのCIに表示し、成功した動画要求のMP4を検証artifactに保存する。端末間のコーデック差・速度・全プロセスメモリは未測定。

APK versionCode83 / versionName `7.6.0-connectome-mp4`、成果物名`BANC888-v7.6-connectome-mp4-debug.apk`。ネイティブ動画機能が必要なのでshell71 / bridge schema5 / asset schema6とし、古いシェルには新しいライブ資産を配らない。

## ホスト上の単発比較

Chromiumの同じ猫画像要求で、既存の内部品質スコア98を維持し、描画27回・約21.40秒から5回・約4.52秒へ変化した。完全一致の再要求は1回・約1.12秒。コードのcompose呼出しは3→1、文書は2→1、キャッシュ再要求は双方0回。コード・文書の小さい初回処理時間は大きく変わっていない。測定は単発で実機の速度保証ではない。原データと最終コードハッシュは `performance/adaptive-quality-host.json`。
