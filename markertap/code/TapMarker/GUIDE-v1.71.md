# MarkerTap v1.71

コイン落としの6687.mp4から、未対応の「タップ2倍」ダイアログと、操作パネルに隠れた報酬ボタンの探索位置を確認して修正しました。クリア後の回収を広告や強化画面の間も保持し、開始後の確認を共通の画面判別へまとめています。

うさぎのお店屋さん・ボックスマージ・うさポ内の農園うさぎ／風船パンチには、ゲーム別の学習設定と巡回設定を追加しました。**追加4ゲームの標準自動操作は未完成です。実画面を使った端末内の実演が必要です。** 「買い物うさぎ」と「うさぎのお店屋さん」、独立した農園うさぎとうさポ内の農園うさぎは別の設定です。

## 更新する

1. 旧版で「全停止」を押し、仮想画面を閉じます。
2. `MarkerTap-v1.71-window-relative.apk`を上書きインストールします。v1.65〜1.70軽量版と同じ `jp.tapmarker.lite`・署名です。
3. コイン落としの未編集の標準設定は自動移行します。手動編集・学習済みの設定は保持します。新しい標準設定を使う場合は「標準設定に戻す」を選択します。以前の設定は退避されます。
4. 仮想画面では実行部を起動し直し、画面を開き直してください。実行部の版も74に更新しました。
5. コイン落としを開き、「自動開始」を押します。

画像を使う自律にはAndroid 11以降が必要です。v1.64以前の `jp.tapmarker` 通常版とは別アプリです。

## コインの変更

| 場面 | v1.71の処理 |
| --- | --- |
| タップ2倍 | パネルの下にある「1タップでコインが2枚落ちてくるよ」と、そのダイアログの「CMをみてゲット」を照合します。CMボタン内を押して広告を待ちます。キャンセルやコイン投入位置へは送信しません。 |
| ゲットの左側がパネルに隠れる | 元の橙色の探索線に加え、ミッションの見出しと見えているゲット文字の右側を照合します。見えるボタン内に座標を置きます。 |
| 押下中・薄暗い報酬画面 | ゲット入力を保留します。録画の111.7〜111.8秒の未押下表示と、112秒以後の押下・暗転表示を区別して検証しました。 |
| 白い三角形と縦線の広告の次へ | 録画にある右上の塗りつぶし型と左上の輪郭型を追加しました。従来の灰白色の円内の黒い記号・白い閉じる・黄色の次へも維持します。 |
| 開始ボタンを押した後 | 専用の`bonus-wait`を共通の確認状態に統合しました。入力送信だけでは連打を再開せず、戻った主画面を2回確認します。 |
| クリア後に広告・強化画面が挟まる | 回収の用件を保持します。確認できた次ステージを開始し、主画面に戻った後にミッションを開きます。 |
| クリア後の時間切れ・未知の表示 | 回収待ちの確認へ進みます。未知の表示から投入連打へ戻しません。 |
| 未完了の赤い通知 | 通知だけでミッションを開く遷移は追加していません。通常のボーナス表示だけでも回収用件を発生させません。 |

各入力は2回の観察と入力直前の再確認を通します。広告・暗転・読み込み・画面サイズの変化があれば、古い入力と座標を取り消します。対象ウインドウの範囲から相対座標を画面座標へ変換します。以前の25種類のコイン見本は変更せず、9種類を追加しました。

## 追加4ゲームを学習する

| 対象 | アプリ／保存の扱い | 現時点の対応 |
| --- | --- | --- |
| うさぎのお店屋さん | `com.kurashiru.usagi.omise` | タップ・曲線・マーカーの実演から自動操作を作成。買い物うさぎの標準図を流用しません。 |
| ボックスマージ | `com.kurashiru.box.merge` | スワイプを曲線として記録し、ウインドウ内の相対座標で再生。コイン落としの連打図を流用しません。 |
| うさポ：農園うさぎ | `com.kurashiru.usapo`内の農園専用設定 | 学習結果・監視領域・マーカー・間隔・学習前の復元・完了条件を専用に保存。 |
| うさポ：風船パンチ | 同じうさポ内の風船専用設定 | 農園の設定を上書きせず、別の操作・判定を記録。 |

1. うさポでは、通常画面または仮想画面を開き、「対象ゲーム」で農園うさぎ／風船パンチを選びます。
2. 操作するゲームの実画面を開き、「学習開始」を選択します。うさポの巡回で入場操作も使う場合は、ゲーム一覧から実演を始めます。
3. ゲームへの入場、通常の操作、ダイアログ、ミッション回収、戻る操作などを実演します。ボックスマージでは必要な方向へスワイプします。連打を実演する場合はマーカーを配置して「マーカー実演」を使います。
4. 一周したら「学習終了・作成」を押し、作成された図を確認して「自動開始」を選びます。

表示や操作が曖昧な場合は保留します。未実演の画面・広告・操作の対応を自動で作った扱いにはしません。標準オートマトンを追加するには、各ゲームの入場から通常操作、ダイアログ、ミッション回収、終了・一覧への復帰までの実画面資料が必要です。

## デイリー完了後に次のアプリへ

各対象で、**全デイリーの達成と報酬受取済み**が明示される表示を開き、「デイリー完了を登録」で2領域を記録します。1つ目は全達成・受取済みの文字や印、2つ目は画面を特定する見出しです。うさポでは、そのゲームに固有の名前・ミッション条件を2つ目の領域に含めてください。

「デイリー巡回」は表示順で1つずつ実行し、2領域が2回一致したら次のアプリへ進みます。最後で停止します。完了の確認中は通常のプレイ・回収・時間切れ再試行を保留します。部分達成、残り0、待ち時間だけでは全デイリー完了になりません。通常画面と仮想画面の完了条件は別々に保存します。

うさポの学習設定では、記録した入場・操作の入力完了を確認してから完了判定を有効にします。開始直後に残っている別ゲームの完了画面を、そのまま今回の完了として使いません。学習を始めた画面から実行してください。

**うさポは1周につき1ゲームを選択します。** 農園うさぎと風船パンチの間でゲーム一覧へ戻り、次のゲームへ入る標準処理は、実画面未確認のため未対応です。選択したうさポのゲームから別のアプリへの巡回は設定できます。

## 検証と再ビルド

56組のJavaホストテストと、ADB起動の模擬8シナリオを実行しました。APKへ変換したものと同じ`build/shrunk.jar`が対象です。6687録画の追加203項目では、学習用の20秒・35秒・111.5秒・119秒を除いた62フレームを使い、そのうち18フレームは856×1920の原画素です。タップ2倍、広告の次へ、クリア・広告・開始・ミッション・ゲットの順序、入力前の表示変化、古い画面サイズ、相対位置、標準移行を検証しました。

既存の6682コイン380項目、F-52A増えうさぎ275項目、Pixel側171項目、農園ダイアログ245項目なども実行しました。移動・縮小・欠落の試験は合成条件です。追加4ゲームのUI、実機入力、Chromebook固有のUI、実ゲームの全デイリー終了後のアプリ切替は未検証です。旧大容量録画Video6651／6662／6666／6669の全列再生は実行していません。

検証記録：`VALIDATION-v1.71.json`、`tests-v1.71.log`、`build-v1.71.log`、`package-v1.71.log`、`tests/video6687-evidence.json`。過去の説明は`GUIDE-v1.70.md`などに残しています。
