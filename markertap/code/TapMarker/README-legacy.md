「優先順位2」「待機500ms」も追加できます。変化時中央タップ以外のフェーズルールは設定画面で編集してください。

コネクトーム由来の旧学習処理は維持します。フェーズ条件と優先処理は通常プログラムが担います。

## 自律監視とマーカー連打の併用
マーカーを配置し、自律処理の指示を設定して「自律開始」。続けて「連打開始」を押す。
自律監視を続けながらマーカーを連打します。通常の連打間隔は初期値3ms。
「連打停止」は連打だけ停止。「自律停止」は自律処理だけ停止。「終了」は両方終了。
自律側が中央タップ・曲線・登録マーカー群を操作する間、通常の連打は待機し、完了後に再開。
Androidのジェスチャー送信は同時に重ねず、完了通知で順番に実行します。
アプリ切替・画面オフ・回転は両方停止します。実際の周期はOSに依存します。

## 領域が変わったら中央をタップ
「監視領域」で長方形を指定し、「指示」に次の文を入力して保存。

監視領域が変わったら監視領域中央をタップ。

そのまま「自律開始」。経路学習、マーカー、曲線は不要です。
最初の観測を基準として登録し、領域特徴の変化量がしきい値を超えた時だけ中央を1回タップ。
初期値は変化しきい値0.004、待機800ms。例：

監視領域が変わったら監視領域中央をタップ。待機500ms。変化しきい値0.01

監視周期は待機設定に画像取得・計算時間が加わります。
タップ後に指定時間だけ待ち、次の観測を新しい基準として登録します。
この待機・基準取り直しの間の変化はタップ対象として数えません。
小さな変化は基準から累積して比較します。同じ画像で連続タップしません。
動画やアニメーションの変化も条件に該当する場合があります。
中央タップモードは条件判定プログラムで実行します。操作選択の学習を必要としません。
「完了で停止」を追加すれば、この領域で教えた完了状態で停止する機能を利用できます。
遷移記録・遷移制約・変化時停止との同時指定は矛盾または未対応として拒否します。
「自律停止」で停止。アプリ切替・画面オフ・回転・操作中断でも停止します。

## 監視領域・曲線・指示・遷移ロジック
1. 対象アプリを開き「監視領域」。変化を監視する長方形をドラッグで指定。
2. 曲線操作なら「曲線描画」で経路を描く。曲線の長さと描画時間を保存。
3. マーカー操作なら既存のマーカーを配置しておく。
4. 「指示」に対応文を入力。「解釈を表示」で操作・遷移モード・待機・停止条件を確認して保存。
5. 「経路学習」で現在の領域状態に、マーカー群または曲線を紐づけ。
6. 次の状態へ進み、必要な操作を「教える」「経路学習」「戻る学習」「完了学習」で登録。
7. 「自律開始」。領域の状態に合う登録操作を回路出力から選択。
8. 「遷移を記録」モードでは操作後に観測した別の登録状態への移り変わりを保存。
9. 「遷移ログ」で状態IDと操作の対応・遷移回数・解釈結果を確認。
10. 指示を「記録済み遷移に従う」へ変更すると、未記録の遷移で待機する。

対応指示の例（「。」または改行で区切る）：
- 監視領域が変わるまでマーカーを連打。遷移を記録。完了で停止
- 描いた曲線をなぞる。記録済み遷移に従う。待機800ms
- 描いた曲線をなぞる。監視領域が変わったら停止
- マーカーを連打。変化しきい値0.004。待機500ミリ秒

日本語の対応文法による解釈で、汎用LLMによる自然言語理解ではありません。
未対応文、矛盾する操作、矛盾する遷移モードは保存しません。
待機は250〜10000ms。変化しきい値は0.00001〜0.1。
指示の保存は既存の操作例を書き換えません。操作を切り替えたい状態で「経路学習」を押してください。
曲線描画は指示の操作部分を曲線へ変更し、待機や遷移モードの指定は維持します。
曲線は連続ドラッグとして再生します。曲線上の全点を連打する意味ではありません。
長い曲線は中間点を間引いて形を近似し、始点と最後の点を保持します。

### 領域だけを見る範囲
AndroidのtakeScreenshotは全画面の画像を返します。画像取得自体を領域限定にはできません。
特徴抽出・画面比較・コネクトーム入力・遷移判定は、指定領域の画素だけを使用。
画像は端末のメモリで一時処理して破棄し、画像そのものは保存・送信しません。
領域外の画像変化は比較結果に影響しません。
旧学習モードの領域はアプリごとに1つ。新しいフェーズモードでは名前付き領域を複数保存できます。
旧版の全画面操作例は保持しますが、新しい領域では教え直してください。
領域が変化したら連打/曲線を一時停止し、次の登録状態を待機。
監視領域が操作状態を区別できる範囲になるよう配置してください。

### 覚えるロジックの意味
アプリ名＋領域＋登録状態IDから、観測した「状態A→状態B」と回数を保存します。
因果関係や操作成功を証明するものではありません。未知状態を自動で意味付けしません。
コネクトームは領域特徴の変換と操作候補の選択を担い、プロンプト解釈・遷移記録・遷移制約は通常プログラムが担います。
記録済み遷移に従うモードは、開始時の最初の状態を自由に認識し、実行後の別状態への遷移を制約します。
画面取得・描画・Androidでの曲線再生は実機未検証です。

## アプリごとの配置と学習
対象アプリを開いて「アプリ登録」。マーカー配置・間隔・操作例をアプリごとに保存。
「追加」「教える」「経路学習」「自律開始」も現在のアプリへ自動登録します。
パネル上部に対象アプリ名を表示します。
登録済みアプリへの切り替えで、その配置と間隔を自動で呼び出します。
別アプリへ切り替えると実行は停止。戻ってきても自動再開しないので「開始」または「自律開始」を押してください。
未登録アプリでは他アプリのマーカーを隠します。「アプリ登録」で新しい配置を作成。
「全消去」は現在のマーカー配置だけを消去。「学習削除」は現在のアプリの操作例だけを消去。
学習例は1アプリ100件まで。同じ見た目の画面でも別アプリの操作は混ざりません。
旧版の学習済み操作はアプリ名による区分を継続します。
旧版の共通マーカーは最初に登録するアプリへ移行します。旧マーカーを使う対象アプリで最初の登録を行ってください。

## マーカーと自律処理を組み合わせる
1. 対象アプリで「追加」→画面タップ→「完了」でマーカーを配置。
2. 「経路学習」を押す。この画面と現在の全マーカーのIDを紐づけ。
3. 別の画面で必要な操作を「教える」「戻る学習」「完了学習」で登録。
4. 「自律開始」。登録画面では紐づいたマーカーを番号順に連打。
5. 最大300msの連打区間の後、画面を再取得して回路で次の操作を選択。
6. 画面が変わればマーカー連打を終了し、次の画面の登録操作へ切り替える。

このアプリの学習がまだない場合、マーカー設置後に「自律開始」を押すだけで
現在の画面と全マーカーを自動登録して開始します。
既に画面操作を教えてある場合は「経路学習」で明示的に登録してください。
同じ画面に単発タップを以前教えてあれば、ほぼ同一画面のマーカー学習で置き換わります。

マーカーを移動すると自律連打もその新しい位置を使います。
保存されたマーカーIDで参照し、見た目の番号が変わっても別のマーカーに入れ替わりません。
紐づけたマーカーの一部がなくなれば、そのグループの連打は待機します。
新しいマーカーを追加しただけでは既存学習のグループへ自動追加しません。
画面ごとに使う全マーカーを配置してから「経路学習」を押してください。

「教える」は単発タップ・スワイプの学習です。「戻る学習」はAndroidの戻る。
「完了学習」は終点画面の登録。到達すると自律停止。
「自律停止」で自律処理だけを停止できます。
「学習取消」で入力待ちを解除。「学習削除」を2.5秒以内に2回押すとこのアプリの学習を削除。
1アプリ最大100件。ほぼ同一の画面へ教え直すと古い登録を置き換えます。
未学習・画面不一致・曖昧な候補・画面変化中・別アプリ・別解像度では待機。
単発タップ・戻るが同じ状態で5回続くと停止。マーカー連打と曲線にはこの5回制限は適用しません。
画面オフ・回転・タップ中断でも停止。
画面取得中は約120msパネルとマーカーを隠します。取得後に戻ります。
ユーザー補助の画面取得で保護された画面は扱えません。

## 通常のマーカー連打
「追加」→画面をタップ→「完了」→上段の「開始」。複数マーカーを番号順に巡回。
停止中にドラッグ移動。「削除」モードで個別削除。
「全消去」を2.5秒以内に2回押してマーカーを全削除。
パネルの状態欄をドラッグしてパネルを移動。
間隔は3/50/100/250/500/1000ms。デフォルト3ms、タップ保持1ms。
OSの処理時間・完了通知の遅延により、実際のタップ周期は長くなる場合があります。
停止時点で送信済みの操作1回は完了する場合があります。

自律モードの単発操作後は800ms待って再観察します。マーカー連打は300msごとに一時停止して再観察します。
通常連打の3ms設定は自律判断周期ではありません。

### 限界
ハエ全脳の再現、ハエの視覚・認知の再現、汎用AI、無指導のタスク獲得ではありません。
嗅覚の配線を画面入力へ転用した工学的モデルです。符号はGABA仮説で生理計測値ではありません。
以前の人工3入力予測の学習済み重みを、画面操作の学習済みモデルとして流用していません。
学習は画面・操作の例の保存であり、内部シナプスの追加学習や自動報酬学習ではありません。
画面の意味や目的を理解しません。文字だけの違いや小さいボタンを区別できない場合があります。
画面位置が変わるアプリ、激しいアニメーション、同じ画面で別操作が必要な手順では不適合があり得ます。
回路のハエ配線固有の優位性、任意アプリでの操作精度は未実証です。

画面は端末メモリ上だけで処理し、画像自体は保存しません。
画面の色特徴、回路出力、アプリ名、操作座標は端末内に保存します。
通信権限はありません。
