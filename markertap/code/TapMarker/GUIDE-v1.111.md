# MarkerTap v1.111：320pxのキャンセル・広告復帰修正版

`jp.tapmarker.lite` / versionName `1.111` / versionCode `114` / 実行部 revision `91`

現在選択している320pxの起動設定を引き継ぎます。通常の上書き更新では設定を引き継げる、従来と同じ証明書で署名したAPKです。

## 録画とレポートで確認した事実

| 根拠 | 観測事実 |
|---|---|
| 6767.mp4 | 増えうさぎの「タップ2倍」確認で、最初はキャンセル文字が出ず、その後に表示される。使用ボタンとキャンセルの位置が別々に見える。 |
| 6767.mp4 | 農園うさぎ側にLast Asylumのプレイアブル広告が残り、元の農園画面への復帰を録画終了まで確認できない。 |
| 04:38:44の端末レポート | Pixel 10 / Android 17、仮想4画面、320×718px、124dpi。農園は主画面認識false、入力完了0回。 |
| 同レポート | 農園の元画像は161ms前、直近の判定は591ms、最後の判定画像は1357ms前。単純に画像を一切取得できていない状態ではない。 |
| 同レポートの履歴 | UIDが一致するウインドウへの入力にならず拒否された記録と、増えうさぎの表示先が`com.android.vending`へ変化した記録がある。これらは検出時点以前の履歴。 |
| 同レポートの履歴 | `IllegalArgumentException`の記録があるが、詳細メッセージとスタックが不足している。現在も同じ例外が出ているとは断定できない。 |

`STATE_STALL`の221637msは、監視側が同じ状態IDから進めないと判断した継続期間です。「状態の経過110ms」は、オートマトンが最後に同じ状態へ入り直してからの時間です。通常の復帰を繰り返して同じverifyへ戻ると、この2つの値は異なります。

## 原因候補とコード上の根拠

1. キャンセル文字の遅延と、現在の縮小配置の取りこぼし。文字の出現前に座標だけで押す方法では確実に閉じられません。
2. 通常復帰が同じActivityを再利用し、内部の広告表示が残る可能性。既存の`CLEAR_TOP | SINGLE_TOP`ではActivityへ新しいIntentを渡す動作があり、Activityの再作成とは限りません。
3. 再取得画像の変換が、複数画面の認識処理の後ろで待つ経路。旧コードでは同じ直列ワーカーへ積まれ、画像が1500msの期限を超える可能性があります。591msの仕事が4件並ぶと約2.36秒、という値は仮定に基づく計算で、全画面で591msを実測した値ではありません。
4. 広告やストアへの遷移で入力先UIDが変わる可能性。入力拒否の事実は確認できますが、個々の広告SDKの内部ウインドウ構造までは確認していません。

このレポートだけで根本原因を一つに確定することはできません。

## 実装した対応

- 「使用する」と「キャンセル」の独立した文字領域を、現在の画像で両方確認してからキャンセルを押す。文字の未表示・片方の欠落は操作を保留する。
- キャンセル確認中は通常連打・ミッション操作・増える量の強化を保留し、送信後は表示の消失を再確認する。
- 今回のプレイアブル広告はロゴと下部の説明文字で識別する。背景やジョイスティックの動きを待機時間のリセット理由にしない。
- 閉じる印を優先し、同広告が続く場合は対象画面へのBackを2回試し、登録したゲームへの通常復帰へ進む。通常復帰後も新しい画像で残留を確認した場合は、対象ゲームのタスクを再起動する。
- タスク再起動は同じ広告区間で最大2回、30秒間隔。送信・再起動要求をゲーム復帰や報酬加算の成功として扱わない。未保存のプレイや広告報酬は復元できない場合がある。
- 実スクリーンショットの変換を認識ワーカーから分離し、複数画面の認識待ちによる画像失効を減らす。
- 古くなった復帰要求にもキャンセル通知を返し、処理中のまま残らないようにする。
- 領域判定で失敗した場合の詳細メッセージを診断へ残す。

共通復帰の対象は、増えうさぎ・農園うさぎ・コイン落とし・お店屋さん・ボックスマージ・ポイポイうさぎです。通常連打への復帰には、それぞれのゲームの主画面と操作対象の再認識が必要です。

## 更新手順

1. 現行版の「全停止」を押す。
2. `MarkerTap-v1.111-cancel-playable.apk`を上書きインストールする。
3. 「端末だけで接続」から更新済みの実行部へ接続し直す。PCのADBを使う場合も新しいAPKから実行部を起動する。
4. 起動幅320pxを確認して、対象ゲームを開き「自動開始」を押す。

今回の変更には実行部の更新が含まれます。旧revision 90の実行部は、新APKから接続し直す必要があります。

## 検証範囲

6767の表示画像、既存ゲームの保存画像、模擬時刻・入力完了通知・縮小画像を使ったJVM試験と、APKのビルド・署名・同梱内容を確認します。最終結果はソース内の`tests-v1.111.log`、`VALIDATION-v1.111.json`、`apk-verification-v1.111.json`を参照してください。再実行用は`verify-v1.111.sh`です。

6767の見えているプレビューは294×660pxです。端末内の320×718pxという情報はユーザーの申告と診断レポートによるもので、動画から生のImageReader画像を回収したものではありません。320pxの画像試験は保存画像からの変換を含みます。

Android実機は接続していません。更新APKを導入したPixel 10での4画面連続稼働、実際のキャンセル到達、広告終了、ゲーム完了・報酬加算は未確認です。Last Asylum以外のプレイアブル広告には、従来の閉じる検出・戻る・通常復帰が適用されます。
