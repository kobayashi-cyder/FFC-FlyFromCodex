# 計算規模と専任化の比較

## 結論

今回の条件では、計算単位を増やすだけでは誤差は減らなかった。学習回数を増やした効果は確認できた。これは特定の課題・初期化・学習率の結果であり、大規模モデル一般の限界を示すものではない。

## 条件

- 課題：sin(3x) と x² を順に学習。既知の処理ラベルで出力先を選ぶ。
- 共有モデル：共通の非線形計算単位と二つの出力。専任モデル：二つの独立した計算単位群。
- 両モデルの重み・バイアス数を一致させた。生物の細胞数ではない。
- 各条件20乱数シード、学習入力81点、評価入力103点。評価は入力範囲内の補間。
- 学習率は 0.4 / 計算単位数、出力重みの初期化は 0.2 / √計算単位数。規模に応じて学習率が下がるため、学習速度との交絡がある。
- 更新回数は同じだが、計算量・時間・電力は同一ではない。学習率の最適化、データ量の拡張、リプレイによる忘却対策は未比較。
- 先の100シード実験と学習率・初期化が異なるため、数値を直接比較しない。

## 結果

誤差は二つの課題の評価平均二乗誤差。小さいほど良い。

|専任側の単位数（各処理）|総パラメータ数|各課題の更新回数|共有の平均誤差|専任の平均誤差|専任が勝った試行|
|---:|---:|---:|---:|---:|---:|
|16×2|98|400|0.093594|0.087196|17/20|
|16×2|98|1600|0.051306|0.015177|20/20|
|32×2|194|400|0.096426|0.093163|16/20|
|32×2|194|1600|0.051410|0.033972|19/20|
|64×2|386|400|0.098632|0.097006|15/20|
|64×2|386|1600|0.060535|0.052339|19/20|
|128×2|770|400|0.098480|0.098054|11/20|
|128×2|770|1600|0.060424|0.059450|14/20|

98パラメータの専任モデルでは、400更新から1,600更新へ増やすと誤差は0.087196から0.015177へ低下した。一方、1,600更新のまま770パラメータへ拡張すると0.059450だった。規模だけから誤差の低下を断定できない。

## 何を示していないか

この実験はBANCの全回路、ニューロンの発生・分裂、消費電力、任意の未知機能の獲得、Android実機の性能を検証していない。専任化は外部から与えた処理ラベルで選択する。生成法則の生物学的な正しさの証明ではない。

## 経験・思考・前頭前野との関係（補足）

学習は、経験などによって、その後の行動や判断が変わることです。人間は直接試すことに加えて、観察や説明から学び、記憶を振り返り、結果を想像することもできます。ただし、想像の前提が間違っていれば予測も間違うため、内部で試すことだけでは正しさを保証できません。

料理なら、実際に作って味を確かめるのが直接の経験です。「前回は塩を入れすぎたから、今回は減らそう」と考えるのは、記憶を使った予測です。

前頭葉は脳の前側の広い領域で、前頭前野はその一部です。前頭前野は他の脳領域と協力し、目的や必要な情報を保つ、行動を選ぶ、不要な反応を抑える、結果に応じて方針を変えることを支えます。料理の例なら「薄味にしたいという目的を保ち、味見してから塩を足す」といった使い分けです。

これは、前頭前野だけが記憶や思考実験を担うという意味ではありません。海馬などを含む複数の領域の連携が必要です。「学習の効率を上げるためだけの部品」と捉えるより、「経験や予測を目的に合わせて使うのを助ける」と考える方が適切です。

計算モデルでも、目的保持・記憶の再利用・予測・候補選択・修正を組み合わせることはできます。ただし、それを「前頭前野相当」と呼んでも、生物の前頭前野を再現した証拠にはなりません。ハエに人間と同じ前頭前野や思考実験を前提とすることもできません。

学習コストが下がれば、同じ予算で多くの更新を試せる可能性がありますが、賢さが比例して増えるとは限りません。同じ予算で未知課題の精度と記憶保持を測る必要があります。

この補足は概念説明です。上の計算実験は、これらの脳領域の働きや生物の発達法則を検証したものではありません。今後の検証結果は、実測結果・仮説・未検証の範囲を分けて追記します。

## 疎な生成回路の大規模実行（追加検証）

各計算単位から近距離24本とランダム2本の接続候補を作り、ランダムな符号付き重みで32ステップの活動計算を行った。各規模は独立生成であり、同じ個体の成長を追跡したものではない。

|単位数|一意な有向接続数|生成時間（秒）|32ステップ（秒）|主要配列容量（MiB）|
|---:|---:|---:|---:|---:|
|1,024|26,583|0.004|0.001|0.23|
|4,096|106,452|0.010|0.003|0.91|
|16,384|425,930|0.043|0.015|3.62|
|65,536|1,703,901|0.169|0.063|14.50|
|153,962|4,002,956|0.429|0.220|34.06|
|1,000,000|25,999,950|4.091|2.223|221.25|

約15.4万単位・400万接続、および100万単位・約2,600万接続で動作した。各規模でランダム16組への到達を確認したが、全組の到達性や故障耐性の保証ではない。主要配列容量は重み・疎行列索引・位置・入力・活動の合計で、生成中の一時配列やプロセスのピークメモリは含まない。測定はホストCPU上の単発実行で、APK端末の速度や消費電力ではない。

これにより大規模な疎回路の生成と活動計算の実行可能性は確認できた。BANCの元の重み、全v888回路、発達・増殖・削減の連続過程、学習精度の改善を再現した結果ではない。復元表の約400万行は領域別集計行で、この生成回路の一意な接続数と直接同一視できない。

再現には NumPy と SciPy を使い、`OPENBLAS_NUM_THREADS=1 python3 sparse_scale.py` を実行する。

## 確認状況（追加）

### 確認済み

- 配布済み v7.14 APK の署名検証と、同梱マニフェストに記載された全アセットのSHA-256照合。
- 配布APKから抽出した関数生成・学習コードで、例からの学習、未提示入力の実行、保存後の再読込、O0固定、評価時の重み固定を検証。
- ソース上の学習・実行関連19テストと、APK抽出コード1テストが成功。ソース試験と配布物試験は区別した。
- 細胞削除後のノード・接続の整合性、保護した端点、重複・不正接続の検査。
- 成長時の複製で、摂動を加える前の出力を誤差1e-12未満で保持すること。
- 記録した数値結果に非有限値がないこと。
- 疎回路を全6規模で再生成し、100万単位まで接続数・到達結果・平均活動・主要配列容量が一致したこと。時間は実行ごとに変動するため一致対象ではない。

### 未確認・限定された確認

- Android実機、実A1111サーバー、実際の消費電力は未確認。
- ブラウザーでの自由会話の包括的な検証は完了していない。会話の文脈引継ぎの限定テストが通ったこととは別。
- 大規模回路の学習精度・故障耐性・連続的な増殖と削減は未確認。大規模実行は生成と32ステップの活動計算の確認。
- 生物の発達法則・BANC v888全回路との同等性・任意の未知機能の獲得は示していない。
