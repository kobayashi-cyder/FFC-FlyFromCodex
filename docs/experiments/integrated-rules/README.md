# 生成・動作・学習と変更レビューの統合実験

ホスト上の合成計算回路で、候補作成 → 学習 → 評価 → 採用 → 保存・復帰を接続し、実行した。Android APKやBANC v888の全回路へ統合した結果ではない。

## 実装した流れ

- 生成則：計算単位を複製し、出力重みを半分にして元の関数を保持する。寄与の小さい単位を削る候補も作る。
- 動作則：入力重み・バイアス・tanh活動・出力重みで出力を計算する。
- 学習則：学習例との誤差からSGDで重みを更新する。
- PR相当：本体の状態を残し、候補に基準版のハッシュを記録する。
- レビュー：別の検証入力で誤差と単位停止時の誤差を比較する。
- マージ相当：基準版が現在の本体と一致し、評価後に候補が変わっていない場合だけ採用する。
- リバート相当：重み・単位ID・学習更新数を記録済みの状態へ戻す。試験で消費した総予算は戻さない。
- 保存・再読込：履歴と候補をJSONへ保存する。

二つの候補が同じ基準版から分岐した場合、一方を採用すると他方は古い候補として拒否する。自動で競合を解決するのではなく、新しい本体に対する候補作成と再評価が必要になる。

## 実行結果

課題は sin(3x) + 0.3x²。学習81入力、変更の判断61入力、最終評価151入力を分けた。単一初期化の実行例であり、多数の課題に対する優位性の証明ではない。

学習候補・増殖候補・削減候補が採用され、隠れ計算単位は8 → 16 → 12へ変化した。最終評価MSEは0.530050から0.134145へ下がった。ただし通常の追加学習も行ったため、この低下を増殖や削減だけの効果とは言えない。以前の同予算比較では自動増殖・削減が小さい固定回路に劣る結果も出ており、その結果を覆すものではない。

単位停止試験は、8種類の乱数初期化で少なくとも一つの単位の出力をゼロにする簡易試験。実際の配線故障、全故障条件、電力や生物の安全性を保証しない。

## 確認済み

五つのテストで、候補と本体の分離、採用、状態復帰、保存・再読込、古い候補の拒否、未評価候補の拒否、評価後に変更された候補の拒否、明らかに悪化する候補の拒否、増殖時の単位IDと元の出力の保持を確認した。

## 再現

Python 3 と NumPy を使用する。

```bash
OPENBLAS_NUM_THREADS=1 python3 test_integrated_rules.py
OPENBLAS_NUM_THREADS=1 python3 integrated_rules.py
```

実行すると integrated-checkpoint.json と integrated-results.json を生成する。基準回路は人工の二層モデルで、BANCの生理学的重みやニューロン発生則を使っていない。自由な会話、任意の機能、並行実行のロック、実機、APK統合は未実装・未検証。
