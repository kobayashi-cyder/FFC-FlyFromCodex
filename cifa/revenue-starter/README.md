# CSV整形・品質検査スターター（受託デモ v0.1）

Python標準ライブラリのみ。顧客に提供するCSV整形の最小実装例。架空の商品データを利用し、実在する顧客情報は含みません。

## 実行

```bash
python3 csv_cleaner.py --input examples/products.csv --config examples/config.json --output demo_output
python3 -m unittest discover -s tests -v
```

出力ファイル：

- `cleaned.csv`：列マッピング・空白正規化・非負数値検査を通過した行
- `rejected.csv`：確認が必要な行と理由、元のCSV行番号
- `report.json`：入力SHA-256、文字コード、正常件数、要確認件数、ワークフロー段階

入力はUTF-8/UTF-8 BOM/CP932、出力はExcelで扱いやすいUTF-8 BOMのCSV。
`config.json`で入力列→出力列の対応、必須列、数値列、重複キーを変えられます。Excelで数式として実行されうる文字列は、出力時（正常行・要確認行）に先頭へ `'` を追加します（入力値から変化する点に注意）。入力CSVと出力ディレクトリは別にしてください。

## 想定受託商品と対象範囲

**試験価格5,000円／1パターン**：顧客提供の1種類のCSV（最大1万行程度を提案上の初期スコープ）を指定列に変換し、必須項目・重複・非負数値の検査結果と実行手順を納品。件数上限は契約時の合意事項であり性能保証ではありません。顧客データは契約・機密保持・許諾確認後に扱うこと。顧客側で最終照合・本番システム投入を実施。

未対応：Excel .xlsx、PDF/OCR、任意サイトのスクレイピング、Webへの自動アップロード、画像項目の検査、仕様不明の複雑な帳票、決済や法令対応の自動保証。これらは別見積もり。

## CIFAとの接続候補

処理を `read → map → validate → deduplicate → export → audit` のステージとして監査レポートに記録します。将来的なCIFAの状態遷移・再試行・エラー復旧モジュールにつなぐための**受託側の土台**です。現時点でCIFA本体へ統合した実績や自律エージェントの実装を意味しません。

## 品質・安全

- 行番号と要確認理由を保持。未知の入力列や重複ヘッダーではエラー停止。
- 先頭ゼロ付き商品番号は文字列として扱い維持。
- CSVインジェクション対策はExcel表示の補助。顧客環境で別途確認が必要。
- 個人情報の入力は標準デモでは不要。外部送信・ネットワーク通信はしません。
- 実運用前に実CSVの仕様、期待値、差分を顧客と照合してください。

## 検証範囲

`python3 -m unittest discover -s tests -v` でテスト。サンプルを実行した結果は別途生成した `demo_output/` にあります。これはテスト済みの小規模試作品であり商用実績・受注実績を意味しません。
