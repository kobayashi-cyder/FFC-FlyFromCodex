# MarkerTap v1.152 autonomous refresh — development candidate (not an APK)

Status 2026-11-03: Java policy implemented and 26 assertions pass. Android integration source has been wired and CI compile is being validated. No v1.152 signed release or Pixel 10 device acceptance exists.

## Changes
- Each VirtualWindows.Window owns a VirtualRefreshPolicy with independent 10-minute budgets and at most two display recreations.
- Stale screenshot recovery: request fresh frame before recreating the affected virtual display. Black pixels alone are not an error.
- Validated network outage or game DNS error: wait, do not restart the game. Remote server/DNS errors are not repaired by display recreation.
- Unexpected one-display removal: if the backend binder still lives, recover one display without clearing the other; if the backend dies, preserve existing global safety stop.
- Manual status dialog refresh menu: recapture image or recreate only this virtual display.
- Failed recreation quarantines the affected window, not the other input lanes.
- Host regression and Android-source compilation checks run in CI.

## Evidence and caveats
- The distributed v1.151 APK is produced with a pinned DEX patch of signed v1.150, not directly from this historic source snapshot. These source changes are NOT in a signed v1.152 APK.
- Host tests cannot verify actual Pixel 10/Android 17 behavior, Shizuku, DNS in games, advertisements, reward collection, or continuous progress.
- A bytecode-audited DEX integration or equivalent full build, original signing certificate, and real-device acceptance remain required before replacing v1.151.
- Acceptance: 1/2-display modes, 20 minimize/restore cycles per window, independent recovery after one lost display, 60 minutes with zero false recovery, DNS outage with zero relaunches, bounded recovery loops, real ad/reward progression.
