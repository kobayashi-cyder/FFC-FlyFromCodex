# MarkerTap v1.72 録画生成と編集の統合版

APK自身が端末の録画ファイルを読み込み、同じ表示を状態に統合し、観測された遷移と判定領域を作成します。画像上で確認したタップ・スワイプだけを登録し、操作後の表示確認を経て次へ進みます。

別チャットのv1.71のコイン修正と追加ゲームの保存先を、検索・複製・取消・元に戻す・やり直す・退避を備えるかんたん編集と統合しました。版は1.72、versionCodeと仮想実行部は75です。

## 更新する

1. 既存版で「全停止」を押し、仮想画面を閉じます。
2. MarkerTap-v1.72-recording-editor.apkを上書きインストールします。v1.65〜1.71軽量版と同じパッケージjp.tapmarker.lite・署名です。先にアンインストールしないでください。
3. ユーザー補助の状態を確認します。仮想実行部と仮想画面を起動し直してください。
4. 対象アプリを開き、設定を確認してから手動で「自動開始」を押します。

画像を使う自律にはAndroid 11以降が必要です。旧jp.tapmarker通常版とは別アプリです。ARM32／ARM64／x86／x86_64を同梱しています。手動編集・学習済み設定は保持し、未編集の標準図は既存の移行方針を維持します。

## 録画を読み込んで生成する

1. 最初の画面の「録画ファイルからオートマトンを生成」またはパネルの「録画から生成」を押します。実行を停止します。
2. 保存するアプリ・ゲームを選び、「録画ファイルを選択」で端末の動画を選びます。端末のデコーダーが対応するMP4などを使います。
3. 解析開始・終了を秒で指定します。最初は10〜30秒程度の短い操作範囲を使います。「開始時刻の画像を表示」で範囲の先頭を確認できます。
4. 「アプリの範囲を指定」で対象アプリの内容ウインドウだけを囲みます。実行時に取得する対象ウインドウと同じ範囲にします。別アプリやステータスバーを含めないでください。
5. 録画に操作パネルが映る場合は「操作パネルなどの除外範囲を指定」で囲みます。
6. 0.5秒・1秒・2秒の取得間隔を選び、「録画を解析する」を押します。「解析を中止」で保存せず中止できます。
7. 結果の状態を開き、画像上でタップ位置やスワイプ経路を登録します。入力不要なら「操作なしで表示を待つ」を選びます。入力した場合は、その操作後に確認する録画中の表示を選びます。
8. 「生成した設定を保存」を押して対象名を確認し、「保存する」で確定します。以前の設定は退避してから置き換えます。保存だけでは自動開始しません。
9. 操作未登録が残る設定は下書きです。対象アプリを開き「かんたん編集」で「操作未登録：元の表示を確認」の操作と位置を設定し、次の表示確認への接続を保った後、「録画の操作確認を完了」で確認済みとして保存します。
10. 対象の開始画面を出し、手動で開始して1回の操作と停止を確認します。

録画は端末内で処理し、送信しません。保存先は解析開始時に確定し、解析中に対象の設定が変更された場合は置き換えを中止します。選択したファイルだけを読み出します。

## 生成の根拠と限界

- 連続した安定表示から状態を候補化し、2つの安定したフレーム対で確認します。単独の遷移フレームは状態にしません。
- 同じ表示・同じ遷移を統合し、状態ごとに主領域と補助領域を共有します。区別できない画像条件は生成時にエラーにします。
- 最大600フレーム、表示候補32までです。長い範囲は取得間隔を自動で広げます。同じ表示が3フレーム以上続き、2状態以上を区別できる録画が必要です。
- 映像だけからタップ位置や任意のスワイプを確定しません。未登録の遷移は次の表示を待つだけで、操作確認が完了するまで開始できません。
- 登録した操作は元の表示を確認して送信し、専用の確認状態で選択した結果表示を待ちます。未知の画面や曖昧な同時成立では保留します。
- 短い表示、未録画の分岐、同じ見た目で異なる操作が必要な場面は、追加学習・領域の編集が必要です。
- 録画終端は観測が終わった状態であり、デイリー全完了の証拠ではありません。自動生成した終了状態は編集で確認してください。
- 画面回転で解析画面が作り直された場合は再解析します。表示配置が異なる端末では、対象端末の画面から作成してください。

## かんたん編集

対象アプリ・ゲームを開き、停止して「かんたん編集」を選びます。上部の対象名を確認し、まず「設定を退避」で保存します。状態名・遷移名・領域名・遷移先を検索し、行を開いて変更します。「保存」は確定、「取消」は未保存の入力を破棄します。削除は別の確認操作です。

実演・録画から作った設定は状態や遷移を複製できます。内部の参照IDを付け替え、同じ状態への遷移はコピー側に接続します。領域は共有するため、片方だけ変える場合は別の領域を作成してください。標準専用IDには専用処理があるので、複製せず退避して直接編集するか実演から作成します。

「元に戻す」「やり直す」は対象ごとに直近最大12回、サービスの稼働中に使えます。画像量によって保持回数が少なくなる場合があります。「設定を退避」は再起動後も残り、対象ごとに1件です。「退避から復元」は現在のオートマトンを戻します。マーカー配置・デイリー完了登録・接続設定は別管理です。アプリをアンインストールすると退避も失われます。

変更後は「設定チェック」で見本不足・参照先・未接続状態を確認します。共有領域を描き直すと、その領域を使う主領域・補助領域の見本が無効になります。必要な遷移で「一致状態を記録」をやり直してください。異なる操作が同時成立した場合の保留は優先度では解除しません。

## コインの変更

| 場面 | v1.71の処理 |
| --- | --- |

| ゲットの左側がパネルに隠れる | 元の橙色の探索線に加え、ミッションの見出しと見えているゲット文字の右側を照合します。見えるボタン内に座標を置きます。 |
| 押下中・薄暗い報酬画面 | ゲット入力を保留します。録画の111.7〜111.8秒の未押下表示と、112秒以後の押下・暗転表示を区別して検証しました。 |
| 白い三角形と縦線の広告の次へ | 録画にある右上の塗りつぶし型と左上の輪郭型を追加しました。従来の灰白色の円内の黒い記号・白い閉じる・黄色の次へも維持します。 |
| 開始ボタンを押した後 | 専用の`bonus-wait`を共通の確認状態に統合しました。入力送信だけでは連打を再開せず、戻った主画面を2回確認します。 |
| クリア後に広告・強化画面が挟まる | 回収の用件を保持します。確認できた次ステージを開始し、主画面に戻った後にミッションを開きます。 |
| クリア後の時間切れ・未知の表示 | 回収待ちの確認へ進みます。未知の表示から投入連打へ戻しません。 |
| 未完了の赤い通知 | 通知だけでミッションを開く遷移は追加していません。通常のボーナス表示だけでも回収用件を発生させません。 |

各入力は2回の観察と入力直前の再確認を通します。広告・暗転・読み込み・画面サイズの変化があれば、古い入力と座標を取り消します。対象ウインドウの範囲から相対座標を画面座標へ変換します。以前の25種類のコイン見本は変更せず、9種類を追加しました。

## 追加4ゲームを学習する

| 対象 | アプリ／保存の扱い | 現時点の対応 |
| --- | --- | --- |
| うさぎのお店屋さん | `com.kurashiru.usagi.omise` | タップ・曲線・マーカーの実演から自動操作を作成。買い物うさぎの標準図を流用しません。 |
| ボックスマージ | `com.kurashiru.box.merge` | スワイプを曲線として記録し、ウインドウ内の相対座標で再生。コイン落としの連打図を流用しません。 |
| うさポ：農園うさぎ | `com.kurashiru.usapo`内の農園専用設定 | 学習結果・監視領域・マーカー・間隔・学習前の復元・完了条件を専用に保存。 |
| うさポ：風船パンチ | 同じうさポ内の風船専用設定 | 農園の設定を上書きせず、別の操作・判定を記録。 |

1. うさポでは、通常画面または仮想画面を開き、「対象ゲーム」で農園うさぎ／風船パンチを選びます。
2. 操作するゲームの実画面を開き、「学習開始」を選択します。うさポの巡回で入場操作も使う場合は、ゲーム一覧から実演を始めます。
3. ゲームへの入場、通常の操作、ダイアログ、ミッション回収、戻る操作などを実演します。ボックスマージでは必要な方向へスワイプします。連打を実演する場合はマーカーを配置して「マーカー実演」を使います。
4. 一周したら「学習終了・作成」を押し、作成された設定を確認して「自動開始」を選びます。

表示や操作が曖昧な場合は保留します。未実演の画面・広告・操作の対応を自動で作った扱いにはしません。標準オートマトンを追加するには、各ゲームの入場から通常操作、ダイアログ、ミッション回収、終了・一覧への復帰までの実画面資料が必要です。

## デイリー完了後に次のアプリへ

各対象で、**全デイリーの達成と報酬受取済み**が明示される表示を開き、「デイリー完了を登録」で2領域を記録します。1つ目は全達成・受取済みの文字や印、2つ目は画面を特定する見出しです。うさポでは、そのゲームに固有の名前・ミッション条件を2つ目の領域に含めてください。

「デイリー巡回」は表示順で1つずつ実行し、2領域が2回一致したら次のアプリへ進みます。最後で停止します。完了の確認中は通常のプレイ・回収・時間切れ再試行を保留します。部分達成、残り0、待ち時間だけでは全デイリー完了になりません。通常画面と仮想画面の完了条件は別々に保存します。

うさポの学習設定では、記録した入場・操作の入力完了を確認してから完了判定を有効にします。開始直後に残っている別ゲームの完了画面を、そのまま今回の完了として使いません。学習を始めた画面から実行してください。

**うさポは1周につき1ゲームを選択します。** 農園うさぎと風船パンチの間でゲーム一覧へ戻り、次のゲームへ入る標準処理は、実画面未確認のため未対応です。選択したうさポのゲームから別のアプリへの巡回は設定できます。

## 合理性監査と検証

既存4標準図の76状態・426遷移を監査し、874項目を通過しました。70状態が通常の矢印から到達可能で、残る6状態は専用のエラー／アカウント入口、外部画面からの復帰入口、手動用停止状態として用途を確認しました。画像参照・数値範囲・同じ判定からの矛盾・保存後の標準所有権・曖昧分岐の保留を検査しています。成功率の測定ではありません。

60組のJavaホストテストと模擬ADB8シナリオを実行しました。APKへ変換するものと同じbuild/shrunk.jarを対象にしています。新しい録画生成器は41項目（反復統合・取得上限・下書き制限・推測入力なし・登録したタップ／スワイプ・操作後確認・短い表示／曖昧性の拒否・6687実画像からの生成）を通過しました。編集の27項目、履歴の19項目、ゲーム対象の28項目も通過しました。

別チャットの6687録画62フレーム（18枚が原画素）の203項目、6682コイン380項目、6680のF52A275項目、6677のPixel171項目、農園ダイアログ245項目などを再実行しました。元の画像見本を変更せず保持しています。旧大容量Video6651／6662／6666／6669の全列再生は今回実行していません。

新APKのAndroidファイル選択・動画デコーダー・実機入力、追加4ゲーム固有のUI、Chromebook固有のUI、実際の全デイリー後の切替、長時間運転は未検証です。ホストでの画像認識や合成条件の検査と、実機での動作は区別してください。

## 再ビルド

Java 17、Android API35／Build Tools35.0.0、Python3、rg、C／C++コンパイラを用意し、展開したTapMarkerで実行します。

```sh
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE="$PWD/signing/lite-development.jks" \
bash build.sh

ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_TEST_GROUP=core bash run-tests.sh
```

既定出力は../MarkerTap-v1.72-recording-editor.apkです。録画読み込みはRecordedImportActivity.java、生成はRecordedAutomatonGenerator.java、編集はEasyEditorUi.java・PhaseUi.java、保存はAppPhases.javaにあります。通常の設定編集でソース変更・再ビルドは不要です。
