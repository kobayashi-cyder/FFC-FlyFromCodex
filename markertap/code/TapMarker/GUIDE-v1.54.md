# マーカー連打 v1.54：Wi-Fi自動接続と仮想画面の並列処理

v1.53と同じ署名の更新版です。APKを上書きインストールしてください。増えうさぎ・農園うさぎの既存設定と、連打間隔の初期値3msを維持します。

## 接続モード

メイン画面の「端末内接続モード」プルダウン、または操作パネルの「端末内接続モード」から選びます。更新直後の初期値は手動です。選択したモードは保存します。

| モード | 動作 |
| --- | --- |
| Wi-Fi接続中は自動接続・維持 | Wi-Fi接続中に端末内の実行部を確認し、未接続なら保存したペアリング鍵で再接続・起動を試みます。失敗時は20〜60秒の間隔を空けます。 |
| 手動接続（自動接続しない） | 「端末だけで接続」などの開始操作を押した場合だけ接続します。接続済みの実行部やゲームを、モード変更だけで終了させることはありません。 |

自動モードでも初回のAndroid側のペア設定と許可は必要です。Androidのワイヤレスデバッグ設定をアプリが勝手に有効にする機能ではありません。設定がオフになった場合はオンに戻してください。自動再接続中にAndroid設定画面を開いて操作を中断させることはありません。

ここで維持するのはゲームを動かす実行部です。実行部の起動確認後はADBの通信接続を閉じ、Binderで操作します。Wi-Fiが切れた際にも、実行部が残っている場合はそれを使い続けます。Wi-Fi切断後の継続は実機での確認が必要です。

「全停止」「複数画面停止」「接続準備を停止」は、自動再接続と保留中の自動復帰も休止します。接続開始、仮想画面の起動、自律開始で休止を解除できます。パネルの「終了」でも休止します。

## 今回の修正

小窓の描画先を直接仮想画面に使う構成を、画面ごとに持つImageReaderへ変更しました。プレビューの縮小や作り直しでゲームの描画先を解放しません。最小表示中も画像の取り込みと有効領域の判定を続けます。描画用Bitmapとバイト配列を再利用し、連続取得時の確保を減らしています。

仮想画面の終了時には、画面内のタスクを本体画面へ移さず終了させる設定を付けます。消失した画面ID・本体画面IDへの入力と起動を拒否し、本体画面へ起動し直す経路を使いません。画面が消えたことや実行部の切断を検出した場合は、入力を止めます。

端末内接続方式で自動モードを選んでいた場合、切断前の対象アプリ・自律の稼働状態・最小表示を保持し、実行部が接続できたら仮想画面を作り直します。全対象の表示を確認してから自律を再開します。停止していた画面は、自律停止のまま復元します。手動モードでは、接続後に自分で仮想画面を開き直します。

自動復帰は、ユーザー補助サービスが動作中に起きた切断・画面消失への対応です。アプリの強制停止、APK更新、端末再起動では対象の起動操作をやり直してください。ゲーム内の進行状態はゲーム側が保存したものから再確認し、失われた画面の古いタップ結果を使いません。

## 並列処理

端末内ADB・PCのADB・Shizukuの仮想画面方式では、各画面に画像取り込み用スレッドと、判定・入力・復帰用の実行スレッドを持たせました。オートマトンも画面ごとに独立したループで動きます。一方のタップや復帰処理の完了を、もう一方が待つ構成を取り除いています。

同じ画面への入力は順番を保ち、別の画面へは同時に送信できます。停止後に届いた古い完了通知が、新しく開始した入力や状態を進めないようにしています。現在の状態で有効な領域と、ゲーム画面確認用の小領域を比較します。

標準権限だけの仮想画面方式と通常の分割表示では、ユーザー補助の入力制約に合わせて入力を順番に送ります。今回の並列入力は、許可されたADBまたはShizukuの実行部を使用する方式です。PC・Shizukuなしの場合は、端末内接続方式を選んでください。

## 開く手順

1. APKを更新し、ユーザー補助の「マーカー連打」を有効にします。古いサービスが残る場合は、無効にしてから有効に戻します。
2. Wi-Fiに接続し、開発者向けオプションの「USBデバッグ」と「ワイヤレスデバッグ」をオンにします。USBケーブルは不要です。
3. 「端末内接続モード」を選びます。初回は「端末だけで接続」から「接続を開始」を押し、Android設定で「ペア設定コードを使用してデバイスをペア設定」の画面を表示します。
4. コードとポートを読み取れれば自動でペアリングします。読み取り不可なら「接続情報を入力」でコードとペアリング用ポートを入力します。接続用ポートの入力時はコードを空欄にします。
5. 「端末内実行部を起動 / ADB接続は切断済み」を確認します。
6. 操作パネルの「複数アプリを開いて自律」で対象を選び、「仮想画面（端末内接続・PC不要）」を選びます。接続済みなら既存の実行部を使って開きます。対象すべての表示が確認できてから自律を開始します。
7. 必要に応じて「仮想画面を最小表示」を押します。プレビューだけを縮め、内部の幅720ピクセルを維持します。

増えうさぎ・農園うさぎには既定のオートマトンを使います。その他のアプリは、アプリ別のオートマトンを先に作成してください。独自の曲線・マーカー操作の矢印は複数画面モードでは従来どおり未対応です。表示できる画面数、各ゲームが裏の仮想画面でも進行するか、同時入力を受け付けるかは端末とゲームにも依存します。実際に送信できるタップ間隔はAndroidの処理速度によります。

## 確認した範囲

- APKのコンパイルとv2・v3署名の検証。署名証明書がv1.53と一致することを確認。
- 27個のテストスイートが成功。既存の状態遷移・停止・相対座標・画面準備・保護判定、増えうさぎの録画領域498項目、農園うさぎ83項目を含みます。
- 新規テストで、片方の入力が完了しない間でも別の入力レーンが完了すること、停止前の通知が再開後の入力を解除しないことを確認。
- Wi-Fi自動／手動・未接続・再試行間隔・全停止後の休止、画像の行／画素パディング、全作成経路の画面終了フラグを確認。
- ネイティブライブラリ8本のELFロード位置とAPK内配置について16KBページ対応を確認。暗号処理はホスト向けJNIを使ったSPAKE2・AES-GCM相互通信を確認。

**Android実機は接続していないため、Pixel 10での起動、処理が落ちる現象の再現、Wi-Fi再接続、実際の2画面・4画面並列動作は未確認です。** 署名とホストテストの成功は、実機の成功を示すものではありません。

## ソースと再ビルド

ソースZIPに、本版のJavaソース、テスト、録画領域データ、ライブラリ、対応する第三者ソースとライセンスを含めています。署名秘密鍵は含めません。

Java、Python 3、ripgrep、Android SDK platform 35/build-tools 35.0.0が必要です。署名鍵を自分で用意し、次を実行します。スクリプトのaliasは`tapmarker`、passwordは`android`です。自分の鍵で署名したAPKは配布APKへ上書きできません。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk TAPMARKER_KEYSTORE=/path/to/your-key.jks bash build.sh
ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

暗号テストにはC/C++コンパイラも必要です。ライブラリ差し替えの方法はソース内の`WIRELESS-v1.53.md`を参照してください。本版では古い実行部を使わないよう接続プロトコルの世代を更新しています。PCのADBを使う場合も、本版APKから実行部を起動し直してください。
