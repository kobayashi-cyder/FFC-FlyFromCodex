# マーカー連打 v1.56：仮想画面の開始と入力失敗からの再試行

v1.55と同じ署名の更新版です。上書きインストールできます。

## 今回の画像から確認できること

増えうさぎ・農園うさぎのゲーム画面が仮想画面に表示されていますが、両方の見出しは「停止中」、中央は「自律OFF」「オートマトン停止」です。ユーザーから「自動開始を押しても停止中」と確認しています。

静止画像には停止した呼出元やAndroidの入力拒否理由がありません。実機の今回の原因を断定した版ではありません。コードから確認できた全停止と開始処理の結び付き、入力失敗後の再試行漏れを修正し、実機の理由を取得できる状況表示も追加しています。

## 上書き更新後の操作

1. APKを上書きインストールし、ユーザー補助が有効か確認します。
2. 「展開」→「端末だけで接続」→「接続を開始」で実行部を起動し直します。旧版の実行部が接続済みの場合は終了し、更新したAPKから起動します。保存済みのペアリング鍵は維持します。Android側で鍵が無効になっている場合は再ペアリングが必要です。
3. 「複数アプリを開いて自律」から増えうさぎ・農園うさぎを選び、「仮想画面（端末内接続・PC不要）」で開きます。
4. 両画面の表示確認が完了すると自律を開始します。停止中なら中央の「自動開始」を押します。本体はChatGPT・ホームなどを開いたままで構いません。
5. 「自律ON」になり、各画面の状態が変化するか確認します。「状況」で各画面の入力完了回数も確認できます。

旧実行部の再起動には、起動時のWi-Fi接続とワイヤレスデバッグが必要です。初期接続手順はソース内の`GUIDE-v1.54.md`・`WIRELESS-v1.53.md`を参照してください。

## 開始と停止

仮想画面を利用中は「自動開始」「オートマトン開始」などの開始ボタンは開始専用です。再押下で2画面の自律を停止しません。実行中の表示は「自律実行中」です。停止する場合は「全停止」を押します。

開始の内部処理は通常画面の自律・マーカー入力だけを終了します。準備済みの仮想画面、準備の完了状態、各画面の入力待ちを全停止する処理は呼びません。

自律中・画面準備中に小窓のゲーム画像へ触れても、全画面の自律を止めません。手動でゲームを操作する場合は「全停止」の後、小窓のゲーム画像をタップします。小窓の見出しをドラッグして移動したり、表示を最小化したりする操作は従来どおり利用できます。

通常の単画面モードの開始・停止切替は維持しています。画面消灯・サービス終了・明示的な全停止は停止します。

## 入力と遷移の修正

| 修正 | 動作 |
| --- | --- |
| 開始時の全停止を除去 | 準備済み画面を維持し、入力準備が成功してから自律ONにします。 |
| 小窓のタップで全停止しない | 自律中・準備中のゲーム画像タップを消費し、両画面の全停止へ変換しません。 |
| タップが拒否された場合 | 遷移や操作完了を記録せず、同じ条件を再確認して試行できます。画像条件には改めて2回の確認が必要です。 |
| 古い失敗通知 | 状態・実行世代が変わった後の失敗通知で、次の状態を取り消しません。 |
| 入力先の指定 | 端末内接続・Shizuku方式では、設定した画面IDを読み返して照合し、対象ゲームのアプリID（UID）を指定して入力します。対象アプリを指定しない入力へは切り替えません。 |
| 入力例外を保持 | 対象アプリへの入力拒否・準備失敗などを「状況」に残します。 |
| 旧版の実行部 | 起動時に版を確認します。旧実行部のまま入力を開始せず、再接続時に更新します。 |

アプリ宛ての入力指定をAndroidが提供していない端末では「開始不可」にします。Androidの非公開機能を利用する部分があり、実際の機種での利用可否は実機確認が必要です。標準権限だけの仮想画面方式は、従来どおりAndroidの起動許可とユーザー補助による画面ID指定に依存します。

## 仮想画面の画素位置への対応

今回の小窓の表示画像を既定の見出し領域で照合すると、元の単画面見本とは一致しませんでした。増えうさぎの見出しは仮想画面内では上端付近へ移っています。

そこで、提供画像から仮想画面用の主画面見本を追加しました。上部の固定表示と「増やす／収穫する」ボタン付近の2つの小領域をそれぞれ照合し、両方が一致した場合に主画面と判断します。一方の一致で他方の不一致を隠す平均判定にはしません。増えうさぎのミッション押下位置と残り匹数の監視位置も、仮想画面用に補正しました。

この補正は仮想画面の実行時だけ適用します。元の単画面設定へ保存しません。既定の主画面認識領域が独自変更されている場合は、独自の領域を優先します。

**見本は小窓を表示した静止画像からの抽出です。実際の720pxの内部描画画像での一致率と、仮想画面内の報酬・広告・ミッション表示での成功率は未確認です。** 今回は主画面の認識位置を補正し、従来の遷移ロジックを維持しています。

## 「状況」で確認できること

中央パネルの「状況」を押すと、次を表示します。「コピー」でテキストをコピーできます。ダイアログを開くだけでは自律を全停止しません。

- 全体の自律ON／OFF、開始不可の理由、最後の全体停止理由。
- 各画面のID、現在の処理状態、画像の最終取得からの時間、Androidの表示情報の取得状況。
- 各画面の入力完了回数、最後の入力拒否理由、個別の停止理由、起動エラー。
- 開始・停止・入力エラーの履歴。コードの呼出元も診断用の履歴に含めています。

ゲーム画面が見えていても入力が届くとは限りません。「自律ON」は監視ループが動いている状態です。画像条件の不成立、保護対象の表示、入力拒否中には操作完了へ進みません。「状況」の入力回数はAndroidへの入力送信完了を示し、ゲーム内の報酬取得までを保証する表示ではありません。

| 表示 | 確認・対応 |
| --- | --- |
| 開始不可：実行部が旧版 | 「端末だけで接続」から更新済みAPKの実行部を起動し直します。 |
| 開始不可：入力の準備… | 「状況」にAndroidの例外を表示します。仮想画面の作成と入力許可を別に扱います。 |
| 入力拒否 | 「状況」で拒否理由を確認します。同じ画像条件の再確認後に再試行します。 |
| 表示情報待ち | その仮想画面のAndroidウインドウ情報が取得できないため入力を保留しています。 |
| 保護表示で待機 | アカウント操作などの表示を検出して入力を禁止しています。 |
| 停止状態 | 各画面の停止条件・復帰の上限などを「状況」に表示します。 |

状況表示にはペアリングコード、鍵、ゲームの画面テキストは含めません。

## 維持する仕様

初期値3ms、Wi-Fi中の自動接続／手動接続、画面ごとの独立した領域判定・入力処理、最小表示時の内部解像度の維持、仮想画面の消失時にゲームを本体画面へ移さない設定、全停止後の自動復帰休止を維持しています。実際の入力間隔はAndroidとゲームの処理速度に依存します。

ログアウト・アカウント削除などの保護判定は維持します。独自曲線・マーカー操作の矢印は複数画面モードでは従来どおり未対応です。

## 検証範囲

32個のホストテストスイートが通りました。新規テストでは、開始時に準備状態・入力待ちを全停止しないこと、開始の再押下、対象アプリと画面IDを指定する実際の入力アダプタ、拒否された操作の再確認と再試行、古い失敗通知による状態破壊の防止を確認しました。提供画像の2つのゲーム画面について、実際の領域サンプラー・状態機械で「復帰確認→各ゲームのメイン」へ進むこと、現在の画面で誤ったイベントへ分岐しないことを検証しました。見出しだけ／ボタンだけの一致、暗くした画像、別ゲームの画像を拒否する検証も通りました。従来の増えうさぎ・農園うさぎの録画領域テストも通りました。

**Android実機は接続していません。今回の端末での並列入力・解消は未確認です。** ホストテストの入力先はスタブであり、Androidの入力権限や配送そのものをテストした結果ではありません。

ビルド、v2・v3署名、従来版と同じ署名証明書、ネイティブライブラリとAPKの16KB境界配置を確認しました。テストログ・検証結果は`tests-v1.56.log`・`validation-v1.56.json`に含めています。

## 再ビルド

Javaコード、テスト、ライブラリ、対応する第三者ソース・ライセンスをソースZIPに含めています。署名秘密鍵は含めていません。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk TAPMARKER_KEYSTORE=/path/to/your-key.jks bash build.sh
ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

Java、Python 3、ripgrep、Android SDK platform 35/build-tools 35.0.0が必要です。暗号テストにはC/C++コンパイラも必要です。自分の鍵で署名したAPKは配布APKへ上書きできません。

入力仕様の確認資料：

- [AOSP InputManagerGlobal：入力先UIDを指定する注入](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/hardware/input/InputManagerGlobal.java)
- [AOSP InputDispatcher：ウインドウ所有UIDの照合と画面IDによる配送](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/main/services/inputflinger/dispatcher/InputDispatcher.cpp)
