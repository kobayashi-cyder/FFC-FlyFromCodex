# MarkerTap v1.121 — 異常終了時の全停止

v1.120の通常解像度・領域取得を維持し、異常終了時の残存仮想画面とバックエンドを終了させます。

## 変更
- アプリの未捕捉例外では、まず接続済み端末内実行部へ非同期の終了要求を送り、Android標準のクラッシュ処理を継続します。
- 所有アプリのBinderが消滅したときは、ADB/Shizuku側の実行部が全仮想画面を解放して終了する所有者監視を追加しました。
- 1つの仮想画面が異常終了・起動失敗したときは全画面を停止し、残りの操作を継続しません。
- 画面解放の途中で一箇所が例外になっても、その他の画面を解放します。
- 仮想画面作成中の終了レースでも、停止後に作成された画面を破棄します。
- クラッシュ後の自動再接続を停止し、ユーザーが「端末内接続」「自動開始」などを明示的に操作したときだけ再接続します。
- 手動実行部再起動の確認操作は引き続き利用できます。

## 操作と範囲
対象はMarkerTapが作成した仮想ディスプレイ・ジェスチャー・ワーカー・ADB/Shizuku実行部です。Android本体の再起動、他社アプリの強制終了、ワイヤレスデバッグのOS設定の切替、保存データの削除は行いません。

Javaの致命的な例外はアプリ側の終了処理と所有者Binderの死亡通知の両方で扱います。OSの強制停止/SIGKILLなど、アプリのコードが実行できない終了はBinder死亡通知によるADB/Shizuku側の解放が基本です。端末の突然の電源断やOS停止後に実行部を操作することはできません。

## 検証
このドキュメントはソース実装時の仕様です。ビルド・既存の署名鍵を用いた署名・Pixel 10/Android 17での実機強制終了・仮想画面残存の検証は未完了です。Android SDKを使ったテストは独立したCIで実施します。

実機では、4画面稼働中のサービス終了、Javaの未捕捉例外、ADBバックエンドの強制終了、画面生成中のクラッシュ、Wi-Fi OFF、手動再起動を個別に確認してください。異常後に画面が残存せず、再開操作までは新たな画面が作成されないことが合格条件です。

実装済み。検証待ちです。
