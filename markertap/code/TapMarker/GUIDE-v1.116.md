# MarkerTap v1.116 — 復帰判定・診断画像・手動介入

`jp.tapmarker.lite` / versionName `1.116` / versionCode `119`

## 更新
1. 旧版で「全停止」します。
2. `MarkerTap-v1.116-recovery-diagnostics.apk` を上書きインストールします。
3. ユーザー補助の状態を確認し、端末内接続を再開して、対象アプリの仮想画面で自律を開始します。

元の署名証明書との一致を確認した更新APKです。設定を消すためのアンインストールは不要です。

## 今回の修正
- ポップアップの「閉じる」が見えただけでは、復帰回数をリセットしません。主画面の画像を新しく2回、350ms以上にわたって確認してから次の復帰エピソードに進みます。
- 同じ下端表示の「閉じる」は2回まで。検出が一時的に途切れたり、名前付き認識と画像認識が切り替わったりしても、主画面未確認のまま回数を補充しません。
- ポップアップを優先する間も、主画面を約2秒ごとに独立確認します。その結果は「独立確認・操作保留」として記録し、ポップアップの背後のゲームを根拠に通常連打を許可しません。
- 「距離0」の論理フラグと、下端見本との実際の画像距離を診断で区別します。操作抑制の前後の判定と、閉じる試行回数も残します。

## 自律実行中の手動タップ
見出しから対象の映像を開き、その映像を1回タップできます。

指を置いた画面だけ通常連打と自動操作を一時停止し、プレビュー座標をその仮想画面の実座標へ変換して入力します。送信後は短く待ち、新しい画像で状態を再判定してから自律を再開します。ほかの画面の入力用エポックを再設定しません。

入力先が対象ゲーム以外へ変わっている場合は、その外部画面へゲームのタップを流用しません。自動操作で既に停止した個別画面を、手動タップだけで自動運転へ戻す処理にはしていません。

## 画像付き診断
仮想画面の進行不良を検出すると、診断文に加えて次を端末内へ自動保存します。
- 直近の制御操作の前画像と、その後の新しい画像2枚。取得できなかった枚数も記録します。
- 定期的な画像と、エラー検出時の画像。1件につき最大8画像です。
- 元画像と、タップ位置・取得できた照合領域を重ねた画像。
- 対象アプリ、仮想画面ID、実行識別子、画像時刻、状態とepoch、選ばれたルール、認識器、判断理由、フィルタ前後の判定。

「進行エラーを見る」→「画像付き診断を共有」、または設定画面の「進行エラー」カードからZIPを共有できます。ZIPは report.txt・incident.json・JPEG・画像別JSONを含みます。文章をコピーしただけでは画像は添付されません。

通常の高速連打ごとに画像をコピーしません。制御操作に対する前後画像と約1秒ごとのサンプルを保持し、圧縮は入力とは別の作業スレッドで行います。320×718の画像はそのまま保存し、大きい画像は最大幅540px・高さ1440pxへ等倍比率で縮小します。保存履歴は最新5件です。外部への自動送信は行いません。

エラー直後は最初のZIPを保存し、約1秒後に同じ実行が継続していれば後画像を反映します。プロセス終了や画像取得失敗の際は、完全な前後画像がそろう保証はありません。欠けた画像を成功扱いしません。

## 再ビルド
Android API 35・Build Tools 35.0.0・Java 17・Python 3・ripgrepを使用します。秘密鍵はソース・修正差分に含みません。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk TAPMARKER_KEYSTORE=/path/to/lite-development.jks bash build.sh
ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

ソースZIPは通常のcoreテスト用素材を含みます。fullグループの追加4録画についてはv1.115と同じ制限があります。
