# BANC888 v7.14 — 四機能統合・認知ループ

## 定義と実装範囲

会話・コード・画像・動画の既存生成ツールを、通常のチャット入力から共通の **要求→計画→コネクトーム選択→実行→観測検証→学習** の経路へ接続する。

この変更で汎用人工知能が完成したわけではない。現状の Figure 3g は集約6ノード/16辺で、意味理解の大半は人間が設計した分類器・ルータ・選択可能な外部言語モデルが担う。有限状態の認知エンジンは計画・検証・失敗に対する重み変更を担う。未習得分野の自律的な世界モデル構築やLLM並みの自由生成能力は実証されていない。

## 実際の生成能力

| 領域 | 利用経路 | 結果の検証 | 限界 |
|---|---|---|---|
| Chat | 端末内の会話機構、またはユーザー設定の言語モデル /v1/chat/completions | 空返答・ツール失敗を排除 | 回答の正しさを外部照合していない。言語モデルは端末内に同梱されない |
| コード | CodeIR、候補生成、静的検証、修復、利用可能なら設定済モデル | review.accepted と validation.pass、および雛形ではないことを必須に | 静的合格はコンパイル・実行・依存関係の成功ではない |
| 画像 | O2手続き描画・候補評価と選択 | O2が実際に描画した場面と品質ゲートを要求 | 内蔵画像拡散モデルや写真級画像モデルは含まれない |
| 動画 | O3アニメーション→Android H.264 MP4、またはユーザー設定のA1111 API | エンコード完了後、バイト数とフレーム数一致を確認 | A1111は外部接続が必要。完了まで出力待機 |

### アプリ操作

普段の会話欄から「説明して」「Pythonコードを書いて」「猫の画像を生成して」「猫が動く動画を作って」のように依頼する。4種の明示的な一括生成要求は、認知エンジンが複数アクションとして計画する。失敗した処理を完了と偽装しない。

内部APIは FFC_PROXY_AGENT.cognitionRequest(text, ctx)（非同期）および FFC_PROXY_AGENT.cognitionCapabilities()。従来の executeAsync と部分的JSON互換API request は既存の呼び出しを壊さず保持する。

### 失敗と報酬の意味

- Chat: nonempty_reply_only は空でない応答が得られた意味のみ。真偽を保証しない。
- Code: static_review_only は静的品質チェックのみ。未実装scaffoldを拒否する。
- Image: procedural_render_quality は手続き描画の内部品質のみ。画像が美的に優れている証明ではない。
- Video: mp4_encoding_confirmed はフレーム数とファイルバイト数が一致した証拠。内容の意味的品質の証明ではない。
- 未完了動画、品質検査失敗、空応答、接続なし等は報酬を成功にしない。

## 限界・次工程

外部モデルへの依存なしで自由な日本語文章・任意コード・写真級画像・本格映像を生成するAI基盤は未実装。後続工程は端末動作可能な言語/視覚モデルの量子化推論、実行環境でのコードテスト、画像実体のファイル保存、画像と動画の内容検査、未知課題ベンチマークと長期記憶・自己訂正の厳格な評価である。
