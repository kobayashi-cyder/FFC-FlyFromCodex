# マーカー連打 v1.55：仮想画面の自律開始・継続の修正

v1.54と同じ署名で上書き更新できます。

## 今回の画像で分かったこと

画像では増えうさぎ・農園うさぎの仮想画面が作成済みですが、パネルには本体のホームアプリ名と「増えうさぎを開いてから」という案内が表示されていました。

コードに、仮想画面の存在を確認する前に本体のアプリ名を要求する開始ボタンが残っていました。v1.55ではこの経路を修正し、開いている仮想画面を開始対象にします。画像だけから、実機で起きた停止の全原因を断定したものではありません。

## 更新後の操作

1. APKを上書きインストールします。更新で実行部が終了するため、ユーザー補助を確認し、端末内接続を起動し直します。通常、既存のペアリング鍵は引き継ぎます。
2. 「複数アプリを開いて自律」から増えうさぎ・農園うさぎを選び、「仮想画面（端末内接続・PC不要）」で開きます。
3. 各ゲームの表示確認後に自律を開始します。「仮想画面を最小表示」で見出しだけにしても、処理は続きます。
4. 停止後はパネルの「自動開始」を押します。ChatGPTやホーム画面を本体で開いたまま、仮想画面を対象に再開します。本体画面でゲームを開く必要はありません。

「自動開始／停止」「オートマトン開始／停止」「対応ゲーム自動開始」「表示中の対象を自律」は、仮想画面を選択・表示している場合に仮想画面を優先します。開始専用ボタンの再押下で、実行中の状態機械を初期化しません。

## 修正内容

| 場面 | v1.55の動作 |
| --- | --- |
| 仮想画面があり、本体はChatGPT・ホーム画面 | 本体のアプリ名を条件にせず、仮想画面で開始します。 |
| 画面を作成中に開始を押す | 作成中の処理を止めず、全画面の表示確認後に開始します。 |
| 準備中に全停止した後の再開 | 開いていた対象の仮想画面を作り直してから開始します。 |
| 1画面を閉じて再開 | 残っている実際の画面を対象にします。保存済み対象一覧との差で拒否しません。 |
| 仮想画面で広告などを表示中に再開 | 作成済み画面の起動先が本体で開かれていることを要求せず、ゲーム画面の再確認状態から進めます。 |
| ユーザー補助が同じサービスへ再接続 | 既存の実行・画面管理オブジェクトを維持し、小窓だけが残って管理対象を失う経路を防ぎます。 |
| 本体の画面構成・向きが変化 | 仮想画面の描画先と自律を維持し、小窓の位置・表示サイズを調整します。通常画面のマーカー操作は従来どおり停止します。 |
| ユーザー補助のフィードバック割込み | 仮想画面の処理を全停止する操作へ変換しません。全停止・画面消灯・サービス終了は停止します。 |

仮想画面の利用中は、パネルの先頭を「仮想2画面 / 自律ON」などにします。本体のホームアプリ名や、通常画面用マーカーの個数を実行対象として表示しません。各小窓の見出しには画面IDと実行状態を表示します。

| 見出し | 意味 |
| --- | --- |
| 実行：状態名 | この画面の状態機械を処理しています。 |
| 停止中・停止状態 | 自律入力を停止しています。 |
| 表示確認中・開始待ち | 起動後の確認または開始を待っています。 |
| 表示情報待ち | この仮想画面のAndroidウインドウ情報を取得できず、入力を保留しています。 |
| 画像取得エラー | 画像の取得・展開に連続して失敗し、入力を保留しています。 |
| 保護表示で待機 | アカウント操作などの保護対象を検出し、入力を禁止しています。 |

「自律ON」は監視ループが動いていることを示します。待機表示中や、画像条件が成立していない間はタップしません。

## 維持する仕様

Wi-Fi中の自動接続／手動接続、画面ごとの並列処理、最小表示時の内部解像度の維持、仮想画面消失時の本体画面移動防止、全停止後の自動復帰休止はv1.54から維持します。初期値3msも維持します。実際の送信間隔は端末とAndroidの処理速度によります。

端末内接続の初期設定と制限は、ソース内の`GUIDE-v1.54.md`に記載しています。初回ペアリングとAndroid側の許可は必要です。独自曲線・マーカー操作の矢印は複数画面モードでは従来どおり未対応です。

## 検証範囲

28個のホストテストスイートが通りました。新規の開始処理テスト35項目では、画像のように本体がホーム・ChatGPTでも2つの仮想画面を開始すること、準備途中の開始が別画面の準備を取り消さないこと、実行中の再押下で初期化しないこと、全停止後の古い完了通知で再開しないことを、実際の開始ルーターと準備状態のクラスを使って確認しました。増えうさぎ・農園うさぎの録画領域による判定テストも通りました。

APKのビルド、v2・v3署名、従来版と同じ署名証明書、ネイティブライブラリとAPKの16KB境界への配置を確認しました。テスト結果はソース内の`tests-v1.55.log`と`validation-v1.55.json`に含めています。

**Android実機は接続していません。Pixel 10で今回の現象を再現して解消確認した版ではありません。** 実機の動作結果と、ビルド・署名・ホストテストの結果を区別してください。

## 再ビルド

ソースZIPにJavaコード、テスト、ライブラリ、対応する第三者ソースとライセンスを含めています。署名秘密鍵は含めていません。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk TAPMARKER_KEYSTORE=/path/to/your-key.jks bash build.sh
ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

Java、Python 3、ripgrep、Android SDK platform 35/build-tools 35.0.0が必要です。暗号テストにはC/C++コンパイラも必要です。自分の鍵で署名したAPKは配布APKへ上書きできません。

仕様確認：[Android AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。`getWindowsOnAllDisplays()`は画面IDごとのウインドウ情報を返し、取得できない場合は空になります。`onInterrupt()`はユーザー補助のフィードバック割込みです。これらを本体画面のゲーム起動確認や仮想画面の全停止と混同しない構成へ変更しています。
