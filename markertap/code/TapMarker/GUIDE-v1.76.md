# MarkerTap v1.76 — 画面認識を軽量化し、通常プレイの連打を継続

`MarkerTap-v1.76-continuous-autonomy.apk` を現在の版へ上書きインストールし、対象ゲームを開いて「自動開始」を押してください。旧版と同じ署名・パッケージを使用します。アプリ登録・マーカー・ゲーム別の学習内容を引き継ぎます。仮想画面を使用中の場合は更新後に実行部を起動し直してください。

パッケージ：`jp.tapmarker.lite`／versionName：`1.76`／versionCode：`79`。仮想実行部の通信プロトコルは75を維持します。

## 連打を続ける条件

「CMが見えていない」だけで連打を続けると、クリア・報酬・確認画面も押し続けることになります。今回の条件は **連打で進む通常プレイ画面を確認できている間は、画面認識の処理中も連打を続ける** です。

| 表示・状況 | 動作 |
| --- | --- |
| 確認済みの通常プレイ画面 | 設定された間隔で連打を続ける |
| 次の画像を取得・判定している途中 | その処理だけを理由に連打を止めない |
| CM・強化ダイアログ・クリア・報酬画面への分岐を最初に検出 | 通常連打を保留し、次の画像で分岐を確認する |
| CM終了印が確認できた | 新しい画像で位置を再確認して閉じる・スキップする |
| ゲームへの復帰を確認 | 通常連打を再開する |
| 対象アプリが消えた・位置が変わった・新しい画像が来ない | 古い座標の入力を取り消し、画面確認を待つ |
| デイリー全達成の登録済み条件を確認 | 従来の巡回設定に従う |

コイン落としは、投入→強化・CM→復帰→クリア→ミッション・未回収報酬→次のプレイの既存オートマトンを維持します。ミッション通知やコイン枚数の変化だけでは通常投入を中断しません。回収途中のCMでも回収意図を保持します。

増えうさぎ・農園うさぎ・買い物うさぎの既存プリセットにも、認識中に通常連打を続ける共通制御を適用しました。複数画面でも各ゲームの入力を独立して継続します。うさぎのお店屋さん・ボックスマージ・うさポ内のゲームは従来の学習済みグラフを使用し、画面認識の軽量化を適用します。独自操作の連打期間・スワイプ・次状態確認は学習した設定に従います。異なるゲームの未確認画面へ標準連打を自動適用することはありません。

通常連打に使用できる画像の経過時間は最大1.5秒です。認識できない状態で連打を無期限に続けません。タップ速度の設定とF-52A用の実効間隔は維持します。

## 軽量化

- 同一画像内の同じ画素範囲の読み取りを再利用します。画像が変わると再利用内容を破棄し、ゲーム・画面をまたいで画像を共有しません。
- サンプリング座標を一度計算し、画素タイルの繰り返しアクセスを短縮します。元の画像値・照合しきい値は変えません。
- 仮想画面の認識と入力を別の実行処理に分け、重い画像探索が同じ画面の入力待ちを増やさないようにしました。
- 複数画面の旧120ms連打バーストを、画面を監視しながら続く入力へ変更しました。
- 正常プレイの確認をBANCへ通知し、通常連打が続いているだけで全状態の復帰探索を繰り返さないようにしました。
- ウインドウ情報は短い100msの範囲で再利用し、ウインドウ変更イベントで破棄します。

## 検証結果と測定範囲

画像サンプリングの最適化を、同じ録画6687の保留画像・同じ探索手順で比較しました。旧版の画像サンプリング／画素タイル実装だけを差し替えた比較であり、APK全体の実機ベンチマークではありません。

| 開発環境での6画像判定 | 旧サンプリング処理 | 改修処理 |
| --- | ---: | ---: |
| 4測定の中央の2値を平均した時間（予備実行1回） | 335.42ms | 138.19ms |
| 画素読み取り要求 | 18,220,032回 | 13,593,600回 |
| 判定データ | 同一 | 同一 |

この条件では判定時間が約58.8%、画素読み取り要求が約25.4%減少しました。Android実機の改善率やタップ受付速度は未測定です。

- 既定のJava検査64組と、回路・プリセット・接続・暗号の追加検査、模擬ADB8シナリオを通過しました。
- 新しいサンプリング754項目で元の計算との完全一致、返却画像の独立、キャッシュの上限・画像切替を確認しました。
- 通常連打27項目で連続入力、CMの最初の検出での保留、復帰、古い画像・座標の拒否、ゲーム別の入力分離を確認しました。
- コイン落としの録画保留画像19項目で、通常投入・強化ダイアログ・CM・復帰・クリア・回収中断を確認しました。
- 最終APKの旧版との署名一致、バージョン、DEXとビルドの一致、画像資産、4種類のCPU向けライブラリ、16KB配置を確認しました。

記録は `tests-v1.76.log`、`VALIDATION-v1.76.json`、`performance-v1.76.json`、`apk-verification-v1.76.log` に含みます。Android実機の入力・CM終了受付・報酬付与、追加4ゲームの未提供画面、Chromebook固有のUIは未検証です。任意の過去4録画のfull検査は別途のフィクスチャが必要です。

## 再ビルド

Java17、SDK platform35、build-tools35.0.0を使用します。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk TAPMARKER_KEYSTORE=signing/lite-development.jks bash build.sh
ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

ソース同梱の測定用プログラム `SamplingBenchmark` は、同じ画像・同じ探索周期のホスト比較用です。最適化前の `RegionSampler.java` と `TilePixels.java` は `tests/baseline-v1.75/` に残しています。
