## Source mismatch found and patched on this PR branch
The supplied evidence names the active package as `com.kurashiru.nouen.usagi` and the state as `farm-default-verify`. The prior v1.139 recovery gate only admitted `com.kurashiru.fue.usagi` and the `usagi-default-main/verify` state names. That means the recovery logic could be bypassed for the exact package/state in this incident, even before determining why fresh frames stopped arriving.

The PR branch has now been updated to:
- accept both observed Kurashiru package aliases (`com.kurashiru.fue.usagi` and `com.kurashiru.nouen.usagi`) for the guarded recovery path;
- accept the observed `farm-default-main/verify` state aliases while retaining the fresh-frame requirement and safe-stop budget;
- add regression assertions and source-audit checks for the incident's actual package/state.

This is a concrete eligibility/coverage defect and fix, **not yet proof that it resolves the underlying frame-capture stall**. CI must pass on the new commit, then the generated APK still needs F-52A/Android 12 validation.
