# マーカー連打 v1.60：オートマトンの関係を保持する修正

`MarkerTap-v1.60-automaton-relations.apk` は同じ署名で上書き更新できます。状態・条件領域・操作・遷移先の対応が崩れる経路を修正しました。連打間隔の初期値は3msを維持しています。

## 更新後にすること

1. APKを上書きインストールします。
2. 仮想画面の実行部が旧版と表示された場合は、「端末だけで接続」から接続し直します。ペアリング情報は維持します。
3. 対象アプリを開き、「オートマトン編集」→「関係チェック」で状態・矢印・領域の参照を確認します。
4. 遷移先が未登録なら、赤い矢印を編集して正しい状態を選びます。開始状態が未設定なら、開始させたい状態を選びます。
5. 「自動開始」で実行します。通常画面でも仮想画面でも、手動編集した開始状態と遷移先を使います。

**v1.59の学習で途中の状態や矢印が欠落した結果は、一度再学習してください。** 以前に保存した学習結果には、欠落した操作直後の元画像が残っていないため、正しい行き先を自動復元することはできません。更新だけで、既に誤って保存された矢印の意味を推測して書き換えることはありません。

手作業で編集した設定は保持します。新しい学習結果を適用するときは、対象アプリの以前の設定を「学習前に戻す」で復元できます。

## 修正した原因

| 原因 | 修正後 |
| --- | --- |
| 操作直後の画面を飛ばし、次の実演開始画面を行き先にしていた | その操作で記録した直後の表示を確認して遷移する。 |
| 実演の間に自然に変わった表示を省略していた | 操作のない表示変化を、表示確認だけの矢印として保持する。 |
| 同じ結果へ向かう見本を一つに減らしていた | 必要な見本を保持し、操作と遷移先が同一の条件はORとして扱う。 |
| 編集・削除した矢印を初期設定の補完で戻す場合があった | 手動編集した設定を保護し、消した矢印を開始や再読込で補完しない。 |
| 通常画面の開始時や仮想画面の復帰時に、固定の開始・復帰先へ置き換える場合があった | 手動編集したオートマトンでは、選んだ開始状態と各矢印の行き先を使う。 |
| 旧履歴設定の変換で補助領域・相対位置・安定待ちなどが落ちていた | 条件と操作の情報を複製して明示的な状態へ変換する。 |
| アプリや設定が切り替わった後に、古い編集画面の内容を保存できた | 対象アプリ・状態・矢印の所有関係を確認し、古い編集は保存しない。 |
| 存在しない行き先が、編集画面で「同じ状態」に見えていた | 未登録の行き先を表示し、選び直すまで保存できない。 |

操作と遷移先が異なる条件が同時成立した場合は、引き続き保留します。優先順位や表示順で選びません。条件が異なっても、実行内容が完全に同じなら、矛盾した分岐として停止させません。

## 学習する手順

1. 対象アプリを通常画面または仮想画面で表示します。
2. 「展開」→「学習開始」から対象を選びます。
3. 記録が完了してから次の操作を行い、一周を実演します。
4. 「学習終了・作成」を押します。
5. 作成結果の「図で編集」で状態と矢印を確認します。
6. 「自動開始」で再生します。

例えば、AでタップしてBが表示され、その後操作なしでCに変わり、Cで次のタップをした場合は、Aのタップの結果をBとして保存します。BからCへの表示変化は入力のない確認として残し、次のタップはCから実行します。

「状態1」などは表示状態です。「操作後の確認」は、入力を再送せずに、その操作で観測した結果を確認する処理用の状態です。入力の送信完了だけで、結果を確認できた扱いにはしません。

同じ表示は同じ状態に統合します。別の表示を判別するために、安定した監視領域を選びます。形や模様だけでなく、判別に必要な平坦な色の領域も使います。選べた領域で違いを判定できない場合は、学習結果を適用せず再学習を案内します。

繰り返しを外した学習で、全く同じ状態・操作・結果に「続行」と「停止」が重なる場合は、停止条件の区別が必要だと表示します。完了を区別できる表示で終了するか、繰り返しを選んでください。停止の矢印を削って続行させることはありません。

## 図で確認・編集する

- 「関係チェック」は、参照の一致、識別子の重複、開始状態、開始から未接続の状態を表示します。見本画像が画面の意味を正しく表しているかまで保証する機能ではありません。
- 未登録の遷移先への矢印も赤く表示し、タップして編集できます。自律開始時には参照エラーを表示します。
- 矢印を編集しても識別子と他の矢印を保持します。古い操作結果や編集結果が、新しい矢印へ紛れ込むことを防ぎます。
- 開始状態を削除した場合は、別の状態を自動選択せず、開始状態を選び直すよう案内します。
- 「矢印全消去」は状態・領域を残し、全ての矢印を削除します。再読込や開始で元の矢印を補完しません。
- 「初期設定へ戻す」は増えうさぎの状態・矢印・領域を初期設定に置き換えます。アプリ内で置換内容を確認してから適用し、以前の設定は退避します。
- マーカーの紐づけは、編集中の対象アプリの登録マーカーから行います。他のアプリのマーカーを代わりに使いません。

領域を描き直した場合、その領域の見本は再記録が必要です。「一致状態を記録」で主領域と補助領域を更新してください。操作位置は相対位置指定・個別の条件領域中央から選べます。

## 画面と並列動作

学習した領域・タップ位置・曲線・マーカー位置は対象ウインドウ内の相対座標です。通常画面・分割画面・仮想画面の位置と大きさの違いは、条件照合と入力で共通の補正を使います。

実行中は現在状態に必要な領域だけを比較します。未知の表示、補助領域の不一致、位置補正候補が重なった場合は入力を保留します。固定の長い待機で遷移を決める方式にはしていません。

複数の仮想画面では各アプリの状態・入力・復帰を独立して扱います。「表示中の対象を自律」または「自動開始」から実行します。全停止は学習・連打・自律と復帰の再試行を停止します。アカウント削除・ログアウトの保護判定も維持しています。

## 検証範囲

39組のホストテストを実行し、全て成功しました。追加した関係の回帰テストは38項目です。旧版で、操作直後の状態の欠落、停止条件の脱落、旧設定変換時の情報欠落を再現してから修正しました。

確認した内容は、実際の操作前後の接続、入力なしの表示変化、異なる遷移先の保留、同じ結果への条件の統合、平坦な色で異なる状態、別アプリへ古い編集結果を保存しないこと、矢印の識別子保持、削除後の古い完了通知の無効化、開始状態の削除、初期設定と編集済み設定の区別です。既存の増えうさぎ・農園うさぎの録画由来の画素再生テストも成功しました。

APKはバージョンコード63、v2/v3署名、16KiBページ向けの配置を検証済みです。署名は以前のAPKと同じです。実機での継続動作・操作の受け渡し・編集画面の表示は未確認です。

## ソースからビルドする

Android SDK35、JDK、同梱のECJと依存ライブラリを使用します。署名用秘密鍵は含めていません。

```bash
export ANDROID_SDK_ROOT=/path/to/android-sdk
export TAPMARKER_KEYSTORE=/path/to/tapmarker-update.jks
bash build.sh
bash run-tests.sh
```

出力は `../MarkerTap-v1.60-automaton-relations.apk` です。追加テストは `ObservationRelationsTest.java` と `AutomatonGraphTest.java`、実行結果は `tests-v1.60.log` に含まれます。
