# MarkerTap v1.73 — APK内のBANC自律・ゲーム間ノウハウ共有

v1.72の録画生成・編集・既存ゲーム設定を土台に、BANC888由来の候補選択と結果学習、録画を使った比較・改修・再検証をAPKへ組み込んだ更新版です。別のBANCアプリを起動せず、MarkerTapの端末内処理として動きます。

## 更新と使い方

1. `MarkerTap-v1.73-banc-autonomy.apk` を既存のv1.72へ上書きインストールします。パッケージと署名を維持し、versionCodeを75から76へ上げています。
2. ユーザー補助を有効にして対象ゲームを開き、従来どおり「自動開始」を押します。仮想画面では対象選択から開始します。
3. パネルの「BANC自律」で自律復帰とノウハウ共有を確認できます。両方とも初期設定はONです。設定画面を開くと自動化を停止します。保存後は「自動開始」で再開してください。
4. 操作ボタンが読めないゲーム画面では「学習開始」で実演するか、「録画から生成」で操作を登録します。確認した新手順も自律復帰の対象になります。

既存の配置・オートマトン・ゲーム別設定を利用します。新しく追加した成功・失敗の共有記憶は、v1.73の使用実績から蓄積します。

## APK内で録画を使って改修を繰り返す

1. メイン画面の「録画で修正箇所を探して繰り返し改修」、または操作パネルの「録画で改修」を押します。
2. 対象ゲームと録画を選び、ゲームの内容ウインドウを囲みます。対象アプリのウインドウと同じ範囲にし、別ゲーム・操作パネルは除外します。
3. 「録画を解析する」を押します。APKが既存の設定と比較し、未登録・条件不一致の表示、曖昧な状態、未登録の分岐、長時間変わらない表示を、録画時刻とともに表示します。見本・範囲の不一致と操作失敗は、録画だけでは区別できない場合があります。
4. 以前に確認した、同じゲーム・同じ表示・同じ結果の操作は引き継ぎます。操作が未登録の状態では画像を押してタップ位置を指定するか、スワイプ・操作なしを登録します。
5. 「修正候補を作成して録画で再検証」を押します。APKが既存の状態・分岐を保持して候補を作り、同じ録画との比較結果を修正前後で表示します。
6. 確認した候補を「修正候補を適用」で保存します。操作未確認の候補は適用せず、修正後に曖昧さが増えた候補も保留します。保存だけでは自動化を開始しません。
7. 「同じ録画で改修後を再検証」、または「次の録画を選んで改修を続ける」を押します。次の解析は改修後の設定を基準に行います。停止箇所を直して実行し、その後の録画で再確認するループを繰り返せます。

「前回の録画を読み込んで再解析」でゲーム別に最後の録画を呼び出せます。端末のファイル提供元が再読み込みの許可を保持できない場合はファイルを選び直します。「改修前に戻す」または「かんたん編集 → 退避から復元」で適用前の設定へ戻せます。改修履歴の要約は直近20回を端末内に保存します。

標準設定と録画の座標系が異なる場合は、対象ウインドウ内の座標を使う追加経路を作ります。以前の領域の座標系は変更しません。追加経路は独立した目印に合わせて小さな位置・大きさの差を補正し、補正を確認できなければ入力しません。「改修後はこの録画の最初の状態からテストする」をONにすると、その録画の開始表示から検証できます。録画からはっきり分からないタップ・結果・完了は作りません。

停止した1画面だけの録画でも表示条件と長時間停止の候補を診断できます。操作後の表示が録画にないときは設定を保持し、次の録画で改修を続ける案内を出します。録画の終端は、デイリー完了や終了状態へ自動変換しません。

## APKが自律的に行う処理

| 状況 | APKの処理 |
|---|---|
| 現在状態の条件が見つからない | 登録済みの他状態も一定間隔で確認し、独立した目印と新しい2枚の画像で復帰先を確認 |
| 登録済みの別画面へ移っている | BANC回路の選択信号を確認して状態を合わせ直し、既存の操作処理へ戻る |
| 同じ遷移ボタンを押しても画面が変わらない | 3回の送信後は連続入力を保留し、8秒待機しながら別の根拠を探索。同じ状態の意図的な連打は対象外 |
| 未登録画面に読めるボタンがある | 対象アプリ・対象画面の可視で有効なボタンから候補を作り、BANC回路で選択。入力直前にもボタンを再確認 |
| 操作を送信した | 送信だけでは成功とせず、登録済みの結果画面を独立した目印と新しい2枚の画像で確認 |
| 結果を確認できた | 手順候補と結果時間を保存。成功2回以上・成功率66%以上・平均学習スコア0.05以上で画面に結びついた手順を獲得。スコアは成功＋0.2、失敗−0.5の内部評価 |
| 結果を確認できない | 未確認・失敗として記録し、同じ画面への同じ入力を保留。画像取得と監視を継続 |

未登録画面で使うボタンの種類は「閉じる・キャンセル」「このままはじめる・ゲームへ戻る」「宝箱を開ける」「報酬・コインを受け取る」「クリア後の次ステージ」です。報酬・次ステージは関連する表示も必要です。曖昧なOK、複数ある受取ボタン、課金・購入などの文脈では新しい入力を推測しません。

## 別ゲームのノウハウを使う仕組み

| 情報 | 扱い |
|---|---|
| ボタン画像・画面特徴・タップ座標 | ゲームごとに保存し、実行先で取得・確認 |
| 個別の状態ID・状態遷移・操作履歴 | ゲームとオートマトンごとに管理 |
| デイリー完了・報酬受領の条件 | 実行先の登録条件で判定 |
| 操作種類ごとの成功・失敗 | ゲーム間で共有し、候補の評価に使う |
| 操作後の応答時間 | 他ゲームの検証済み実績を使い、結果待ち時間を15～30秒の範囲で調整 |
| 確認できなかった操作の経験 | 別ゲームで同じ操作種類を試す際の評価や待機時間に反映 |
| 共通の処理手順 | ボタン特定 → 入力直前の確認 → 操作 → 結果確認 → 登録手順への復帰として再利用 |

例えば、農園で「受け取る」の後に画面が落ち着くまで時間がかかった経験は、コイン落としでも受取候補の評価と結果待ち時間に使います。コイン落とし側のボタン・位置・結果画面は、その場で確認します。他ゲームの成功回数をコイン落とし自身の成功回数へ加算することはありません。

うさポ内の農園うさぎと風船パンチも、個別の画面記憶を持ち、共通ノウハウは利用できます。オートマトンの条件・座標・履歴・画像などを編集すると、以前の画面に結びついた獲得手順をそのまま適用せず、共通ノウハウを参考に再検証します。

## 停止・完了条件

「全停止」、明示的な終了状態、録画の未確認操作、履歴条件、ミッション回収中のゲーム復帰制限を維持します。自律復帰は実行済み操作の履歴やデイリー完了を作りません。古い画像、同じ画像の再利用、複数の復帰先に一致する表示では復帰しません。

## BANCの実装範囲

BANC888 v7.12の `ConnectomeSelector` と自律学習の考え方をJavaへ移植しました。候補選択はBANC Figure 3g由来の6集約ノード・16接続、6回の活動伝播を通ります。入力・読出しの割当て、活動更新則、神経伝達物質の符号は工学的なモデルです。従来の `circuit.bin` は維持しています。

ネットワークや外部AI APIを使用せず、共有ノウハウとゲーム別記憶を端末内に保存します。BANCの一般会話・音声機能をすべて移植したものではありません。文字がユーザー補助に出ないゲーム画面の未知操作は、実演・録画登録を使って拡張します。

## 検証と現在の限界

- 元のBANC888 JavaScriptと、移植した回路の20通りの出力・16接続の報酬更新を照合。
- 全接続を切った場合に復帰・新規ボタン操作を選ばないことを確認。
- 別ゲームの成功・失敗・応答時間が選択へ反映されることと、実行先の画像・ボタン・結果確認が必要なことを検査。
- 録画比較、前回の登録操作の継承、追加結果分岐、既存状態と操作IDの保持、同一録画の繰り返しで状態が増殖しないこと、停止だけの録画の診断、ウインドウ内の座標を検査。
- 1.72の録画生成、オートマトン、既存ゲームの録画フレーム、相対位置、入力拒否・中断、デイリー巡回などを回帰検査。
- 署名、APK内のDEX、4種のCPU向けライブラリ、16KBアラインメントを検査。

検査の詳細・結果は同梱の `VALIDATION-v1.73.json` と `tests-v1.73.log` を参照してください。自動化の実機入力、F-52A・Chromebookでの停止解消、電池消費は未確認です。テストの成功率を未知ゲームへの対応率とは扱いません。

ソースの既定検査は `TAPMARKER_TEST_GROUP=core` です。過去の4録画の拡張検査 `full` には、同梱されていない旧録画フィクスチャが必要です。
