# MarkerTap v1.105：増えうさぎの縮小ミッション・増える量

`jp.tapmarker.lite` / versionName `1.105` / versionCode `108`

## 更新方法

1. 旧版で「全停止」を押し、仮想画面を閉じます。
2. `MarkerTap-v1.105-usagi-controls.apk` を上書きインストールします。
3. 対象を選び直して仮想画面を作成し、「自動開始」を押します。

以前と同じ署名証明書を使います。通常の上書き更新で設定を引き継ぎます。

## 今回の修正

- 録画6753の縮小ミッション画面について、見出しと最初の未達成項目の「プレイ」を組み合わせて確認します。主画面やCMとの誤認を避け、プレイを押してから主画面の再確認へ進みます。既存のゲット・報酬回収経路は残します。
- 画面全体から主画面の目印を探し直す場合、増えうさぎの実際の通常タップ対象も現在の画像に必要とします。ミッション一覧の文字を主画面の目印へ代用する経路を抑えます。
- 「増える量」は、左側の見出しと「必要」または「CMを見る」の表示を同じ強化ボタン内で確認します。主画面の位置補正を反映し、ボタン内の位置へ1回の強化操作を送ります。「CMを見る」での強化を最初から対象外にしていた従来処理も変更しました。
- 強化処理は通常連打とは別に動きます。送信完了だけでは成功扱いにせず、その後のレベル表示の変化を確認します。変化しなければ再確認の待ち時間を置きます。
- 強化CMが表示されたら通常の広告復帰処理へ進み、強化前のレベル表示を保持します。主画面へ戻ってから表示の変化を確認し、変わらなければ成功扱いにしません。CMが始まらない場合は10秒、復帰後に変化しない場合は3秒で結果待ちを解除します。同じ強化CMの入力は最短60秒間隔です。通貨による強化はこのCM間隔の対象外です。
- CM・ボーナス・ミッションなどの別イベントでは、新しい強化入力を保留します。コイン落としのCM除外方針は変更しません。
- 新しく追加した状態表示も日本語・英語へ対応します。

## 確認した原因と限界

v1.104の実行クラスに録画6753のミッション画面を与えると、ミッション見出しを認識できず、別の文字領域から主画面へ進む分岐が成立しました。`tests/usagi-controls-v1.104-baseline.log` に記録しています。

強化ルールを通常連打の状態機械から分離すると、画面補正側の有効ルール一覧からその参照画像が外れます。今回は増える量専用の画面根拠と入力位置を、分離後も採取・確認できるよう連携させました。

6753には強化可能な主画面や実際にレベルが上がる場面は映っていません。増える量の検出には、同梱済みの過去録画6677を使用しました。今回の端末で起きたすべての失敗原因を特定したことや、実機で強化を完了したことを意味しません。

## 検証

`UsagiControlReplayTest` は349項目。6753の2・8・16・24・32・39秒の6場面、過去の通貨・CMによる強化ボタン、押下直前の再確認、ミッション経路の解放、強化後の表示確認、CM開始失敗・復帰後の未変更・再試行間隔を検査します。

6753の0秒と、過去録画6677の0001・0059は見本作成に使用したため、新規の検証成績には数えません。CMボタンの検証には同6677の0021を使います。拡大縮小・ウインドウ位置変更・一部の隠蔽・入力完了通知・CM後の経過・レベル表示の変化は模擬です。

最終の確認結果は `VALIDATION-v1.105.json`、通常回帰は `tests-v1.105.log`、最終追加確認は `final-checks-v1.105.log` を参照してください。

Android実機は未接続です。端末上の入力配送、新APKでの実際の増強量、長時間運転、未提示のミッション配置や広告は未確認です。

## 再ビルド

Java 17、Android SDK platform 35 / build-tools 35.0.0、Python3、ripgrep、C/C++コンパイラ、元の署名鍵を使用します。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE=/path/to/original-key.jks \
bash build.sh

ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

元の署名鍵はソースZIPに含めません。
