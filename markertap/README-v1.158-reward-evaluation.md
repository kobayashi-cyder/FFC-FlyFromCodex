# MarkerTap v1.158: 報酬確定ゲート付き評価コネクトーム

## 評価関数
ゲーム／仮想画面の各レーンに独立した回路を設ける。累積評価値は以下のとおり。

```text
J = 100 × C + 20 × ln(1 + Q) - 4 × T_ad[秒]
C = 実際の報酬受領を確認したサイクル数
Q = 確定した報酬の実測増分（通貨単位はゲームごとに固定）
T_ad = 新鮮なCM肯定画像の連続区間から観測したCM滞在時間
```

C/Q一定ならCM滞在時間の短縮で J は上がる。CM滞在時間一定なら確定サイクル数・確定報酬数量が増えると J が上がる。「ゲームをクリアした」「獲得を押した」「報酬ダイアログに見える」「CMを2秒で強制終了した」だけではC・Qは増えない。CM強制終了は未確定の受領を破棄し、スコア付与しない。

## 結線と確定条件

- `CM肯定画像 → 滞在時間積算 → 評価値減点`。撮影時刻が異なる鮮度1.5秒未満の連続肯定フレームのみ計上。読み取れない区間は推定加算しない（したがって実CM時間の下界に限る）。
- `ゲーム通貨の事前残高 → 獲得操作受付 → 獲得後UIの独立証拠 → 新鮮な残高画像2枚で同一の増加を確認 → 受領確定 → サイクル・報酬数量の加点`。
- 報酬受領の識別子ごとに一度だけ加算。古いフレーム、画面の再送、数量不明、符号反転、通貨違い、タイムアウト、再起動後の未確定獲得は加算不可。
- `AutoPilot` と `SplitPilot.Slot` はそれぞれ独立した `RewardEvaluationConnectome` を持つ。レーン間で評価値を混ぜない。

## 実装済み範囲と未完了の接続

この変更は**旧ソースツリーの評価回路・CM観測の組込み**であり、配布中の署名済みAPKにはまだ反映されていない。

- 済：純Javaの受領確定ゲート・評価関数、物理／仮想のCM観測接続、広告復帰時の未確定獲得無効化、診断文字列、JVMユニット試験・CI。
- 要実装：各ミニゲームで **受領前／受領後の同一残高カウンターを確実に読み取る専用アダプター**。既存の `RewardReceipt` はポイポイうさぎの「報酬画面」または「一覧変化」を二重確認できるが、加算額の実測値は出せない。したがってこのコードだけではその操作を受領確定として加点しない。
- 要実装：実機と仮想画面でアダプターの精度、受領キャンセル時の整合性、評価値表示、ソースを署名済みDEXへ統合、APK再署名、READMEの完成版導線を検証する。
- 意図的に未実装：スコアが高くなるように広告視聴義務を回避する判断、残高実測がない場面での報酬数量の推定、「サイクル数」の遊戯ループだけによる架空加点。
