# MarkerTap ANR回避＋ChatGPT診断共有（2026-10-22）

## 対象と扱い
- 観測: Pixel 10 / Android 17 / v1.128 の障害ZIP（08:35 JST）。
- ANR履歴: main、画像解析スレッド、診断スレッドが同一 `frameLock` を待機。旧画像closeをロック内で実行する経路あり。ネイティブ処理の根本の停止理由は未確定。
- 本ブランチのコードベースは **GitHub復旧版 v1.123**。端末の **v1.128 ではない**。このブランチをビルドしても最新APKにはならず、上書きインストールすべきではない。
- ローカルに保存されている v1.127 source kit + v1.128 patch と統合する際、ロック修正とChatGPT共有を再適用する必要がある。署名鍵はGitHubに投稿しない。

## 実装したソース改修（v1.123復旧枝へのバックポート）
- `VirtualWindows`: image readerの寿命をretainしてからロック外で `RegionImage.fromImage` を構築。最新フレームの交換のみ短い `frameLock` 内で行う。
- 旧画像の `close()` を非UIの専用作業キューへ移動。積み残し8件以上で新たなフレーム受入を抑制。操作UIを画像解放に巻き込まない。
- `FrameCircuit.Input` の `tiles()`、領域プレビューの `capture()`、全画面明示取得の画素読取を共有ロック外に移し、取得時にretain・終了時にrelease。
- 画面再構築、画面解放、画面再取得に残っていたロック内旧画像解放を退避。
- `ProgressErrors`: 「ChatGPTに診断を送る（共有画面で確認）」を追加。`ACTION_SEND` の text/plain を試し、ChatGPTアプリを直接呼び出せない場合はAndroid共有先一覧へフォールバック。存在する診断ZIPはURI共有権限つきClipDataで補助的に添付。
- 従来の「画像付き診断ZIPを共有」ボタンは維持。Work必須の文言を削除。

## 自動送信の境界
- 現状のコードは**ユーザー操作による共有**。ユーザーの個別ChatGPT会話への無断・完全自動送信はできない。Androidの共有先が添付ZIPを受け付けることも保証されない。
- 将来の完全自動解析は、本人同意＋診断内容のサニタイズ＋安全な独立ゲートウェイ（OpenAI API）＋失敗時のローカル保存を備えれば実現可能。ただしOpenAI APIの呼び出しはユーザーの通常ChatGPT会話への投稿とは異なる。
- 端末識別子・資格情報・スクリーンショットにはプライバシー情報が混ざり得るため、デフォルトで外部サーバーへ送らない。

## GitHub Actionsの範囲
- 本ブランチ用のCIはソースを復元し、使い捨てのCI署名鍵でAPKをビルドして回帰テスト。生成するAPKは **CI検証専用** であり、既存アプリの更新用ではない。
- 本番には v1.128 に対する同じ改修の移植、versionCodeの単調増加、**旧APKと同じ証明書での署名**、Pixel 10実機での安定性検証が必要。
- **GitHub上のCI成功＝Android端末でANRが解消したことの証明ではない**。

## 実機受入条件
1. 2画面・1080×2424・ポップアップ／広告／手動介入ありで2時間以上のANRゼロ。
2. UIスレッドがフレーム資源解放を待たず、画像処理ロックを長時間占有しない。
3. 引き続き有効な画像のみ処理。reader寿命・参照数・保留キューの上限を監視。
4. アプリ内の「進行エラーを見る」からChatGPT送信（または共有先一覧）を開き、本文が送信できる。
5. ZIP添付がChatGPTで扱えない場合も本文コピーと従来のZIP共有が有効。
6. 自動連打が手動介入中に再開しない。
