# v1.112 — 復帰確認の循環修正

- 320pxの起動幅と現在の画面数・負荷設定を維持。
- 工場設定の6ゲームで、通常復帰の要求回数を状態名・再入場時刻とは別に保持。同じ確認状態へ戻っても失敗回数をリセットしない。
- 通常復帰3回後も30秒以上未判別が続き、新しい画像が確認できる場合は対象ゲームのタスクを再起動。同じ停止区間で最大2回、再起動間隔30秒。提供済みの特定プレイアブル広告には既存の早期復帰条件も維持。
- 判別可能なゲーム画面・キャンセル・広告の閉じる操作を優先。再起動上限後も画像監視と明示的な閉じる操作は継続。別画面は停止させない。
- 通常の復帰要求・再起動の送信失敗や古いコールバックでも要求回数を消さない。停止・画面の世代変更で保留中の起動を無効化。
- コインのミッション回収中は復帰確認からミッション表示の確認へ戻す。復帰要求の送信を回収完了として数えない。
- コインは全候補の現在位置・保存位置を先に確認し、不一致の画面候補の詳細探索を1画像につき2候補へ分散。毎回同じ候補から探索しない。
- 画像一致距離と通常連打の許可状態を分離して診断へ追加。実際の広告表示を確認していない休止を「CM終了待ち」と表示しない。
- 編集済み・学習済みの独自オートマトンには新しい再起動方針を適用しない。
- 実行部のプロトコルはv1.111のrevision 91と互換。v1.110から更新する場合は更新後に端末内接続を作り直す。

実機の画面内容、広告終了、ゲームの進行、報酬加算はホストテストだけでは確認できない。
