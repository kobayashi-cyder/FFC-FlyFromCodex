# MarkerTap v1.114 — 表示中のポップアップから復帰

`jp.tapmarker.lite` / versionName `1.114` / versionCode `117`

## 更新手順

1. 旧版で「全停止」。
2. `MarkerTap-v1.114-popup-controls.apk` を上書きインストール。
3. 「端末だけで接続」で実行部に接続し、「自動開始」。

既存の署名を維持しています。起動幅320px・選択アプリ・画面数の設定は維持します。
削除してからの再インストールは不要です。

## 今回の修正

- 増えうさぎ・コイン落としにも、詳細な主画面探索より前にポップアップを確認する経路を追加しました。
- 録画6772で確認した、白い下部パネルと一部だけ見える灰色の閉じるボタンを2領域の画像で照合します。画像の外にあるボタン中央ではなく、画像内に見えている部分へ入力します。任意の下端のボタンを押す処理ではありません。
- ユーザー補助に「閉じる」という操作名がある場合も、そのボタンの見えている範囲を利用します。対象アプリ・対象ディスプレイ・操作可能なノードという条件を維持します。獲得やCM開始のボタンには、画面外に欠けたボタンの例外を適用しません。
- ポイポイの「コインアップチャンス」の見出しと「このままはじめる」を、既存の文字画像と照合してから処理します。今回の表示位置のずれを補正します。CMを見る黄色のボタンはこの入力先にしません。
- 農園の期間告知は、録画にある2領域の表示と実際の丸い×を確認して閉じます。読み込み中にもこの告知を確認できます。
- ポップアップを確認できた場合は、詳細探索・録画からの修復探索などを同じフレームで重ねて実行しません。新しい画像と2回の観測を必要とする条件は維持します。
- 通常の復帰要求・タスク再起動要求の回数を、受付、対象アプリの表示確認、主画面の確認から区別して診断へ記録します。要求したことだけで再起動の成立やゲームの復帰を確認済みにしません。
- Google Playなど対象外アプリへ切り替わり、通常復帰で戻らない場合は、3回目の復帰要求で対象ゲームのタスク再起動を要求します。入力対象アプリの制限は維持します。
- 復帰回数が上限に達していても、実際に確認できたポップアップの閉じる・通常継続は処理できます。閉じる入力の完了だけで通常連打や報酬加算を確認済みにしません。

## 確認した範囲

録画6772の48個のプレビュー切り出しを保存しています。下端のボタン外観は増えうさぎ0秒、農園の見出しは28.07秒を参照として使い、ほかの時刻で照合しました。同じ録画内の似た静止表示であり、未知のあらゆるポップアップへの対応を示すものではありません。

録画内で途中に挟まるポイポイの広告には、従来の右上の×処理を使うことも確認します。ポイポイの継続ボタンの見本は従来のままで、新しい広告の見本へ置き換えていません。

繰り返し観測、320px・540pxへの拡縮、部分的な遮蔽、上限消費後の状態、操作完了通知はホスト上の再現条件です。実際の320×718のImageReader画像、Android 17への入力到達、ゲーム側の応答、報酬残高や4画面の長時間動作は実機未検証です。

## 再ビルド

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE=/path/to/lite-development.jks \
bash build.sh
ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

Android API 35・Build Tools 35.0.0・Java 17・Python 3・ripgrepを使用します。署名秘密鍵は同梱しません。
録画の再現データの再生成には、元の6772.mp4、ffmpeg、Pillow、NumPyを使い、`python3 tools/create-popup6772-replay.py /path/to/6772.mp4` を実行します。

標準のcoreテストを配布データで実行できます。fullの追加4録画テストには旧録画の別データが必要で、このソース一式には含まれていません。検証の実行範囲は `VALIDATION-v1.114.json` に記録します。
