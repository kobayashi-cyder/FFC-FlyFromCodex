# MarkerTap v1.158: 報酬確定ゲート付き評価コネクトーム

## 評価関数
ゲーム／仮想画面の各レーンに独立した回路を設ける。累積評価値は以下のとおり。

```text
J = 100 × C + 20 × ln(1 + Q) - 4 × T_ad[秒]
C = 実際の報酬受領を確認したサイクル数
Q = 共通pt残高から実測した確定増分（単位：pt）
T_ad = 新鮮なCM肯定画像の連続区間から観測したCM滞在時間
```

C/Q一定ならCM滞在時間の短縮で J は上がる。CM滞在時間一定なら確定サイクル数・確定報酬数量が増えると J が上がる。「ゲームをクリアした」「獲得を押した」「報酬ダイアログに見える」「CMを2秒で強制終了した」だけではC・Qは増えない。CM強制終了は未確定の受領を破棄し、スコア付与しない。

## 結線と確定条件

- `CM肯定画像 → 滞在時間積算 → 評価値減点`。撮影時刻が異なる鮮度1.5秒未満の連続肯定フレームのみ計上。読み取れない区間は推定加算しない（したがって実CM時間の下界に限る）。
- `ゲーム通貨の事前残高 → 獲得操作受付 → 獲得後UIの独立証拠 → 新鮮な残高画像2枚で同一の増加を確認 → 受領確定 → サイクル・報酬数量の加点`。
- 報酬受領の識別子ごとに一度だけ加算。古いフレーム、画面の再送、数量不明、符号反転、通貨違い、タイムアウト、再起動後の未確定獲得は加算不可。
- `AutoPilot` と `SplitPilot.Slot` はそれぞれ独立した `RewardEvaluationConnectome` を持つ。レーン間で評価値を混ぜない。共通pt残高の二重帰属を避けるため、請求受領ウィンドウの競合時は両方の評価を無効化する。

## 実装済み範囲と未完了の接続

この変更は**旧ソースツリーの評価回路・CM観測の組込み**であり、配布中の署名済みAPKにはまだ反映されていない。

- 済：純Javaの受領確定ゲート・評価関数、物理／仮想のCM観測接続、広告復帰時の未確定獲得無効化、診断文字列、JVMユニット試験・CI。
- 済（候補実装）：提供画像の左上 `10,175pt` 表示を元に、共通白背景ヘッダーの数字列および `pt` 接尾辞を画像から読む `KurashiruPointHud` を追加。物理単独、2レーン分割、仮想画面の各フレームに接続し、`observeBalance("pt", ...)` を供給する。実測値が判定できないフレームは棄却。
- 済（候補実装）：増えうさぎ、コイン落とし、ショッピング、ボックスマージ、ポイポイうさぎの指定された回収操作のみ `claimSent` を認め、独立した報酬画面証拠を新しい2フレームで確認してから、さらに同じpt残高の安定した増加を2フレームで確認して加点。
- 済：複数ゲームが共通pt残高を同時回収した場合は帰属が曖昧なため、`SharedPointClaimArbiter` が両方の評価を拒否する。操作や残高自体を無理に変更するものではない。
- 済（候補実装）：農園うさぎには、報酬画面を閉じた時点ではなく、プレイ画面で実測した事前pt残高、報酬ダイアログの連続2画像、以降の新しい2画像での安定したpt増分を満たす `FarmPassiveReward` を接続。まだ実機検証前。
- 要実装：全ミニゲームの画面比率／フォント／上部ヘッダー座標の実機校正。開拓うさぎの報酬受領イベントは独立したv1.157 DEX回路にあり、v1.158の共通評価回路への直接接続は未実装。未検証報酬は加点しない。
- 要実装：実機と仮想画面でOCRの精度、受領キャンセル時の整合性、評価値の画面表示、ソースを署名済みDEXへ統合、APK再署名、メインREADMEの完成版導線を検証する。
- 意図的に未実装：スコアが高くなるように広告視聴義務を回避する判断、残高実測がない場面での報酬数量の推定、「サイクル数」の遊戯ループだけによる架空加点。

## ユーザー提供画像による共通ヘッダー観測

2026-11-04の参考画像（1080×2424）では、左上の白いカプセル表示に `10,175pt`、その右にミッションボタンがある。ポイント欄だけを画像解析し、ミッションの数字、ゲーム内部の枚数、広告の表示文字を残高として読み取らない。

現在の画像読取器は正規化範囲 `x=0.105〜0.392, y=0.089〜0.111` にある白背景の黒文字と `pt` 接尾辞を照合する。フォント違い・数字の潰れ・不一致・白背景がない場合は -1 とし、推定値を出さない。最小表示幅・画像の鮮度チェックも適用。

**重要**：他のタイトルでも同一位置にポイント欄があるというユーザー観察は有用だが、全ゲーム、全端末、全仮想画面で位置と文字デザインが完全一致することは未検証。確認できない画面は欠測として扱う。

JVMユニットテスト：`KurashiruPointHudTest`, `KurashiruPointHudRecordedTest`, `KurashiruClaimPolicyTest`, `SharedPointClaimArbiterTest`, `FarmPassiveRewardTest`。提供された実画面の数字形状を圧縮した読取テストは `10,175pt` を再現し合格。各ゲームのライブ画面での正読率を保証するものではない。

テスト合計は 41 + 7 + 1 + 30 + 11 + 21 = **111**（うち録画画像由来の実画像1試験）。併せて接続点の静的検査を実施。JVM単体テストは `markertap/v1.158-host-tests/` に隔離（旧Androidビルドのテスト偽クラス競合を防止）。


## ビルドと署名について

- `.github/workflows/markertap-v1158-full-source.yml` は保存済みの旧ソースアーカイブを復元し、現在のソース差分を上書きしてAndroidコンパイル・APKパッケージ化・一時鍵によるv2/v3署名を検証する。**生成物のAndroidManifestは旧ソース由来のv1.123であり、v1.158リリースやv1.157の上書き更新APKではない。**
- 既存の `run-tests.sh` は旧テスト `LoopbackRetryPolicyTest` に依存する `LoopbackRetryPolicy` クラス欠落により失敗するため、フルソースビルドの試験から分離した。これは既存テストの未修正欠陥であり、「すべての既存テスト合格」として扱わない。
- v1.158を原署名証明書で公開するには、v1.157署名済みDEXへの評価回路統合（または同等の完全なAPK再ビルド）と、原署名鍵の正規受け渡しが必要。v1.157の署名手順は一時公開鍵と原JKSの暗号化受け渡し方式であり、秘密鍵はリポジトリに存在しない。この変更だけでv1.158の原署名済みAPKが自動生成されるわけではない。
