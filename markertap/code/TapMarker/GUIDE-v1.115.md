# MarkerTap v1.115 — 通常獲得と、閉じない下端広告からの復帰

`jp.tapmarker.lite` / versionName `1.115` / versionCode `118`

旧版で「全停止」してから `MarkerTap-v1.115-offline-recovery.apk` を上書きインストールし、端末内接続後に「自動開始」してください。署名の一致を検証した更新APKです。

## 改修した原因

録画6774では、コイン落としのオフラインボーナス×154が表示されたままでした。v1.114のソースには、コイン落としの通常獲得を処理する分岐がなく、名前付き「獲得」も対象から外れていました。

また、増えうさぎの下端に一部だけ見える「閉じる」はv1.114の画像認識で検出できましたが、録画中の表示は変わりませんでした。この入力がゲーム側で受理されたかは録画だけでは確定できません。ソース上では、この下端の閉じる入力に回数制限がなく、同じ認識を復帰済みの根拠として扱って再試行を続ける問題がありました。

## 変更

- コイン落としの通常獲得を、既定の各稼働状態から処理します。ミッション中は回収先を保持します。名前付き操作と画像の両方に対応します。
- 画像では黄色い見出しの位置を測り、「オフラインボーナス」と、その下の白い「獲得」を別々に照合します。増えた枚数は見本に含めません。「CMをみて獲得2倍」は入力先にしません。
- 見出し、通常獲得、白い本体が広告で隠れた場合は、獲得を押しません。認識した画面の寸法とウインドウ位置に対応した入力座標だけを使います。
- 下端広告の閉じるは、画像認識・名前付き操作の双方で、同じ表示につき最大2回、各入力の応答待ちを挟んで送信します。表示が残る場合は広告復帰状態へ移り、既存の対象画面への「戻る」2回、対象アプリへの復帰、必要時のタスク再起動へ進みます。
- 上限に達した閉じる表示を、復帰処理の取り消し根拠にしません。回数は画面ごとに独立しています。2回の新しい画像で下端表示の消失を確認すると、次の表示を処理できます。
- 入力の完了通知だけで、報酬加算やゲーム復帰を成功扱いしません。

## 検証の範囲

録画6774から52個のプレビューを切り出しました。コイン6秒の見出しと獲得文字を参照とし、ほかの時刻で確認しています。同一録画内の確認であり、独立した別セッションの検証ではありません。0秒・2秒のコインは広告で覆われており、通常獲得を出さない条件です。

320px・540pxへの拡縮、位置移動、枚数部分の変更、領域の遮蔽、閉じる後に表示が変化しない場合、入力完了通知はホスト上で再現した条件です。Android 17実機への入力到達、報酬加算、実際の広告終了、4画面での長時間運転は未検証です。実行した回帰テストは `VALIDATION-v1.115.json` と `tests-v1.115.log` に記録します。

## 再ビルド

Android API 35・Build Tools 35.0.0・Java 17・Python 3・ripgrepを使用します。秘密鍵は同梱しません。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk TAPMARKER_KEYSTORE=/path/to/lite-development.jks bash build.sh
ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

標準core一式は同梱データで実行できます。fullの追加4録画には、このソースに含まれない旧録画のデータが必要です。
