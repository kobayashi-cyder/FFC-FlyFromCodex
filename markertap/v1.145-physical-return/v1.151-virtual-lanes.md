## Changes shipped in this candidate source
1. `VirtualFrameQueue` now holds up to **two in-flight screenshot requests** with one request per (generation, display ID). Global Android screenshot issue pacing remains 400ms. One callback can stall without blocking another display's **issuance** for the full original 2.5s timeout.
2. Late success/failure cannot finalize a removed or expired request; no image may be attributed to the other display or an earlier run generation.
3. A one-display removal clears only that display's queue entry. The existing backend-fatal policy remains intact: a genuinely removed virtual display still triggers the previous full-session safety stop. This change does not covertly relax owner-death cleanup.
4. `VirtualPreviewVisibilityBridge` transforms `View.GONE` into `View.INVISIBLE` when hiding the **phone-side** virtual preview. This retains measured view layout; it does not release or recreate the VirtualDisplay, ImageReader, input target or automation state. It is a mitigation experiment for the reported collapse/offline correlation, **not a verified network fix**.
5. The screenshot hardware-copy executor now has two workers and a **bounded capacity of two queued callbacks**. A hung copy worker cannot monopolize the other display's copy slot; overload fails closed instead of creating unbounded memory pressure.
6. The DEX integration patcher replaces the baseline `VirtualFrameQueue` (including `$Request`), redirects the virtual preview visibility call, and checks the original ABI and final bytecode against the exact overlay. It fails closed if the baseline methods or hooks differ.
7. `build.py`, `sign-release.py` and `release-local.py` have v1.151/versionCode154 and preserve the original update certificate and existing SHA safeguards.

## Remaining blockers / acceptance
- The full APK was built and checked from the pinned public signed v1.150 baseline. **Still requires the original non-public signing key to sign v1.151**, independent signing certificate verification and actual Pixel 10 acceptance before Release promotion.
- On Pixel 10 / Android17: test both 1 and 2 virtual displays, both physical and virtual controls, and each display's screenshot age/input counter; force one screenshot callback to stall and verify the second display still publishes.
- Collapse and expand **each** virtual preview while the game is online. Distinguish an app-side offline banner from a lost ADB/Shizuku binder and a stale or black frame. Verify the games keep progressing and rewarded actions are confirmed.
- Verify that the DEX bridge changes only `VirtualWindows.frameCopyWork` and not its retirement or preview executors. Measure process memory/HardwareBuffer pressure. In-flight screenshot concurrency can increase peak memory and must be disabled or reduced for low-memory devices if it regresses stability. If Android screenshot throttling is hit, tune cadence rather than blindly shortening delays.
- Do not claim fully autonomous gameplay or a network fix without the above on-device evidence.

- The pinned v1.144 baseline **bytes are available in the user's private file library** and were independently hashed in an isolated container: **5,639,011 bytes**, SHA-256 `f62e8d6020a3cacb2ea9a9085be235ea48da12f03c5de2f4e3ae80b801b6e970` (exact match). This is *not* a signed v1.151 build or a verification of the APK's signing certificate. See [v1.151-baseline-sha256-audit.json](v1.151-baseline-sha256-audit.json); the APK itself is not committed.
- The preflight for the prior candidate commit `b2c13153` completed successfully: [Actions run 41550684945](https://github.com/kobayashi-cyder/FFC-FlyFromCodex/actions/runs/41550684945). Subsequent commits need their **own** green CI run before accepting them.
- Extra JVM assertions now cover removing one of two active requests, callback after removal, reused display ID with a new generation, and expired/stale image rejection. These are host tests only.
- **Follow-up implementation:** The screenshot copy executor now uses a bounded two-worker pool (2 active + 2 queued); a blocked screen's callback cannot monopolize the only copy thread. The DEX patch must confirm the exact `frameCopyWork` field assignment. On-device memory and hardware buffer compatibility remain unverified.
- **Important limitation:** `displayListener.onDisplayRemoved` still invokes `backendLost()` for one removed display. This preserves the old safety stop, but it does **not** meet a stronger requirement of recovering a single lost display while the other continues. Distinguish intentional removal and one-display loss from actual backend death in a separately reviewed, tested change.
- Preview `INVISIBLE` only retains the host view's layout. It does not prove the game's network session stays online after collapse. No release promotion until the actual game-side offline indicator and reward progress are tested on Pixel 10 / Android 17.
