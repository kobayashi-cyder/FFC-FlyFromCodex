# MarkerTap v1.75 — 広告の黒い余白・左上スキップ・最後の×での停止を修正

`MarkerTap-v1.75-ad-stall-fix.apk` を現行版へ上書きインストールし、対象アプリを開いて「自動開始」で再開してください。

パッケージは `jp.tapmarker.lite`、versionNameは `1.75`、versionCodeは `78`。従来版と同じ開発用署名で更新します。仮想画面を使う場合は、更新後に端末内の実行部も起動し直してください。実行部の通信プロトコルは75です。

## 添付4画面への対応

| 画像 | 確認できる表示 | v1.75の処理 |
| --- | --- | --- |
| 6695.png | 右上の「5s」、左上のフィードバック印 | 終了操作を送らず、スキップ・×が出るまで待機する |
| 6696.png | 黒い上余白の下、左上の三角＋縦棒 | 現在のスキップ記号の位置を取得して操作し、次の表示を確認する |
| 6697.png | 黒い上余白の下、左上の丸いスキップ印 | 同じ終了操作の判定を適用する |
| 6698.png | エンドカード右上の白い× | ×の中心を取得して操作し、ゲームまたは次の広告画面を確認する |

旧v1.74のランタイムでは、4枚すべてで広告終了の検出値が0でした。探索範囲が画面上端の14%に固定され、今回のスキップや×が範囲外にありました。また、農園の共通広告判定には三角＋縦棒のスキップ形状が含まれていませんでした。

今回の修正は、画面上部の黒い余白から探索範囲を補正します。画面全体をゲームの配置として切り詰めず、広告の隅だけに適用します。農園・増えうさぎ・コイン落とし・お店屋さんで広告記号の判定を共有し、ゲーム固有の画面見本や学習保存先は従来どおり分かれています。

## 終了から復帰まで

1. 画像で×またはスキップを確認します。終了印が見つからない間は連打を保留します。
2. 新しい画像でも表示が成立していることを確認し、その画像上の位置で操作します。
3. スキップ後に別位置の×が出る場合は、次の画像から位置を取り直します。
4. ゲーム表示が確認できれば、該当する操作・収穫へ戻ります。
5. 終了印が見つからない場合は、従来の待機上限後に対象画面で「戻る」を最大2回試し、登録アプリへの復帰処理へ進みます。通常の広告状態では初回30秒、既存の報酬広告で設定された120秒の上限は維持します。

秒数、縦棒がない再生三角、広告中央の「Install」「詳細を見る」、関心の選択肢は新しいスキップ操作として扱いません。既存のコイン・お店屋さんの録画由来の終了記号も使えます。

操作パネルには「広告：終了印待ち」「広告：閉じる・スキップを確認中」「広告：戻る・復帰を確認中」を優先して表示します。「復帰確認まで」の秒数はアプリ側の待機設定を表し、広告側の残り秒数を読み取った値ではありません。

## 検証

新しい `AdStallScreenshotTest` は添付4枚を丸ごとの検査画像として使用します。これらの画像から新しい学習見本を作って照合する実装にはしていません。

- 原寸と3種類の画面サイズ、最近傍・補間リサイズでの位置確認。
- 「5s」での操作保留、スキップ→別位置の×→ゲーム確認→主画面復帰。
- 縦棒を消した再生三角、×を消したインストール画面、従来のゲーム・報酬画面の除外。
- 終了印が消えた場合の操作取消、画面サイズ変更後の古い座標の拒否。
- デスクトップ上で移動した対象ウインドウへの座標変換。
- 従来のBANC、録画改修、農園ダイアログ、コイン・お店屋さん、巡回、入力中断、接続・暗号などの既定回帰検査。
- 最終APKの署名・旧版との証明書一致・バージョン・DEX・4種類のCPU向けライブラリ・16KB配置。

結果は `tests-v1.75.log` と `VALIDATION-v1.75.json` に含めます。Android実機での広告タップ・SDKによるスキップ受付・報酬付与は未検証です。新しい三角＋縦棒の形状以外を使う広告や、終了を受け付けない広告には待機・戻る・復帰処理が適用されます。

## 再ビルド

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk TAPMARKER_KEYSTORE=signing/lite-development.jks bash build.sh
ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

SDK platform 35・build-tools 35.0.0とJava 17が必要です。過去の4録画を使う任意の `full` 検査には、従来どおり別途の録画フィクスチャが必要です。新しい検査画像はソースに含まれています。
