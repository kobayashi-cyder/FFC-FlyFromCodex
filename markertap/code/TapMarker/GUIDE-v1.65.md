# MarkerTap v1.65 軽量版

添付のv1.64を基に、他のARM端末でも使いやすいように処理負荷と対応CPUを修正しました。APKは **3,029,116 bytes（約3.03MB）**。元の4,220,897 bytesから約28.2%削減しています。

## インストールと開始

1. 旧版を使っている端末では、旧版の「全停止」を押し、仮想画面を閉じ、旧版のユーザー補助をOFFにします。
2. `MarkerTap-v1.65-portable-lite.apk`をインストールします。アプリ名は「マーカー連打 軽量版」です。
3. 軽量版のユーザー補助を有効にします。Androidが制限している場合は、アプリ情報の「制限付き設定を許可」を確認してください。
4. 負荷設定はまず「自動」。動作が重い場合は「軽量」を選びます。
5. 仮想画面では、軽量版で「端末だけで接続」を設定し、対象アプリを選び、仮想画面を開いて開始します。

**旧版とは別アプリです。** 元の更新用署名鍵が添付ソースに含まれていなかったため、旧版をアンインストールせずに導入できる独立版にしています。旧版の設定・ペアリングは自動移行されません。標準4アプリのオートマトンは引き続き同梱しています。

## 負荷設定

以下は仮想画面の設定値です。実際の処理速度・タップ間隔は端末とアプリに依存します。

| 設定 | 仮想画面の幅の上限 | 画像取込の最短間隔 | 判定の最短間隔 | プレビューの最短間隔 | 連打間隔の下限 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 自動 | 端末に応じて軽量／標準 | 同左 | 同左 | 同左 | 同左 |
| 軽量 | 540px | 220ms | 350ms | 500ms | 24ms |
| 標準 | 720px | 140ms | 220ms | 300ms | 12ms |
| 高速 | 720px | 70ms | 120ms | 180ms | 3ms |

低RAM判定、アプリのメモリ枠、端末の総メモリ、CPU構成を基に自動選択します。画像バッファの予算に応じて幅をさらに下げます。処理時間が長い場合は判定周期を延ばし、メモリ不足通知時は一時的に軽量設定へ切り替えます。

保存した連打間隔が上表より長い場合、その設定を優先します。表示サイズを変えるには仮想画面を開き直してください。文字の認識が止まる場合は「標準」を選び、開き直してください。複数ゲーム自体の描画負荷は残るため、低性能端末では少ない画面数から増やしてください。

## 主な修正

- 32bit ARM（armeabi-v7a）と64bit ARM（arm64-v8a）の通信・ペアリング用ネイティブ部品を同梱。x86端末向けのAPKではありません。
- 仮想画面の画像をARGB配列として保持。判定用配列を再利用し、通常の判定でフルサイズBitmapを毎回生成・破棄する処理を除去。
- 通常画面・学習画面では画素を32×32タイル単位で一括取得。最大64タイルのキャッシュを使い、1画素ずつのJNI呼出しを削減。
- 通常の複数ウインドウでも領域判定をUIスレッドの外へ移動。仮想画面のプレビュー生成もUIスレッドの外で実行。
- 同じ取得時刻の画像を再判定せず、新しい画像を待機。古い画像、停止後の処理、状態が切り替わった後の結果を実行に使わない。
- 初期見本のJSON解析をキャッシュ。呼出し元には独立した配列を返し、設定の相互変更を防止。
- 回路の作業配列を再利用。各画像で状態をリセットし、従来の計算結果を維持。
- ネイティブ部品とDEXを圧縮。ネイティブ部品はインストール時に展開する設定に変更。

例として1080×2424の端末では、従来の720×1616の主なアプリ内画像バッファ3本は約13.96MBです。新版は同サイズで2本、約9.31MB。軽量の540×1212では約5.24MBになります。これは配列・Bitmapのサイズからの計算で、実測RAM使用量ではありません。ImageReader／GPU／プレビュー／ゲーム本体などの使用量は含みません。半透明画素があるフレームでは、従来のBitmap変換と色を合わせる互換経路を使い、一時バッファも必要になります。

標準4アプリの見本、回路、ライセンスを含む元APKの全assetsはバイト単位で維持しました。状態判定の閾値や矢印の操作順序も維持しています。異なる画面を容量削減のために同じ状態へ統合する変更は行っていません。

## 対応範囲と検証

| 機能 | 必要なAndroid版 |
| --- | --- |
| 通常のマーカー連打 | Android 7以降 |
| 単一画面の画像判定／仮想画面 | Android 11以降 |
| 通常の複数ウインドウの画像判定 | Android 14以降 |

仮想画面の作成・入力には端末側の対応と適切な接続設定が必要です。メーカー固有の制限はこのビルドでは実機確認できていません。

- Javaの46組のホストテストと、ADB起動の模擬8シナリオが成功。
- 画面遷移、停止、古い完了通知、独立した入力レーン、保護表示、重複整理、録画領域、暗号交換を確認。
- 新規テストではRGBAの配置・チャンネル・バッファ再利用、画素キャッシュの一致、メモリ予算、回路の従来出力との一致を確認。
- 540px／720px幅へ縮小した既存の増えうさぎ・農園うさぎ録画で、主画面の認識と座標範囲を確認。未知の暗い画面から連打状態へ進まないことも確認。
- APKのv2／v3署名、コンポーネント、両ARM ABI、各ネイティブELFの16KiBページ対応を確認。

**実機のインストール、速度、電池消費、Android TLS通信、複数ゲームの長時間並列運転は未確認です。** 大容量の録画列が配布ソースから省かれているため、Video6651／6662／6666／6669の全列再生テストは今回は実行していません。縮小録画の成功は、全端末・全状態の認識を保証するものではありません。

詳細はソースの`VALIDATION-v1.65.json`と`tests-v1.65.log`にあります。Bitmapの色変換を合わせる処理は[AndroidのBitmap仕様](https://developer.android.com/reference/android/graphics/Bitmap)に基づきます。

## ソースと再ビルド

`MarkerTap-v1.65-source.zip`を展開し、`TapMarker`で実行します。Java 17、Android API 35／Build Tools 35.0.0、Python 3、rg、C／C++コンパイラが必要です。

```sh
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE="$PWD/signing/lite-development.jks" \
bash build.sh

TAPMARKER_TEST_GROUP=core \
ANDROID_SDK_ROOT=/path/to/android-sdk \
bash run-tests.sh
```

同梱の開発署名鍵は、この軽量版の次回更新に使えます。旧版v1.64の署名鍵とは異なります。任意のABIを選ぶ場合は、`TAPMARKER_ABIS=arm64-v8a,armeabi-v7a,x86,x86_64`などを指定します。
