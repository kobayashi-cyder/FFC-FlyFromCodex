# MarkerTap v1.68 — 農園うさぎのボタン判定修正

農園うさぎの通常画面で「閉じる」「このままはじめる」を認識する処理と、取得できた「宝箱を開ける」ボタンの実位置をタップする処理を追加しました。デイリー全達成・報酬受取済みを確認して次のアプリへ進み、最後のアプリで停止する処理を継続しています。完了条件は、各アプリの実際の完了画面から初回に登録します。今回の動画には全デイリー終了後の表示がなく、完了画像は同梱していません。

## 更新

1. 旧版で「全停止」を押し、仮想画面を閉じます。
2. `MarkerTap-v1.68-window-relative.apk`を上書きインストールします。v1.65／1.66／1.67軽量版と同じパッケージ `jp.tapmarker.lite`・署名です。アンインストールは不要です。
3. 「マーカー連打 軽量版」のユーザー補助を有効にします。画像認識による自律にはAndroid 11以降が必要です。
4. 仮想画面では「端末だけで接続」から実行部を起動し直し、画面を開き直します。実行部もv1.68へ更新しています。

v1.64以前の通常版 `jp.tapmarker` とは別アプリです。通常版からの自動設定移行はありません。

## 農園うさぎの未タップへの修正

手元のPixel録画を再生すると、従来の「閉じる」判定は、仮想画面用の報酬見出しを通常画面にも要求して一致しませんでした。「このままはじめる」は、背景の色や縮小による細い文字の変化に左右されていました。

| ボタン | v1.68の処理 |
| --- | --- |
| 閉じる | 通常画面の「コインを獲得しました」と「閉じる」の黒い文字を別々に照合し、確認したボタン内をタップします。従来の仮想画面用の見本も維持します。 |
| このままはじめる | CM案内の文字と、下にある開始ラベルの白い文字を別々に照合します。背景と獲得コイン数への依存を減らし、下の開始ラベルをタップします。 |
| 宝箱を開ける | 旧設定は宝箱の演出を待つだけで、開くボタンへのタップがありませんでした。対象アプリがユーザー補助にこのボタン名と範囲を公開している場合、その実位置を取得してタップします。 |

ボタンごとに表示位置を確認するため、主画面の位置がまだ決まっていなくても通常ダイアログを判定できます。2回の一致確認、入力直前の再確認、対象アプリ・表示先の確認を通します。画像やウインドウの大きさが変わった場合は、古い座標を使いません。通常画面・仮想画面・分割ウインドウの標準設定に適用します。標準設定には宝箱の遷移を自動追加します。

**宝箱の画像UIへの対応は未完了です。** 提供済みの6612／6614録画には、自動で開く宝箱の演出があり、「宝箱を開ける」ボタン自体は確認できませんでした。対象アプリがボタン名を公開せず、画像として文字を描いている場合、今回追加した名前による取得処理は働きません。F-52Aでそのボタンが表示されているスクリーンショットか短い録画が必要です。

手動編集・学習済み設定は自動更新対象外です。手動で記録した宝箱の画像条件と位置も保持します。デイリー全達成を確認中の場合は、この3つの操作よりも次のアプリへの切り替えを優先します。

## デイリー終了後に次のアプリへ

1. 全デイリーを達成して報酬も受け取り、その状態が明示されるミッション画面を開きます。
2. 操作パネルの「デイリー完了を登録」で対象の通常画面または仮想画面を選びます。
3. 「2領域を選ぶ」を押し、**全デイリー達成・受取済みの文字や印**をドラッグで囲み、続けて**デイリーミッションの見出し**を別の範囲で囲みます。
4. 各アプリで登録します。通常画面と仮想画面は別に保存します。異なる端末では、その端末の表示で登録してください。
5. 「デイリー巡回」で対象を選び、「巡回開始」を押します。番号の表示順で1アプリずつ実行します。

完了表示と見出しの両方が2回続けて一致した場合だけ、現在の連打・自律を止め、次のアプリを開いて自律を開始します。最後で巡回を停止します。全達成後に「プレイ」「GET」が残っていても、次のプレイ操作や時間切れの再試行を保留してアプリを切り替えます。

空欄、ボタンが消えた状態、1つのミッションの達成印、「プレイ」ボタン、待ち時間を全デイリー完了の根拠にはしません。全達成だけに現れる固定の表示を登録してください。完了条件未登録では巡回できません。標準4アプリ以外は操作のオートマトン設定も必要です。「全停止」で巡回と次のアプリの遅延起動を取り消せます。

仮想画面では現在のアプリ1つだけを操作し、他の選択画面に「順番待ち」、終了済みの画面に「デイリー完了」を表示します。

## ミッション確認の多発と画面認識の修正

旧版は赤いミッション通知に一致するとミッション画面を開いていました。通知自体は達成の証拠ではないため、この遷移を標準設定から削除し、既存の標準設定にも移行処理を入れました。ボーナス開始後も、直ちにミッションを開かず主画面の判別へ戻します。

残り数は数字欄全体の「0」で判定し、複数桁の数字に含まれる0では移りません。クリアやボーナスを確認したあとのミッション処理は維持します。これはデイリー全達成とは別の条件です。

動画では中央の「増やす」ボタンや背景が動いていました。固定された上部表示と下部ラベルの2領域を用いる主画面の見本を追加し、動くボタンへの依存を減らしました。

認識・タップ位置を対象アプリのウインドウ範囲とゲーム表示領域から変換します。移動、画面サイズの違い、左右の黒帯を扱い、判定時から範囲が変わると再取得を待ちます。増えうさぎ・農園・コイン落とし・買い物の標準設定にこの変換を通しています。

F-52A向けの自動負荷設定とAndroid 11／12の仮想画面入力は継続しています。F-52Aで複数アプリを扱う場合は仮想画面を利用してください。通常の分割ウインドウでの複数画面判定はAndroid 14以降です。詳細は同梱の `GUIDE-v1.66.md` を参照してください。

手動編集した独自オートマトンは標準設定の自動更新対象外です。以前の標準設定を編集して使っている場合は、バックアップ付きの「標準設定に戻す」で新しい標準設定を適用できます。

## Lenovo Chromebookの対象アプリUI

ARM32／ARM64に加えx86／x86_64を同梱し、タッチスクリーン必須条件を外してウインドウ変更に対応しました。

**操作対象のアプリ自体のボタン、配置、画面遷移が異なる場合は、そのUIに合う認識領域と操作順序が必要です。** 相対位置の変換だけでは配置変更を解決できません。Chromebook上のゲーム画面資料がないため、固有UIの標準設定は未調整です。

その端末で既存の「学習開始」から操作を一周実演し、「学習終了・作成」でウインドウ基準のオートマトンを作成できます。完了画面は別途「デイリー完了を登録」で記録します。こちらで標準設定を調整するには、Chromebookのゲーム主画面・ミッション一覧・報酬受取後・全デイリー終了時のスクリーンショットか動画が必要です。

## 再ビルド

ソースZIPを展開し、`TapMarker`で実行します。Java 17、Android API 35／Build Tools 35.0.0、Python 3、rg、C／C++コンパイラが必要です。

```sh
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE="$PWD/signing/lite-development.jks" \
bash build.sh

TAPMARKER_TEST_GROUP=core \
ANDROID_SDK_ROOT=/path/to/android-sdk \
bash run-tests.sh
```

既定出力は `../MarkerTap-v1.68-window-relative.apk`。署名鍵と4種類のCPU用ネイティブライブラリを同梱しています。
