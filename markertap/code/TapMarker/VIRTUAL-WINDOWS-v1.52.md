# v1.52 仮想画面の個別準備とADB接続

標準権限方式で、最初のアプリの起動が拒否された時に、残りのアプリが「準備中」のまま取り残される問題を修正。画面ごとの準備・起動・表示確認・失敗を個別に管理し、全対象が確認できるまで自律開始しない。準備停止後のSurface通知・起動完了・画像通知は自動開始に使用しない。

配置方式に「仮想画面（ADB接続・Shizuku不要）」を追加。PCからインストール済みAPKの実行部を起動する。操作は [adb/README-JA.md](adb/README-JA.md) を参照。PCとADB接続は実行中維持する。標準権限方式・Shizuku方式も選択可能。

ADB接続窓口はDUMP権限で保護し、呼び出しUIDがshell/rootの場合だけ受け付ける。入力RPCはAPKのUIDとシェル自身のみ受け付ける。アプリ終了時に実行部を終了し、接続終了時に自律を停止する。任意シェルコマンドを受け付けるAPIはない。対象はサービスが作成した画面IDだけで、物理画面ID0へ仮想タップを送らない。rootは不要。

実行コンテキストはシェルパッケージの専用Contextを作り、system Contextから継承した誤った呼び出しパッケージを使用しない。app_processの未登録ApplicationThreadを使ったContentResolver経路ではなく、シェル用の外部Provider接続でBinderを渡す。隠しAPIはユーザーが明示起動したシェルプロセス内でだけ使用する。

小窓の最小表示は既存と同じくタイトル＋1ピクセル、内部解像度は幅720ピクセル。見た目の縮小でゲーム描画負荷やメモリが削減されると保証しない。画面取得はAccessibilityのdisplayId指定で行う。未知の画素状態や取得不可では操作を保留する。

既定2ゲームの画素領域、オートマトン、相対座標、デフォルト3ms設定を継続。既存のマーカー・独自オートマトンを消去しない。独自曲線・マーカーの仮想画面での再生は未対応。

ビルドと署名、JVM検査、録画ROI再生を実施。スクリプトの実ADB通信・シェルBinder接続・Pixel 10でのゲーム起動と入力は実機未確認。
