# MarkerTap v1.110 最小幅から上げる解像度実験

## 今回の変更

起動幅を下げていく操作を、最小幅32pxから順に上げる操作へ変更しました。高さは元の画面比率に合わせ、DPIも起動幅と連動します。

v1.110で実験画面を初めて開くと、次回起動の指定幅を32pxに設定します。稼働中の画面をその場で変更したり、既存の実験記録を消したりはしません。2回目以降は選んだ幅を保持します。

## 手順

1. 旧版を「全停止」し、`MarkerTap-v1.110-resolution-lab.apk` を上書きインストールします。従来と同じ証明書・パッケージです。
2. 「設定」→「仮想画面の起動解像度」→「起動解像度の実験」を開きます。
3. まず幅32pxで試します。画面が開いていれば「選択した幅で開き直す」、まだ開いていなければホームから対象アプリを選んで開きます。
4. 「動作結果を記録」で、表示が崩れる・認識できない・タップが合わない・起動できない、のどれかをアプリ別に記録します。
5. 成立しなければ「一段上げる（次回起動）」→「選択した幅で開き直す」を押します。
6. 表示できる幅になったら、ホームの「自動開始」で認識とタップを試します。主画面だけでなく、ミッション・確認画面・CM復帰も確認してください。

実験画面の「開き直す」で作り直した直後は自律停止の状態です。対象の表示を確認した後に自動開始します。上限720pxで「一段上げる」を押しても、自動設定や小さい幅へ戻りません。

昇順は **32→48→64→96→128→160→200→240→280→320→360→400→480→540→640→720px** です。自動（従来設定）は選択肢の末尾にあります。自動を選んだ後の「一段上げる」は、再び最小幅32pxから始まります。

「最小幅32pxからやり直す」で起点へ戻せます。「正常と記録した幅へ戻す」は、全画面を手動で正常と記録した時の幅を選び直します。いずれも次の画面作成から反映されます。

## 相対位置が成立するか

要素数の推定・1〜6領域の比較・解像度との関係は、同梱の `RELATIVE-ELEMENTS-v1.110.md` にまとめています。今回の結果では、目印を増やすだけでは全ての状態を識別できませんでした。実験用の領域の組をゲーム操作へ自動適用する変更は加えていません。

32pxはこの実験版の起点です。動作可能と確認した幅ではありません。0pxでは仮想画面を作れません。実用的に成立する幅は、端末とアプリごとに測定します。

## 記録と検証範囲

直近80起動の幅・高さ・DPI・指定幅・アプリ・手動評価などを保存し、「実験記録を見る・コピー」で取り出せます。入力完了回数は送信完了で、ゲームが反応した成功数ではありません。

画像用メモリの見積もり、Javaヒープ使用量、端末の空きメモリは性質が違う値です。瞬間的な空きメモリの差だけから、解像度変更による削減量を断定しないでください。

ビルド・署名・起動幅の昇順・旧設定からの初期化などをホスト側で検証します。Android実機での最小動作幅、設定画面の実操作、低解像度でのゲーム反応は未確認です。過去版の詳しい記録仕様は `GUIDE-v1.109.md`、今回の結果は `VALIDATION-v1.110.json` を参照してください。
