# MarkerTap v1.70 — コイン落としのオートマトン修正

ユーザー提供の6682.mp4で、「このままはじめる」「閉じる」「ポケット倍率アップ」と広告の「次へ」を従来の判定が取りこぼす条件を再現しました。操作パネルやマーカーに隠れない目印を追加し、確認できたボタンの相対位置へ操作を送るよう修正しました。未完了の赤い通知だけでミッションを開く遷移も削除しています。

録画の画素による判定・座標・状態遷移をホスト上で検証しました。新APKを実機に入れたあとのタップ成功、長時間運転、実際のアプリ間切り替えは未検証です。

## 更新と適用

1. 旧版で「全停止」を押し、仮想画面を閉じます。
2. `MarkerTap-v1.70-window-relative.apk`を上書きインストールします。v1.65〜1.69軽量版と同じパッケージ `jp.tapmarker.lite`・署名です。アンインストールは不要です。
3. 「マーカー連打 軽量版」のユーザー補助を有効にし、コイン落としを選びます。編集していない標準設定は、自動移行で今回の修正が適用されます。
4. 手動編集・学習済み設定を使っている場合は保持します。今回の標準オートマトンを使うには、コイン落としの「標準設定に戻す」を選んでください。以前の設定はバックアップされます。
5. 仮想画面では「端末だけで接続」から実行部を起動し直し、画面を開き直します。実行部も版73に更新しています。
6. コイン落としの「自動開始」で実行します。

画像認識による自律にはAndroid 11以降が必要です。v1.64以前の通常版 `jp.tapmarker` とは別アプリで、自動設定移行はありません。

## 原因と修正内容

従来のコイン設定は、ダイアログ上部の見出しとボタン文字を別々に照合していました。6682録画では上部の見出しが操作パネルに重なり、開始ラベルの中央もマーカーに重なっています。元の判定を録画の原画素に適用すると、開始・報酬・倍率アップが一致せず、連打を保留して画面判別を続ける条件になりました。録画中の状態名は途中で省略されているため、その表示だけから具体的な内部状態を特定していません。

| 場面 | v1.70の処理 |
| --- | --- |
| このままはじめる | カード内の「ステージクリア時のポイントアップ」と、マーカーに隠れない開始ラベルの右側を照合します。CMボタンの下にある開始ラベルの内側をタップします。 |
| コイン獲得の閉じる | 操作パネルに隠れない見出し部分と「閉じる」を照合します。この報酬の閉じるボタンをタップし、ミッション表示を再確認します。 |
| ポケット倍率アップ | パネルの下にあるカード内の説明と、そのダイアログのCMボタン文字を照合します。確認したCMボタンをタップし、強化CMの終了を待ちます。 |
| 広告の丸い次へ | 録画にある、灰白色の円内の黒い三角形・縦線を認識して中央をタップします。再生中、空の円、読み込み中、同じ角に複数の候補がある場合は操作しません。 |
| ミッションの赤い通知 | 通知だけで主画面からミッションを開く矢印を削除します。既存の未編集の標準設定にも移行処理を適用します。 |
| ステージクリア後 | 登録済みのクリア演出を確認した後は、次のステージを開始してミッション回収へ進む処理を残します。通常の未完了ボーナス開始後は、主画面の表示確認へ戻します。 |

ミッション画面がすでに開いている場合の、未回収の「ゲット」を優先して回収し、報酬を閉じ、その後「プレイ」でゲームへ戻る処理も検証しました。今回の録画にないボタンの位置は推測で追加していません。

判定は2回の確認と入力直前の再確認を通します。表示が広告などに変われば、タップと遷移を取り消して再判定します。ボタン位置は対象アプリのウインドウ範囲から画面座標へ変換し、画面サイズが変わった場合は古い座標を使いません。

従来のコイン用13種類の画像見本を変更せず、追加の見本を併用しています。手動で変更した画像・領域・しきい値・操作は、追加の標準判定で置き換えません。

## デイリー終了後に次のアプリへ

1. 各アプリで全デイリーを達成し、報酬も受け取って、その状態が明示される画面を開きます。
2. 操作パネルの「デイリー完了を登録」で、対象の通常画面または仮想画面を選びます。
3. 「2領域を選ぶ」で、全達成・受取済みの文字や印と、デイリーミッションの見出しを別々に囲みます。
4. 各アプリで登録し、「デイリー巡回」の対象を選んで「巡回開始」を押します。番号の表示順で1つずつ実行します。

両方の領域が2回続けて一致すると、現在の連打・自律を止めて次のアプリを開きます。最後のアプリで停止します。全達成の確認中は「プレイ」「ゲット」や時間切れの再試行を保留し、切り替えを優先します。「全停止」は巡回と遅延起動も取り消します。

一部のミッションの達成、残り数の0、ボタンが消えたこと、待ち時間は、全デイリー完了の根拠には使いません。完了条件は端末の実際の画面で登録してください。通常画面と仮想画面は別に保存します。今回の録画には、全デイリー達成・受取済みの画面は含まれていません。

## 継続する端末・他アプリへの対応

- v1.69で追加したF-52Aの増えうさぎ用の主画面見本、Pixelの従来見本、数字欄全体の0判定を維持しています。
- 農園うさぎの通常画面の「閉じる」「このままはじめる」と、名前が公開されている「宝箱を開ける」の処理を維持しています。宝箱のボタンが画像だけで描かれるUIは未調整です。
- ウインドウの移動・サイズ変更・黒帯からの相対位置変換、F-52A用の負荷設定、Android 11／12の仮想画面入力を維持しています。連打の実効間隔は今回変更していません。
- ARM32／ARM64／x86／x86_64を同梱し、タッチスクリーンは必須としていません。Lenovo Chromebookで操作対象アプリのボタン配置や遷移が異なるUIは、実画面の資料がないため未調整です。既存の「学習開始」「学習終了・作成」で、その表示に合う設定を作成できます。

以前の変更の詳しい説明は、同梱の `GUIDE-v1.69.md`、`GUIDE-v1.68.md`、`GUIDE-v1.66.md`を参照してください。

## 再ビルド

ソースZIPを展開し、`TapMarker`で実行します。Java 17、Android API 35／Build Tools 35.0.0、Python 3、rg、C／C++コンパイラが必要です。

```sh
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE="$PWD/signing/lite-development.jks" \
bash build.sh

TAPMARKER_TEST_GROUP=core \
ANDROID_SDK_ROOT=/path/to/android-sdk \
bash run-tests.sh
```

既定出力は `../MarkerTap-v1.70-window-relative.apk`です。署名鍵と4種類のCPU用ネイティブライブラリを同梱しています。6682の見本を再作成する場合は、PythonのPillow・NumPyとffmpegを用意し、`python3 tests/prepare-video6682.py /path/to/6682.mp4`を実行します。可変フレームレートの録画を秒位置で読み込み、元動画は変更しません。
