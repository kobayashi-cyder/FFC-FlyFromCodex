# マーカー連打 v1.57：仮想画面の停止・広告・報酬復帰の修正

v1.56と同じ署名の更新版です。上書きインストールできます。

## 更新後の操作

1. `MarkerTap-v1.57-virtual-recovery.apk`を上書きインストールします。
2. 「展開」→「端末だけで接続」→「接続を開始」で、更新した実行部に接続し直します。
3. 「複数アプリを開いて自律」で増えうさぎ・農園うさぎを選び、「仮想画面（端末内接続・PC不要）」で開きます。
4. 表示確認後に自律が始まります。停止中なら「自動開始」を押してください。
5. 「状況」で各画面の状態と入力完了回数を確認できます。「全停止」で両画面を止めます。

実行部の起動にはWi-FiとAndroidのワイヤレスデバッグが必要です。保存済みのペアリング鍵は維持します。端末側で鍵を無効化している場合だけ再ペアリングが必要です。初期設定はソース内の`WIRELESS-v1.53.md`を参照してください。

## 動画6645.mp4で確認した問題

| 場面 | 動画から確認できる事実 | 修正 |
| --- | --- | --- |
| 増えうさぎの停止 | ゲームが表示されても復帰確認を続け、「ゲーム画面への復帰を3回試しても確認できません」で停止している。 | 小さな画素ずれに耐える主画面照合と、復帰の再試行を修正。 |
| 農園の報酬表示 | 「コインゲット！ +100」と「閉じる」が表示されても、復帰確認のまま入力回数が増えない。 | 仮想画面内の実際のボタン位置と見本へ補正。 |
| 広告の終了印 | 左上または右上に白い×が見えても、その画面に留まる場面がある。 | 広告復帰の状態で、画面の左右の隅だけを確認して終了印をタップ。 |

動画中の状況表示はv1.56です。65秒付近では増えうさぎの入力完了が2回、農園が669回で、入力拒否はいずれも「なし」でした。開始操作と並列入力が全く動かない状態ではなく、増えうさぎの認識・復帰と農園の報酬分岐が主な修正対象です。

## 主画面の画素照合

上部の固定表示と主操作ボタン付近を別々に確認し、両方が一致したときだけ主画面と判定します。

v1.56の細かい画素比較では、動画の増えうさぎの見出しが許容値を超えました。v1.57は小領域内の隣接サンプルを平均して比較し、縮小表示による文字の画素ずれを許容します。一方の一致で他方の不一致を隠す判定にはしません。

農園の第2領域は、動く「収穫する」の文字から、収穫ボタン内の緑色の固定部分に変更しました。ボタンの押下表示でも主画面判定を維持し、広告や暗くなった報酬背景を主画面にしないことを動画の画素で確認しています。

補正は仮想画面の実行時だけ適用し、通常の単画面設定へ保存しません。既定の主画面認識領域を独自変更している場合は、その領域を優先します。

## 農園の「閉じる」

動画の仮想画面では、既定の閉じる領域が実際のボタンより下にありました。仮想画面用の領域を横40.5〜59.5%、縦56.8〜60.3%へ補正しました。入力先は、その個別領域の中央です。

「コインゲット！」の見出しと「閉じる」の文字領域をそれぞれ確認してから操作します。報酬が表示されている間は収穫連打を許可しません。タップ送信後は「画面判別」へ戻り、実際の次画面を確認してから収穫を再開します。

## 広告の終了と再試行

既定の広告復帰・復帰確認・画面判別の状態でだけ、左右上隅にある白い×を検出します。各隅の確認範囲は幅10%、高さ6.5%です。両方を合わせても画面面積の1.3%で、広告本文や全画面の図柄を走査しません。主画面の収穫・増やす中にはこの検出を実行しません。

暗い背景、×の形、周囲の暗さを確認し、2回の画像確認後に検出した印の中央をタップします。確認できない印の位置を推測してタップしません。今回の動画にある、黒い背景上の白い終了印に対応したものです。背景色・形状・位置が異なる広告すべてでの成功は未検証です。

終了印を確認できない場合は、登録ゲームの起動先へ、その仮想画面を指定して復帰を要求します。通常の起動とは別の復帰要求を使い、登録ゲームより上に積まれた画面を戻すフラグを指定します。実際の結果はゲーム側の画面構成に依存するため、要求後にも画素確認を行います。本体画面へゲームを移す経路は使いません。

仮想画面では復帰要求を3回試しただけで永久停止しません。次の要求を8秒保留し、その間も画面を確認します。終了印や既知の報酬・主画面が確認できれば、対応する分岐へ進みます。この回数・待機は各画面で独立し、他の画面の連打を止めません。通常の状態遷移へ8秒の待機を加えた変更ではありません。

明示的な「全停止」は監視・入力・自動復帰を止めます。再開始した状況表示では、古い停止理由を実行中の理由として表示しないようにしました。

## 維持する動作

- 連打間隔の初期値3ms。実際の入力速度は端末とゲームの処理速度に依存します。
- Wi-Fi中の自動接続／手動接続の選択。
- 画面ごとの独立した状態、画像判定、入力処理。
- 小窓の最小表示中も内部解像度と仮想画面を維持。
- 自律中の小窓タップによる全停止を防止。手動操作は「全停止」の後に行います。
- 入力先の画面IDと登録ゲームUIDを指定し、入力失敗を操作完了と扱わないこと。
- ログアウト・アカウント削除などの保護判定。独自曲線・マーカー操作の矢印は複数画面モードでは従来どおり未対応。

画像取得そのものは仮想画面全体のバッファを利用します。画素の判定・特徴量計算を必要な小領域に限定しています。

## 検証範囲

33個のホストテストスイートが通りました。新しい`VirtualRecoveryReplayTest`は104項目です。動画の8つの表示画像を使い、次を確認しました。

- 増えうさぎが「復帰確認」から主画面へ進み、残り506匹で誤ったイベントや購入へ分岐しない。
- 農園の押下中の収穫ボタンでも主画面を認識し、灰色の「CMを見る」をスコップ強化として押さない。
- コイン報酬が主画面・判別・広告・復帰確認の各状態から報酬処理へ進み、個別の閉じるボタン内を入力先にする。
- 広告の左右の終了印を検出し、期限の切れた復帰要求よりも終了印の操作を選ぶ。
- 主画面・報酬画面に終了印を作り出さない。＋印や未対応の白背景を終了印として操作しない。
- 再試行保留後に復帰を再開でき、各画面の回数が独立している。

従来の単画面、オートマトン、入力先指定、停止後の取消、暗号・接続関連のテストも通りました。APKのv2/v3署名、従来版と同じ署名証明書、16KB境界配置を確認しました。

**この環境にAndroid実機は接続していません。修正版を端末へ導入した後の連続動作、実際の720pxの内部描画画像での一致率、全広告・全ミッションの成功率は未確認です。** 動画からの画素検証と端末操作の実証を区別しています。

ソース内の`tests-v1.57.log`と`validation-v1.57.json`に検証結果を含めています。今回の動画表示を再生するテスト画像は`tests/virtual-recovery-replay.bin`、抽出位置は`tests/virtual-recovery-evidence.json`です。

## 再ビルド

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk TAPMARKER_KEYSTORE=/path/to/your-key.jks bash build.sh
ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

Java、Python 3、ripgrep、Android SDK platform 35/build-tools 35.0.0が必要です。暗号テストにはC/C++コンパイラも使います。録画の見本再生成にはPillow、NumPy、ffmpegを使います。署名秘密鍵はソースZIPに含めていません。

復帰フラグの確認資料：[Android Developers：Intent.FLAG_ACTIVITY_CLEAR_TOP](https://developer.android.com/reference/android/content/Intent#FLAG_ACTIVITY_CLEAR_TOP)、[タスクとバックスタック](https://developer.android.com/guide/components/activities/tasks-and-back-stack)。
