# マーカー連打 v1.59：端末内の実演からオートマトンを作成

`MarkerTap-v1.59-on-device-learning.apk` は同じ署名で上書き更新できます。動画を送らず、端末で実演した操作からアプリ別の状態・監視領域・操作位置・遷移を作成する機能を追加しました。

## 最初の操作

1. APKを上書きインストールし、ユーザー補助の「マーカー連打」を有効にします。
2. 学習するアプリを開きます。仮想画面の場合は、対象の小窓を表示しておきます。
3. 操作パネルの「展開」→「学習開始」を押します。
4. プルダウンで通常画面または対象の仮想画面を選び、「学習開始」を押します。
5. 「画面を操作してください」と表示されたら、タップや1本指の曲線を実演します。操作の記録が終わってから次の操作を行ってください。
6. 一周したら「学習終了・作成」を押します。繰り返したい場合は、最初の表示または既に実演した状態へ戻ってから終了してください。
7. 作成結果の「図で編集」で状態と矢印を確認し、「自動開始」で再生します。

仮想画面の実行部も更新されています。上書き後に「実行部が旧版」と表示された場合は、「端末だけで接続」→「接続を開始」で接続し直してください。以前のペアリング情報は維持します。

## 同じ状態と違う状態の判断

状態の比較には画素を使います。学習中に記録した表示を、安定した領域の色と形の特徴で比較します。細かい描画の差を許容するため、ピクセルの完全な一致ではなく、画素特徴と設定されたしきい値で判定します。

| 記録された内容 | 作成・実行の動作 |
| --- | --- |
| 同じ表示、同じ操作 | 同じ表示状態と操作に統合する。 |
| 違う表示 | 別の表示状態を作り、違いを判定できる監視領域を選ぶ。 |
| 同じ表示、同じ操作から複数の結果へ移る | 操作をまとめ、操作後の表示で記録済みの遷移先を確認する。 |
| 同じ表示に異なる操作が記録されている | 同じ状態にまとめる。条件が同時に成立する場合は保留し、「条件の区別が必要」と表示する。 |
| 未記録の表示、見本との不一致 | 入力を保留して監視を続ける。 |
| 位置補正の候補が複数あり確定できない | タップ位置を決めず、表示の確認を続ける。 |

操作の順番だけで表示状態を分けたり、優先順位で曖昧な操作を選んだりしません。表示で区別できない操作は、自動で目的を推測しません。

「状態1」などは表示の同一性で統合した状態です。「操作後の確認」は、入力を再送せずに遷移先を確認するための処理用の状態です。タップの送信が成功しても、それだけで遷移先の表示を確認できた扱いにはしません。

## マーカーを取り込む

1. 学習前に対象アプリで「追加」→位置をタップ→「完了」と操作してマーカーを配置します。
2. 学習中に「マーカー実演」を押します。
3. 登録マーカー群を短時間連打し、その前後の表示を記録します。
4. 作成した矢印には、マーカーの識別子と実演時の相対位置を保存します。

自律中にも記録したマーカー操作を実行できます。マーカーが削除されていた場合は、その操作を保留します。マーカーの位置を変えて学習結果も変更したい場合は、その位置で実演し直してください。

連打間隔の初期値は3msです。実際の入力速度はAndroidと対象アプリの処理に依存します。

## 通常画面・仮想画面・分割画面

監視領域、タップ位置、曲線は対象ウインドウ内の相対座標で保存します。仮想画面では小窓の表示サイズからではなく、内部のゲーム画面の大きさから座標を計算します。通常画面と分割画面では、実際のウインドウ位置を加えて入力します。

記録した目印を現在状態の領域付近で確認し、確定できた場合は内容の余白・位置・拡大率の差も補正します。条件の照合と入力で同じ補正を使います。画面構成が大きく変わって目印を確認できない場合は、操作を保留します。

仮想画面を複数表示している場合は、アプリごとに学習します。学習中は自律処理を停止します。学習後は「表示中の対象を自律」または「自動開始」で、設定済みの各画面を独立して動かせます。

## 比較する領域と待機

学習中は状態と監視領域を選ぶためにウインドウ全体を観察します。学習結果の作成後は、現在状態または操作後の確認で必要な領域だけを比較します。主領域と補助領域を併用した条件は、すべての領域の一致が必要です。

位置を確定できないときの探索も、現在状態の目印付近と有限個の補正候補に限定します。探索の再実行は最大1秒に1回です。認識済みの位置は再利用します。

生成する矢印の「操作後の待機」は0msです。通常画面の撮影要求間隔は既存の350msを維持し、同じ条件を独立した撮影で確認します。仮想画面は各画面のフレームを使います。固定の長い待機で遷移したと判断する方式にはしていません。

## 図で修正する

「オートマトン編集」から状態や矢印をタップして編集できます。

- タップ位置は「相対位置を指定」でX・Yの百分率を編集するか、「条件領域の中央」に切り替えます。
- 監視領域は「領域一覧」から描き直せます。通常・仮想とも、対象の表示の中に描いてください。
- 主領域と補助領域の見本を更新するには、対象の表示を出し、矢印編集の「一致状態を記録」を押します。
- 補助領域を使う条件は「学習した補助領域もすべて一致させる」で調整できます。
- 曲線は学習した経路を保持するか、「曲線描画」の経路に置き換えます。
- 「変化」「記録した表示が消えた」「時間経過」の条件へ変更できます。
- 「矢印全消去」で遷移を消去し、状態と領域から組み直せます。

同じ状態で異なる操作が保留された場合は、画面の違いが出る領域を条件にしてください。見える情報が同一であれば、どちらの操作を選ぶべきかは判定できません。

仮想画面の「戻る」操作には対象画面へ入力できる端末内接続方式が必要です。対応できない方式では、本体画面への戻るを代わりに送らず保留します。

## 保存と停止

学習終了時に対象アプリのオートマトンへ適用し、以前の設定を保存します。「学習前に戻す」で復元できます。再度押すと、復元前の学習結果へ戻せます。既存の増えうさぎ・農園うさぎの設定は、学習結果を適用するまでは引き続き使えます。

「全停止」は学習・自律・連打を停止します。作成前の学習は取り消されます。画面消灯、向き変更、仮想画面の実行部切断でも、途中の入力結果を使って学習設定を作りません。学習中の画像は一時メモリで扱い、終了・取消後に破棄します。処理のために動画や画面を外部へ送信しません。

既存のアカウント操作・異常ダイアログへの保護判定を入力前に維持します。

一回の学習は64操作までです。自動作成が対象とする実演は、タップ、1本指の曲線、登録マーカー群です。実演していない操作や未観測の分岐は生成しません。通常画面の学習にはAndroid11以降、物理的な分割画面の自律にはAndroid14以降が必要です。

## 検証範囲

37組のホストテストを実行し、すべて成功しました。追加した学習と相対座標のテストは55項目です。

同じ表示の統合、違う表示の分離、小さな画面端の違い、同じ操作からの複数分岐、曖昧な操作の保留、操作後の表示確認、マーカー・曲線の保存、通常と仮想の大きさ・余白補正、補正候補が重なる場合の保留、編集後の変化・表示消失条件を確認しています。既存の増えうさぎ・農園うさぎの録画由来の画素再生テストも成功しました。

APKはバージョンコード62、v2/v3署名と16KiBページ向けの配置を検証しています。署名鍵は以前のAPKと同じです。実機での学習操作・タップの受け渡し・継続した並列動作は未確認です。

ソース一式には、`ObservationLearnerTest.java`、`LearnedLayoutTest.java`、`tests-v1.59.log`、既存の画像再生テスト、ビルド手順を含めています。

## ソースからビルドする

Android SDK 35、JDK、同梱のECJと依存ライブラリを使用します。ソースには署名用の秘密鍵を含めていません。

```bash
export ANDROID_SDK_ROOT=/path/to/android-sdk
export TAPMARKER_KEYSTORE=/path/to/tapmarker-update.jks
bash build.sh
bash run-tests.sh
```

`build.sh`は`../MarkerTap-v1.59-on-device-learning.apk`を出力します。署名には対応するキーストアが必要です。ビルド用のエイリアスとパスワード設定は`build.sh`で確認してください。

Androidの仕様参照：[AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)、[GestureDescription](https://developer.android.com/reference/android/accessibilityservice/GestureDescription)。
