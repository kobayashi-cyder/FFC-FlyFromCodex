# MarkerTap 手動実行部再起動 — 2026-10-21

## 反映済み（ソース）
- ホームの「端末内実行部を再起動」と操作パネルの「実行部を再起動」から確認ダイアログを開く。
- 利用者が確定したら、自動操作を停止し、仮想画面を解放し、復旧予約を取り消す。
- 登録済み ADB Binder の SHUTDOWN RPC を UI スレッド外で実行し、終了後に接続参照を破棄。
- Wi-Fi 接続があるときだけ、既存のワイヤレスデバッグ接続経路で新たな実行部を起動する。
- Wi-Fi が切れている場合は停止のみ行い、接続できない原因を表示。
- 対象アプリ選択・設定は維持。画面再生成と自動実行再開は利用者が行う。
- PC 所有中・PC 表示中は再起動を拒否。二重実行の要求も抑止する。

## 制約
- これは **Android 端末そのものの電源再起動ではない**。対象は MarkerTap が接続している端末内 ADB 実行部。
- 既に Binder 管理下から外れた孤立プロセスを OS 上で強制掃除する操作ではない。
- リソースの解放は旧実行部の SHUTDOWN と VirtualShell.closeAll に依存する。
- 実行部終了を確認できない場合は、重複実行を避けるため再接続を中断する。
- 新版 APK は **未ビルド／未署名／未実機検証**。ソース反映と構造確認のみ完了。

## 実機回帰テスト（Pixel 10 / Android 17）
1. 4つのゲームを仮想画面で実行中、ホームから再起動を操作。確認前は実行が続くこと。
2. 確定後、旧ディスプレイが解放され、旧 ADB 実行部が終了することを確認。
3. Wi-Fi ON / ワイヤレスデバッグ ON で実行部を再接続し、選択済みアプリを再表示できること。
4. Wi-Fi OFF で操作した場合、終了のみ完了し、接続待ちをループしないこと。
5. PC 表示中は実行部を停止しないこと。連続操作による二重接続が起きないこと。
6. 過去に接続したアプリ・仮想画面の孤立が残らないか、ADB process / DisplayManager で実機照合すること。
