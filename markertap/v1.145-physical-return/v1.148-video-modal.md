# v1.148 開拓うさぎ動画に基づくダイアログ安全処理

## 動画観測（2026-11-02、96.7秒・1080×2424）

- 0–28秒: 広告画面が前面に存在。アプリへの自動復帰が必要な場面。
- 32–48秒: 開拓うさぎのミッション表示。MarkerTap操作パネルが中央のボタン表示を覆う。
- 44秒付近: 自律ON／「送信完了 26852回」と表示。しかしこの数値は入力送信の累計であり、報酬反映成功の証拠ではない。
- 52秒: 最小化した「MarkerTapに戻す」はドラッグ可能な独立フロート。ゲームは 6620pt。
- 68秒: 「タップ２倍」「1タップで進む量が２倍！」、広告付き「使用する」と「キャンセル」が現れる。
- 88秒: 「クリア！」画面が出る。ゲームは 6720pt まで増加したが、全行程をMarkerTapが自律攻略したことは立証できない。
- 90秒: 「コインアップチャンス!!」「ステージクリア時のコインがアップ」、広告付き報酬と「このままはじめる」が現れる。

## 実装

- v1.147のフロート移動/最小化を維持したまま、既存の `KaitakuUiEvidence.sample → KaitakuNamedControls.apply` 呼出し1箇所だけを新しいダイアログ判定に接続。
- 同一の新鮮なユーザー補助UIツリーが**タイトルと説明文**を示した場合に限り、広告を見ない明示的なアクション（「キャンセル」または「このままはじめる」）の矩形を使う。
- ダイアログは認識できるが安全なボタンの位置を確認できない場合、既存の開拓連打を保留する。報酬広告の「使用する」「CMを見て30ゲット」は自動押下しない。
- ミッション項目「タップ2倍を3回使用する」と実際のダイアログを区別する。従来のミッション・ゲーム動作は旧コードへ委譲。
- ポップアップを閉じた後は従来の確認待ちへ進み、画面の再認識を要求する。画像処理、フロート移動、各ゲームの既存状態を無条件に変更しない。

## 実証と限界

純Javaホスト試験14件、旧回帰試験とDEX接続監査をCIで実行する。**動画だけでユーザー補助ツリーにラベルが公開されるかは判別できない**。Unity/Canvas系画面でラベル取得不能の場合は新しい操作が発動しない。動画に操作イベントIDと報酬反映ログがなく、実機の完全自律・署名済みAPKの稼働成功を主張しない。

署名鍵や画面録画本体はGitHubにアップロードしない。署名済みAPK作成には保護された元鍵と固定SHA-256のv1.144正本が必要。
