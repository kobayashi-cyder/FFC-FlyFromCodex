# MarkerTap v1.85 — 配置方式に「PC」を追加

パッケージ `jp.tapmarker.lite` / versionName `1.85` / versionCode `88`。実行部85とPC連携プロトコル1を維持します。1.84と同じ署名で上書き更新できます。

## 使い方

1. `MultiScreen-PC-v2.4.zip` をすべて展開し、USBデバッグを許可したスマホを接続します。
2. PCの `START-WINDOWS.cmd` を起動し、scrcpy 4.1のフォルダーを選びます。
3. 「TapMakerを更新・設定」で付属APKを上書きし、スマホのユーザー補助が有効なことを確認します。
4. スマホの操作パネルで「複数アプリを開いて自律」→対象アプリを選択→「配置方式へ」→「PC（PCに各画面を表示して自律）」を選びます。
5. スマホで選んだ対象と順序がPCへ渡され、PCに各画面を表示します。PCでアプリを選び直す必要はありません。

PCは接続・アプリ読込を済ませた状態にしてください。接続待ちは2分です。間に合わなかった場合は、配置方式の「PC」を選び直します。
従来どおり、PC側でゲームを選んで「TapMakerで同時操作」から開始する方法も使えます。

## 動作

「PC」はTapMaker自身の仮想画面を使用します。ゲームごとの画像判定とタップは既存TapMakerが処理し、PCは画面を表示します。
配置要求は一度だけ受け付け、PCの定期確認による重複起動を防ぎます。PCの接続待ちに「自動開始」を押しても、端末本体のゲームへ切り替えて起動しません。
「全停止」、別の配置方式、仮想画面の終了でPC待機を取り消します。取り消した後のPC応答から遅れて画面を作りません。
PC側の「すべて停止」「自動処理だけ停止」も、接続待ちを取り消します。通信断で停止が届かなかった場合は、接続復帰時に停止を優先して再試行します。
ゲーム処理開始後の通信断による20秒の停止は1.84から維持します。

## 条件と検証範囲

Android11以降、所有者ユーザー0、ユーザー補助、対象ゲームの有効なオートマトンが必要です。ゲーム別設定や学習データは上書き更新で維持します。
標準対応4ゲームと独自オートマトンの扱いは1.84と同じです。PC2.4でスマホからの配置要求を自動受付します。旧PC版ではPC側の手動開始を使用してください。
APKのビルド・署名一致と、配置の引き継ぎ・重複受付・取消し等のロジックと模擬PC連携を検証しています。Windows GUIと実機のAndroid IPC・ゲーム入力は未検証です。

# MarkerTap v1.84 — 既存TapMakerをPCから複数画面で実行

パッケージ `jp.tapmarker.lite` / versionName `1.84` / versionCode `87`。実行部リビジョン85、PC連携プロトコル1です。
既存の1.83と署名が一致しています。アンインストールせず、`MarkerTap-v1.84-pc.apk` を上書きしてください。

## PCからの使い方

1. `MultiScreen-PC-v2.3.zip` をすべて展開し、USBデバッグを許可したスマホを接続します。
2. `START-WINDOWS.cmd` を起動し、お持ちのscrcpy 4.1のフォルダーを選びます。
3. 「TapMakerを更新・設定」を押し、スマホ側でユーザー補助が有効なことを確認します。
4. 「接続・アプリ読込」でゲームを複数選択し、「TapMakerで同時操作」を押します。

今回報告された「この端末用のPCツールが既に動いています」は重複起動のエラーです。
新PC版の「前のPC処理を終了して再接続」、または `RECOVER-WINDOWS.cmd` を使用できます。
以前のGUI版には終了要求を渡し、後片付けを待って再接続します。旧コンソール版AllDisplaysは、その画面でQを押してください。

## 処理の担当

仮想画面の作成、画像取得、ゲームごとの判定、タップは既存TapMakerが担当します。
PCは返された画面IDを表示し、開始・停止・状態取得だけを行います。scrcpyで作った画面をTapMakerが認識しない問題を避けるため、TapMaker自身の仮想画面を使用します。
各画面で既存のSplitPilot・AppPhases・Tapperと独立した画像・入力処理を使います。PC用の連打エンジンは追加していません。
カスタム設定、ゲーム別のデータ、通常の5点ランダムタップ、F-52Aの入力設定、コイン落としの任意CM除外、1.83の買い物うさぎの判定を引き継ぎます。

## 開始条件と状態表示

- Android 11以降、所有者ユーザー0、ユーザー補助の有効化が必要です。
- 対象ゲームの保存済みオートマトンを開始前に確認します。標準設定はふえうさぎ・農園うさぎ・コイン落とし・買い物うさぎです。
- ぽいぽい等は、端末に有効な独自オートマトンが保存されていれば使用できます。未設定の場合は対象名と理由を表示します。そのゲームを選択から外すか、TapMakerで設定してください。
- スマホ側の別の仮想画面は、PCから無断で置き換えません。スマホのTapMakerで終了してから再試行してください。
- 「準備中」は画像と対象アプリの表示確認待ちです。「TapMaker並行処理」は既存エンジンの実行状態です。
- 各画面の入力完了回数と画像の新しさをPCへ表示します。入力完了はAndroidへの送信完了であり、ゲームの反応は映像で確認します。
- PCの映像ウィンドウは表示専用です。自動操作はTapMakerが行います。

## 停止と切断

「自動処理だけ停止」は映像を残して自動処理を停止します。「すべて停止」はこのPCが開始した仮想画面も終了します。
個別の映像ウィンドウを閉じるだけでは自動処理は停止しません。PCの停止ボタンを使用してください。
PCの操作画面を閉じたときも停止要求を送ります。停止が未確認の場合は実行成功として扱わず、接続復帰後に停止を再試行します。
通信が20秒以上途切れた場合はTapMaker側でも自動処理を停止します。この場合はスマホの仮想画面を残します。
Androidユーザー切替では元のユーザーへ停止を要求します。スマホで別の仮想画面に切り替えた場合は、古いPCの終了要求で新しい処理を停止しません。

## 検証範囲

APKビルド、既存1.83との署名一致、既存のゲーム別判定・入力取消し等の回帰テスト、PCの模擬ADB/scrcpy結合検証を行いました。
Windows GUI、スマホ実機、実際の5ゲームへの同時入力はこの環境では未検証です。模擬検証をゲームの実機動作確認とは扱いません。

# MarkerTap v1.83 — 録画6717の買い物うさぎ・再開・広告矢印への対応

パッケージ `jp.tapmarker.lite` / versionName `1.83` / versionCode `86`。
`MarkerTap-v1.83-shopping-6717.apk` を上書きインストールしてください。同じ署名なのでアプリの削除は不要です。

## 録画で確認したこと

提供された `6717.mp4` は約185秒、1080×2424の録画です。通常画面では連打カウンターだけでなくゲーム内の表示も変わっています。一方、1分56秒～1分58秒付近では「このままはじめる」の画面を、パネルが広告終了待ちとして扱っています。

録画には全停止後の手動操作も含まれます。広告先のページやストアが出る場面だけを根拠に、自動処理が誤タップしたとは断定していません。パネルは「実効1ms以上」というv1.82より前の表記で、端末型番とインストール済みAPKの版は映像から確定できません。

v1.82の実行コードに録画画像を読ませると、通常画面、「このままはじめる」、右上の白い矢印などの認識漏れが再現しました。今回はその画像認識と、確認できたボタンの操作位置を修正しています。

## 修正した操作

| 場面 | v1.83の確認方法・動作 |
| --- | --- |
| 倉庫の通常画面 | 「お店に戻る」と、下部の「運ぶ量」を確認。中央の文字がマーカーに隠れても通常画面を確認できるようにしました。 |
| このままはじめる | 説明文と右側の再開文字を確認して、その文字を1回押します。大きい表示と小さい表示に対応。操作後は通常画面を再確認します。 |
| コイン獲得の閉じる | パネルの下に見えるコイン図柄と「閉じる」を照合します。隠れた見出しだけに依存しません。 |
| ミッションのゲット | ミッション見出しと、パネル右側に残るゲット文字を確認。ボタン列を上から探し、確認できたボタンの右側を押します。 |
| ミッションのプレイ | 見出しと黄色いプレイ文字を確認し、そのボタンを押します。ゲットの回収を優先する既存の方針を維持します。 |
| 買い物のタップ2倍 | 確認画面の説明文と「はい」を照合します。広告の利用方針は従来の設定を継続します。 |
| 広告右上の白い「→」 | 録画で確認した矢印の形と、上部の黒い帯を確認して終了候補にします。既存の×・Closeなどが同時に見える場合も候補を残します。 |

文字や説明文が欠けた場合、画面が暗くなった場合、対象の表示が消えた場合は、その根拠の操作を送りません。入力直前の再確認と、画面サイズ・ウインドウ位置の確認も行います。

矢印は、黒い広告上部に現れた白い右矢印が対象です。全種類の矢印や広告に対応する一般OCRではありません。終了候補の試行回数と、別の終了候補・戻る・登録アプリ復帰への切替は、既存の処理を使います。

## 設定の引き継ぎ

買い物うさぎの標準設定には、CMを見ずに再開する分岐を追加します。旧標準設定を更新する前に退避します。独自に編集したグラフは自動で書き換えません。見本・座標・厳しい判定条件を変更した操作についても、その編集を工場設定の追加根拠で置き換えません。

次のv1.82の設定・機能は引き継ぎます。

- 通常連打の位置は、中央・上下左右の有限5点から毎回ランダムに選択。押下中は固定し、離してから次の点を選びます。
- F-52Aの自動設定は、60Hz時に押下17ms以上＋解放17ms以上。従来の最短1ms要求も選べます。
- コイン落としの任意CM視聴除外、ポット増加のキャンセル、左右のCloseと別候補への切替。
- タッパーと判定処理の分離、通常プレイ中の継続連打、別イベントでの保留、入力通知の期限と遅延通知対策。
- 「タップが届くか10回確認」で、端末で受信した押下と解放の回数を確認する画面。

## 更新後

1. APKを上書きインストールします。
2. 「タップの押し方」は「自動」、「連打の場所」は「5点からランダム」で使用できます。
3. 買い物うさぎを開き「自動開始」を押します。独自編集した設定を使っている場合は、その内容が優先されます。

ユーザー補助が停止した場合はAndroid設定で「マーカー連打 軽量版」をOFF→ONにしてください。仮想画面は開き直してください。実行部リビジョンはv1.82と同じ85です。「旧実行部」と表示される場合は、端末内接続またはShizukuで接続し直してください。
