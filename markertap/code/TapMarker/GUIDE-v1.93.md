# MarkerTap v1.93 — マーカーなしのプリセット自律・位置再認識・農園フィーバー

パッケージ `jp.tapmarker.lite`、versionName `1.93`、versionCode `96`。v1.92と同じ更新用署名です。

## 更新と開始

1. 旧版の「全停止」を押します。
2. `MarkerTap-v1.93-markerless.apk`を上書きインストールします。
3. ユーザー補助が有効なことを確認し、対象ゲームを開いて「自動開始」を押します。

プリセットへのマーカー配置・位置調整は不要です。仮想画面・PC表示を利用している場合は、更新後に接続と表示を開始し直してください。学習・編集したオートマトンや手動マーカーの記録は保持します。

## 変更した動作

| 場面 | v1.93の動作 |
| --- | --- |
| プリセットを使う | マーカーを自動生成しません。保存済みの手動マーカーもプリセットでは表示しません。 |
| マーカーがない・大きくずれている | プリセットの通常連打は画面内のボタンやプレイ対象を認識して動きます。保存済みマーカーの位置は使いません。 |
| 見出しとボタンの位置関係が変わる | 対象アプリのウインドウ内を探索し、それぞれの表示を個別に確認します。操作前にも現在の表示を確認します。 |
| 連打対象が動く・消える | 古い座標への入力を保留して再探索し、現在の画像で再認識できれば再開します。 |
| ウインドウ配置・画面の向きが変わる | 古い画像と未完了の指示を無効にし、実行状態を維持して新しい配置を確認します。 |
| 農園うさぎがフィーバーになる | 「フィーバータイム」と白い「収穫する」の文字を確認し、虹色への変化を通常連打の停止理由にしません。 |
| 宝箱・報酬・CM・確認画面 | 通常連打を保留し、既存の画面別処理を優先します。 |
| 録画・実演から作った操作 | 記録した対象と補助条件を個別に再認識できます。保存済みの連打位置はマーカー表示なしで再生します。 |

通常のプリセット対象は、増えうさぎ・農園うさぎ・コイン落とし・買い物うさぎ・ボックスマージ・ポイポイうさぎです。「連打のみ」「追加」「削除」などを明示的に選んだ場合は、手動用マーカーを使用できます。

コイン落としの任意CMを開始しない方針、ポイポイうさぎの「タップ2倍」は「使用しない」、通常連打と強化処理の分離、F-52A向けの離散した押下・解放を維持します。

## 対応範囲

画面内に見えている既知の文字・図柄を手掛かりにします。見た目自体が別物になった未学習のUIは、新しい録画・学習が必要です。探索で同程度の候補が競合した場合や、操作対象が見えない場合は観察を続けます。

録画から作った設定で、操作位置が記録された判定領域の外にあり、対象そのものの見本がない場合は、別の見出しだけを根拠に移動先を推測しません。新たに対象を記録することで対応できます。

## 検証

配布APKへ変換する縮小済みJavaクラスに対して、`bash run-tests.sh`のcore回帰検証を実行します。結果は同梱の`tests-v1.93.log`と`VALIDATION-v1.93.json`に記録します。

新しい検証には、6ゲームのマーカー情報なしでの対象認識、見出しと操作対象の独立移動、ミッションボタンの移動と消失、録画の操作先補正、別時刻の通常画面・割込み画面を含みます。農園フィーバーは録画6612の20秒と、F-52Aとして提供された録画6680の168秒を使い、連打許可の継続と宝箱・報酬・CMでの保留を確認します。6612のフィーバー表示は見本と検証で共用しており、6680は別録画です。

Android実機は接続していません。録画での画面判定とホスト検証の結果であり、新APKを入れた実機での入力受付・速度・ゲームの反応は未確認です。

## 再ビルド

Java、Android SDK platform35 / build-tools35.0.0、同梱のECJを使用します。`ANDROID_SDK_ROOT`と`TAPMARKER_KEYSTORE`を設定し、`bash build.sh`でビルドします。署名鍵は配布ソースに含めません。仮想実行部の通信リビジョン89と4種類のCPU向けライブラリを維持します。
