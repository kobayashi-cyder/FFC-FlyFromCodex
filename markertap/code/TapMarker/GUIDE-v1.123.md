# MarkerTap v1.123 — 描画コネクトーム / 静止・動画ノード分離

## 仕組み
プレビューを32×32ピクセルのノード（タイル）に区分し、上下左右の隣接関係をもつ疎なイベント駆動グラフ（PreviewConnectome）でサンプリング時刻を割り当てます。

- **動的ノード**：実際にピクセルが変化したノードは連続して再検査し、上下左右にも再検査信号を伝えます。
- **静止ノード**：連続して変化が見られない領域ではプレビュー画素読み取り間隔を600〜1200msへ段階的に延長。以前のBitmapとViewをそのまま維持します。
- **シーン切替**：解像度・認識領域構成（ROI）・セッションが変わればグラフとプレビューキャッシュを初期化し、全領域を再取得します。
- **描画メモリ**：変更されたタイルでも既存の可変BitmapへsetPixelsして再利用します。未変更タイルはViewをinvalidateしません。
- **安全な影響範囲**：動画CM・ゲーム画面をAndroid OSが描画する処理自体を変更するものではなく、MarkerTapが表示する端末内プレビューの画素取得・描画のみを効率化します。自動認識・タップ・広告終了検出は従来のフレームに基づき、サンプリング省略の対象外です。
- **停止・復帰**：v1.121の全停止、v1.122のロック画面保護を保持します。

## 検証
PreviewConnectomeTestで、全領域初回取得・静止ノードの間引き・一定時間内の再取得・動的ノードの上下左右への信号伝播・領域/解像度変更時の初期化・不正スケジュール拒否を確認します。GitHub ActionsでAndroid 35のソースビルドと既存core試験を実行します。

実際のCPU使用率・GPU負荷・メモリ削減率・4画面長時間稼働・Pixel 10でのCM描画追従は未計測です。Android本来のゲーム描画と音声デコード負荷の削減を保証しません。

実装済み。ビルドと実機検証の結果を確認してください。
