# MarkerTap v1.100：仮想2画面の広告エラー・ストア復帰

`jp.tapmarker.lite` / versionName `1.100` / versionCode `103`

v1.99と同じ署名で更新できます。仮想画面2つと、100%・75%・50%・35%・最小表示を引き続き利用できます。

## 更新手順

1. 旧版の「全停止」を押し、開いている仮想画面を閉じます。
2. `MarkerTap-v1.100-recovery.apk`を上書きインストールします。
3. ユーザー補助を確認し、使用していた接続方法で仮想画面を開き直します。
4. 対象を2アプリまで選び、「自動開始」を押します。

## 今回修正した停止要因

| 場面 | 旧版で再現した問題 | 修正 |
| --- | --- | --- |
| 農園うさぎの「広告を表示できませんでした」 | 添付6746のOKが検出されず、背後の主画面の目印が一致していた | オレンジ見出し・白い本文・縁取り付きOKを別々に測定。エラー表示を主画面より優先し、連打・強化入力を保留する |
| Google Playの途中から出る白いシート | ×が画面上端14%の探索範囲から外れていた | Google Playの見出しと実際の×を同時に確認。取得した×の位置を使い、入力直前にも再判定する |
| 仮想画面内に対象外アプリが出る | 入力拒否やCMのタイムアウトまで復帰処理に入らない場合があった | 別パッケージの表示を検出した時点で、その画面の登録ゲームへの復帰を開始する |
| エラー処理中の見出し | 「主画面確認済み」の古い表示が残る | 広告エラーのOK確認中であることを画面別に表示する |

農園のOKは新しい2枚の画像で確認し、最大3回まで間隔を空けて試行します。消失も2枚で確認してから主画面を再判定します。片方の処理で他方の待機状態や試行回数を変更しません。

ストアシートの処理は白いシートの見出しと×の両方を必要とします。閉じた後もゲームの表示を確認するまでCM状態を維持し、ミッション回収途中ならその経路を保持します。対象外パッケージが表示されている場合は、従来の入力先UID制限を保ったまま登録ゲームへ起動要求を送ります。

## 検証と限界

- 録画6745と添付6746から、タイトルバーを除いたプレビュー画像48枚を切り出しました。
- `Video6745ReplayTest`は180項目に合格。実際のエラーOK、複数のストアシート、通常プレイ・報酬・広告の負例、画像の寸法違い、表示変更直前の入力取消、通常とミッション経路の保持を検査します。
- Google Play見出しの認識見本には録画の最初のカードを使い、別カードと添付画像で検証しています。
- 新しい拡縮・遮蔽・入力完了の順序は模擬条件です。録画から切り出した小窓の画像は、端末内部の未縮小フレームバッファそのものではありません。
- 既存の回帰検査、ビルド、署名・16KB境界配置の確認結果は `VALIDATION-v1.100.json` とログを参照してください。
- この環境にAndroid実機は接続されていません。端末での連続稼働、個々の広告の待ち時間、すべての広告からの復帰成功率は未検証です。

## 再ビルド

Java 17、Android SDK platform35/build-tools35.0.0、Python3、ripgrepを使用します。暗号検査にはC/C++コンパイラが必要です。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE=/path/to/original-key.jks \
bash build.sh

ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

秘密の署名鍵はソース・修正キットに含めません。配布APKの証明書SHA-256は `7f42d636e4d3c251f475eb998fbe8e92b515ded8bce3ff4d30aa90b9a738cfb1` です。

修正キットはv1.99完全ソースの上に展開します。単独でビルドする場合は完全ソースを使用してください。画像検査の再生成手順は `tests/prepare-video6745.py` を参照してください。
