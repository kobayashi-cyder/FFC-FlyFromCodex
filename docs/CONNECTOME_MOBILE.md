# コネクトームを計画選択へ広げる軽量 APK v7.5

## 継承元と対象

`banc888-apk-connectome-topology-v3` / `3e9e8cdc3a632489b768c2b9a974cbfc0e84d574`（PR #7）を基盤に、`banc888-apk-connectome-mobile-v1` で改修する。既存の会話、画像、音声、専門ツール、獲得スキルの実装を継承する。PR はこの基盤ブランチへ提出し、既存の変更と分けてレビューする。

内蔵データは既存実装が BANC Figure 3g 由来と記録する 6 個の display_name 集約ノード・16 接続。出典と集約粒度を維持し、接続・符号仮説・正規化・6 tick のモデルを変更しない。全脳や生理学的忠実性、AI 全般への優越はこの変更では実証していない。

## 回路の寄与

従来は獲得スキルが見つかると専門分類の提案より先に採用していた。適用可能な獲得スキルと専門処理の **異なる動作系列** は、権限検査後に同じ回路へ入力し、回路出力で計画を選ぶ。同じ動作系列なら獲得スキルを再利用する。基本候補の回路選択と各実行ステップの回路ゲートも継承する。意味分類・ツール対応は工学的な入力アダプタであり、生物学的意味理解とは呼ばない。

`connectome_multiplex.test.cjs` は実際の APK 代理人スクリプトを実行し、候補の入力スコアだけでは得られない選択、特定出力への接続切断による選択変更、全切断による実行停止を確認する。結果の `plan.connectomeCandidates` と `steps[].connectome` で判断を追跡できる。

## 速度と作業メモリ

接続を数値インデックスと Float64 配列へ一度だけコンパイルし、疎な辺リストを走査する。元の JavaScript Number と同じ精度・加算順序を守る。候補ごと・tick ごとの Map、全候補の活動ログ、順位ソート、辺メタデータの複製を除いた。作業配列を再利用し、連続する同じ刺激は共有し、採用候補だけにログと報酬帰属を作る。出力上流の探索は逆向きの疎な隣接表を使う。

以下は Node v24.19.0 / Linux x64、30 回のウォームアップ後に 100 回測定したホスト上の値。Android 実機値・電力値・AI との課題比較ではない。生の結果とコードハッシュは `performance/connectome-mobile-host.json` にある。

| 回路 | 候補 | 旧 p50 (ms) | 新 p50 (ms) | 速度比 |
|---|---:|---:|---:|---:|
| embedded BANC | 1 | 0.0243 | 0.0051 | 4.7× |
| embedded BANC | 8 | 0.1367 | 0.0120 | 11.4× |
| synthetic 128 | 1 | 0.3507 | 0.0844 | 4.2× |
| synthetic 128 | 8 | 2.6942 | 0.1607 | 16.8× |
| synthetic 512 | 1 | 1.7661 | 0.6646 | 2.7× |
| synthetic 512 | 8 | 15.1245 | 0.6495 | 23.3× |

8 候補のログ生成は 48 枚から 6 枚へ減る。数値作業領域は単一回路で `25 × ノード数 + 36 × 接続数 + 4` バイト。内蔵回路では 730 バイト。この値は文字列、インデックス Map、保存状態、活動ログ、報酬 Map、APK/WebView 全体のメモリを含まない。JSON のヒープ値も選択後のサンプルで、GC 待ちのオブジェクトを含むため厳密なピークや端末メモリの削減率には使わない。

## 多重化と学習の帰属

`ConnectomeMultiplexer` はグラフと作業配列を共有し、スレッドごとの可塑性倍率と未消費の報酬帰属を分離する。CPU の同時並列処理ではなく時間的な多重化。APK の `threadCode` を系統 ID として使う。初期上限は 8 系統（API では 1〜64 に設定可能）。内蔵回路を 8 系統で使う数値領域は 1,626 バイトで、独立カーネル 8 個の 5,840 バイトに対して約 72% 少ない。

上限を超えたら、未消費の報酬を持たない系統を LRU で再利用する。その系統固有の倍率は失われる。全系統が報酬待ちの場合は追加選択を拒否し、別系統の報酬を取り違えない。`selectMany()` は最大 64 件の有限バッチ、`discard()` は学習せず帰属を解放する。評価用報酬は倍率を更新せず、帰属も消費して後の学習への漏れを防ぐ。

チェックポイント schema 2 では接続の identity を一度だけ保存し、系統ごとの倍率を保存する。schema 1 の旧状態は各系統の初期倍率へ移行できる。別回路・別出典の状態は復元しない。完了・取消の目標履歴は通常 80 件までに整理し、未完了の目標を削除しない。

## 検証と APK

```sh
node tests/connectome_selector.test.cjs
node tests/connectome_mobile.test.cjs
node tests/connectome_multiplex.test.cjs
node --expose-gc tools/connectome_mobile_benchmark.cjs
# JDK 17、Gradle 8.9、Android platform 35 / build-tools 35.0.0
 gradle --no-daemon --max-workers=2 :app:assembleDebug :app:assembleDebugAndroidTest
```

180 ケースで旧計算部との選択・符号付き活動・全 tick のログ・学習結果を完全一致で比較した。全 18 JavaScript 検査ファイルと構文・manifest ハッシュ検査を通した。Chromium で Android シェルと同じ順序にスクリプトを読み込み、回路経由の 2+3=5、保存・再読込、ページエラーなしを確認した。

アプリ APK と Android 検査 APK のローカルビルドを確認した。Maven Central が HTTP 429 を返したため、ローカルだけ Gradle init script で公式 Google Maven Central ミラーを使い、TLS とダウンロード検証を維持した。CI は元の依存関係設定を使う。Android では `ConnectomeMobileIntegrationTest` を追加し、配列再利用・系統分離・回路を通した実行を検査する。端末上の遅延・全プロセスメモリ・電力は未測定。既存の音声等を含む Android 検査の実行結果は PR の CI で確認する。

## 課題ごとの範囲

コード・文書・画像の品質条件を満たす最良候補の間で、工学的な出力アダプタを通して回路が選択する。全接続切断では出力を受理しない。入れ子の評価は実行ステップの報酬帰属を保存する。

内容読解は最大 12,000 文字の提供本文から関連文を抽出し、原文の根拠と回路ログを返す。自由な推論ではない。コード生成は既存の用途別実装と構成案、文書は提供記録を保持する構成案。資料なしの議事録は未完成と明記する。画像は手続き的なシーン、動画は新しいシーンとタイムラインであり MP4 の生成ではない。会話を含むこれらの機能は GPT-5.6 Sol 相当の能力を実証していない。

実際のブラウザーで本文要約、会話、CSV コード、文書、画像、動画タイムラインの 6 系統を実行し、回路ログとコード・文書・画像の検証結果を確認する。
