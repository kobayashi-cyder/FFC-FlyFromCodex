# MarkerTap v1.104：キャンセル確認中の広告割込み

`jp.tapmarker.lite` / versionName `1.104` / versionCode `107`

## 更新

旧版で「全停止」を押し、仮想画面を閉じてから `MarkerTap-v1.104-ad-confirmation.apk` を上書きインストールしてください。対象アプリを開き直し、「自動開始」を押します。従来と同じ署名証明書を使用します。

## 再現した問題

報告された「キャンセル後の確認」は、増えうさぎの「キャンセル後の画面を確認」に対応します。今回の現象そのものの録画・例外文は提供されていないため、実機で起きた原因を一つに断定したものではありません。

v1.103のコードでは、この状態で広告の閉じる印が検出されると、「キャンセルが消えた → 画面の再判別」と「広告の閉じる → 広告復帰」の両方が成立し、状態機械が次の診断を出す経路を再現しました。

> 複数の分岐条件が成立 / 領域と見本画像を確認してください

広告の閉じる印を、キャンセルダイアログが引き続き表示されている根拠として扱う経路もあり、割込み検出を妨げていました。

## 修正

- 現在の画像から、押下位置と試行回数を確認できた広告終了操作を扱う間は、隠された画面の「消失」を完了の根拠にしません。
- 広告の閉じる印は、元のゲーム画面が継続している根拠に数えません。
- 通常のゲーム画面やキャンセル表示が実際に一致している場合は、その確認を保持します。座標のない終了フラグから入力を作りません。
- 閉じる操作の送信完了後も広告・復帰画面を確認します。ミッション回収中ならその経路を維持し、通常連打に直ちに戻りません。

単画面と複数画面で使用する既定の広告処理に適用します。独自編集の状態機械と、学習したウインドウ相対の状態機械の分岐規則は変更しません。

## 診断文を残す

「入力と自動実行の状況」の「直近の自律診断」に、検出した分岐競合や失敗の日時・対象アプリ・状態・理由を残します。「コピー」で取得できます。全停止や通常動作の再開では消しません。新しい失敗があれば、その内容へ更新します。

保存するのは長さを制限した文章です。この処理で画面画像や動画を保存・送信することはありません。Androidの設定でこのアプリのデータを消去すると診断文も消えます。

## 検証の範囲

- `CancelAdInterruptionTest`：67項目。既存の録画6750の広告画像、模擬したキャンセルと広告終了の競合、押下前の再確認、古い完了通知の拒否、通常キャンセル、各ゲームの画面消失待ち、未回収ミッションの保持を検査します。
- v1.103の実行クラスで同じ検査を行うと、分岐競合を再現して失敗します。記録は `tests/cancel-ad-v1.103-baseline.log` に含めます。
- `AutomationIncidentTest`：9項目。文章の上限、同じ失敗の重複抑制、手動停止・通常再開後の保持、新しい失敗への更新を検査します。
- 最終の署名済みAPKと一致する実行クラスでの回帰結果を `tests-v1.104.log` と `VALIDATION-v1.104.json` に記録します。

Android実機は未接続です。今回の未録画の現象自体、端末への入力配送、実機の設定保存、長時間運転は確認できていません。

## 再ビルド

Java 17、Android SDK platform 35 / build-tools 35.0.0、Python3、ripgrep、C/C++コンパイラ、元の署名鍵を使用します。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE=/path/to/original-key.jks \
bash build.sh

ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```
