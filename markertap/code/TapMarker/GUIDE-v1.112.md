# MarkerTap v1.112

`jp.tapmarker.lite` / versionName `1.112` / versionCode `115`

## 更新方法

1. 旧版で「全停止」。
2. `MarkerTap-v1.112-stall-recovery.apk` を上書きインストール。
3. 「端末だけで接続」で実行部へ再接続。
4. 起動幅320pxを確認し、対象ゲームで「自動開始」。

既存と同じ署名で更新する。設定を消す再インストールは不要。

## 今回の修正

同じ復帰確認状態への再入場に関係なく、通常復帰の回数と未判別の経過時間を追跡する。3回の通常復帰後も表示を判別できない場合、新しい画像を条件に対象ゲームのタスク再起動へ進む。再起動は30秒間隔、同じ停止区間で最大2回。上限後も画面の監視と閉じる操作を続け、ゲーム画面が新しい画像で確認できれば自律操作へ戻る。

対象は既存の増えうさぎ、農園、コイン落とし、お店屋さん、ボックスマージ、ポイポイ。キャンセルや閉じる印が確認できる場合はそちらを優先する。ミッション回収中のコインは、再起動後もミッションの確認へ進む。再起動により実行中のゲーム演出は最初からになる可能性がある。アプリの保存データを削除する操作は行わない。

コインの画像探索は現在・保存位置の照合を全候補で継続し、見つからない画面候補の詳細探索を2候補ずつ交代で実行する。320pxの画像を使い続ける。

## 診断の読み方

- `主画面の認識` は画像と状態条件を合わせた通常連打の許可判定。
- `画像照合（状態条件を除く）` は画像自体の一致距離と閾値。状態の不一致と画像の不一致を区別する。
- `復帰処理` は同じ停止区間の通常復帰回数、再起動回数、未判別時間。
- `入力完了` は送信実績。報酬加算・ゲーム完了の確認ではない。

## 検証範囲

状態機械、録画由来画像、合成320px画像、合成時刻、模擬入力で回復の制御と既存操作を検証する。Pixel 10 / Android 17の実機を接続した検証ではない。実機でのCM終了、実際の入力到達、報酬取得、4画面の長時間稼働は未確認。

詳細結果は同梱の `tests-v1.112.log` と `VALIDATION-v1.112.json` を参照。

## 再ビルド

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE=/path/to/lite-development.jks \
bash build.sh
bash verify-v1.112.sh
```

Java 17、Android API35、Build Tools35.0.0、Python3、ripgrepが必要。署名秘密鍵はソースZIPに含めない。
