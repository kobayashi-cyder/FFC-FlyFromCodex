# MarkerTap v1.106：増えうさぎの回収修正・見出しをパネル内へ収納

`jp.tapmarker.lite` / versionName `1.106` / versionCode `109`

## 更新方法

1. 旧版で「全停止」を押し、仮想画面を閉じます。
2. `MarkerTap-v1.106-usagi-panel.apk` を上書きインストールします。
3. 仮想画面を作り直し、「自動開始」を押します。

以前と同じ署名証明書を使用します。通常の上書き更新で設定を引き継ぎます。

## 見出しのみの表示

- 操作パネルの「仮想画面 ▾」を押すと、各アプリの見出しと状態がパネル内に開きます。もう一度押すと折り畳みます。
- 見出し、または横の「拡大」を押すと、そのアプリの仮想画面の映像を表示します。既存の仮想画面をそのまま表示するため、アプリの起動し直しや本体画面への切替は行いません。
- 「収納」を押すと、映像を隠してパネル内の見出しへ戻します。映像の上部にある収納ボタンも同じ動作です。
- 「画面」→「見出しのみ（パネル内）」で、すべての映像をまとめて収納できます。初回は見出しのみを既定とし、その後は全画面の表示方式の選択を保存します。
- 見出し一覧はパネル幅に収め、長いアプリ名は最大2行、状態は1行にします。一覧の高さを端末の高さに合わせて制限し、収まらない項目は一覧内でスクロールします。「詳細」を開くと見出し一覧は折り畳みます。
- 見出しを長押しすると、その画面の状況を確認できます。仮想画面そのものの終了は「詳細」内の終了操作を使用します。

収納はスマホ上のプレビュー表示とその縮小画像だけを隠します。仮想画面の描画先、元画像の取得・解析、自律処理、入力先の画面IDを維持します。したがって、CM待機中にも表示を収納できます。実機でのCM再生継続やOSによるプロセス終了の回避を保証するものではありません。

端末内の仮想画面の選択上限は従来どおり2アプリです。画面ごとの処理は既に非同期ですが、ゲーム本体や画面バッファのメモリは残ります。今回の変更だけで3アプリ以上へ上限を拡張してはいません。

## 原因

録画6759では、増えうさぎがデイリーミッションの達成済みステージ報酬（1/1、ゲット）を表示している一方、操作パネルは「復帰画面を確認」のままでした。

v1.105の実行クラスへ録画の10場面を与えると、すべてでミッション画面の判定が成立せず、復帰確認からミッションへ進む分岐が出ないことを再現しました。縮小ミッションの追加判定が見出しと「プレイ」の組合せだけを前提としており、「ゲット」へ切り替わった画面を扱えていませんでした。記録は `tests/video6759-v1.105-baseline.log` にあります。

録画から、端末内でのタップ配送や実行APKの版を直接確定したわけではありません。今回特定・修正したのは、最新版ソースに存在するこの停止経路です。

## 修正内容

- ミッション画面の確認と、ゲット・プレイそれぞれの操作対象の確認を分離しました。ゲットを優先し、確認できた現在のボタンへ入力します。
- 表示中のタスク行を有限の候補として調べ、ラベルの位置の小さな違いにも対応します。「開く」をプレイへ代用しません。すべての未提示レイアウトに対応したという意味ではありません。
- ゲット送信後は報酬表示を待ち、閉じる、プレイ、主画面の再確認へ進みます。入力完了通知だけで回収完了とは判定しません。
- ゲット・プレイを確認できない一覧では、見出しと実際の戻る矢印を確認して一覧から戻れます。その場合も通常操作の再開には主画面の再確認が必要です。
- 報酬などの登録済みポップアップが見える場合は、その処理を優先します。ミッション一覧の裏側へ入力しません。
- 操作直前にも見出しと対象を再確認し、隠れたり変化したボタンの古い入力位置を使いません。
- 単画面と仮想複数画面の両方で、一覧を離れた後のミッション経路を解放する処理を共通化しました。
- 増える量の通貨・CM強化はv1.105の独立処理を引き継ぎます。今回追加した状態表示も日本語・英語へ対応します。

## 検証と限界

`Video6759ReplayTest` は646項目。6759の2～18秒の9場面、縮小・拡大、ウインドウの移動、ラベルの隠蔽、行の移動、ゲットとプレイの区別、ポップアップの優先、入力完了後の待機を確認します。0秒はゲットと戻る矢印の見本作成に使ったため、検証用の場面には数えません。9場面はいずれも同じ一覧の静止場面であり、独立した9種類の画面ではありません。

6759のゲット、過去録画6677の報酬・主画面、6753のプレイを組み合わせ、回収から通常操作へ戻る経路を3周検査しました。1周には回収中のCM状態への割込みを挿入しています。この時系列・入力完了・画面変化は模擬で、実機での成功記録ではありません。拡大縮小・位置変更・隠蔽・行移動・ポップアップの合成も模擬です。

従来の `UsagiControlReplayTest` 349項目により、6753のプレイと、6677の増える量の通貨・CM強化を継続確認します。通常回帰の結果は `tests-v1.106.log`、署名・配布内容等の結果は `VALIDATION-v1.106.json` を参照してください。

追加UIはAndroid API35に対するビルドと表示処理の経路を確認します。見出しの展開・収納では仮想画面の作成・解放・起動や自律停止を呼ばず、元画像の取得経路を維持するよう実装しています。既存の `VirtualPreviewTest` / `VirtualPreviewReplayTest` で相対入力位置と見出しのみ表示時の内部画像の独立性も継続確認します。

**Android実機は接続していません。追加UIの端末での描画・タッチ操作、新APKでの端末入力、実際の報酬加算・強化量、長時間運転、未提示の広告とレイアウトは未確認です。**

## 再ビルド

Java 17、Android SDK platform 35 / build-tools 35.0.0、Python3、ripgrep、C/C++コンパイラ、元の署名鍵を使用します。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE=/path/to/original-key.jks \
bash build.sh

ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

元の署名鍵はソースZIPに含めません。
