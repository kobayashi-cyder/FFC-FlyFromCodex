# MarkerTap v1.153: embedded ADB bridge / no standalone Shizuku requirement

## Summary
Select an Android 11+ on-device ADB model rather than bundling or copying the Shizuku privileged service. Source runtime code removes the Shizuku API calls and ShizukuManifest provider. The original local wireless ADB pairing protocol, localhost-only ADB transport, AndroidKeystore-encrypted client credentials, and shell-UID Binder registration remain in place.

## User setup
1. Open MarkerTap → 仮想画面 → 端末だけで仮想画面. The first time, enable developer options, wireless debugging, and open the pairing-code dialog.
2. The application guides and performs the on-device ADB pairing, using only local device addresses. It does not change system permissions, developer settings, or pair with another device without authorization.
3. Choose 自動接続の設定 → Wi-Fi接続中は自動接続・維持 (opt-in). If the client key was previously paired, the app may reconnect when the service is available, with the existing bounded exponential backoff.
4. After a reboot, wireless debugging may need to be enabled again. Android does not permit an ordinary third-party app to grant shell privileges to itself.

## Security and compatibility
- The ADB process runs with shell UID (2000); it is NOT a system/root process. Binder provider accepts only shell/root callers.
- A stored paired state is only a hint, not a new authorization mechanism. If Android revokes credentials, users must pair again.
- Permission-free normal split/window view stays available where Android allows it.
- Detached ADB bridge is still tied to app owner's binder. True backend death continues to trigger existing safety stop; app reconnect has explicit budgets.
- Third-party Shizuku license files remain as historical notices. Shizuku code is not copied or falsely represented as a built-in system API.

## Integration / verification
- Source changes on PR: removal of Shizuku provider, API calls, Shizuku menu; existing on-device ADB bridge is primary.
- Host CI checks Shizuku-free source references, local ADB source protections, WirelessModePolicy unit tests, and prior v1.152 virtual refresh tests.
- A production APK is NOT built or signed by source CI. Historic app source snapshot lacks some third-party JARs, ECJ archive, and generated UI translations; these must be resolved or a fully audited DEX overlay integrated into the genuine signed baseline.
- A signed Android 17 Pixel 10 test is still needed before claiming complete autonomy or replacing an existing APK link.
