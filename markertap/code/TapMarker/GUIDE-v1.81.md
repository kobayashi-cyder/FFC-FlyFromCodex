# MarkerTap v1.81 — Closeの認識・終了候補の切替・連打位置の離散化

パッケージ `jp.tapmarker.lite` / versionName `1.81` / versionCode `84`。
`MarkerTap-v1.81-ad-exits-discrete-taps.apk` を上書きインストールしてください。v1.80と同じ署名・パッケージです。アプリ削除は不要です。

## 広告から戻る操作

提供画像6716.pngの、左上の白い「Close」文字ボタンを追加しました。従来の×印・スキップ印に加え、左上・右上の限定した領域でCloseの文字形と明るい背景を確認します。上部の黒い余白と、対象アプリのウインドウ位置を考慮します。

ユーザー補助から取得できる「閉じる」「Close」「スキップ」などの終了候補も収集します。画素から候補が見つかっただけで他の候補の確認を打ち切らず、左右や同じ側にある別の終了候補を保持します。候補が複数見えることだけを理由に状態分岐を止めず、確認した一つへ入力します。

1. 新しい画像で終了候補を確認し、対象を一つ選びます。
2. 入力直前にも同じ候補の位置・表示・画像サイズを再確認します。
3. 送信後は800msの再入力待ちを設けます。送信完了を広告終了とは扱いません。
4. 次の取得画像にも終了候補が残る場合は、未試行の別候補を優先します。左から右、右から左、同じ側の別候補への切替に対応します。
5. 同じ終了位置は最大2回、1回の広告復帰で合計8回までです。候補を使い切ったら、既存の時間制限に従って戻る・登録アプリへの復帰へ進みます。
6. ゲーム画面を確認すると、次の広告用に試行回数を初期化します。

試行状態は実行画面ごとに独立しています。入力直前に選択候補が消えた場合は、前の候補や古い座標へ勝手に戻さず再判定します。古い画像も終了ボタンへの入力を許可しません。BANCから取得した同じ広告終了候補も、通常の終了処理へ集約し、別経路から同じ終了ボタンを繰り返すことを防ぎます。

「インストール」や広告内のプレイを代替の終了操作として選ぶ変更ではありません。新しい文字形モデルは提供された白地のCloseが対象で、全フォント・全配色のOCRではありません。

## 連打位置を離散化

離散化は、**実際に送る座標を1画素刻みの整数点へ確定すること**として実装しています。保存されたマーカーの表示位置ではなく、入力先へ送る接触位置が対象です。

- 小数画素の目標は最も近い画素へ丸めます。画面の右端・下端からはみ出さないよう範囲内へ収めます。
- 押下中の1点は固定し、目標位置の更新で動かしません。
- 1回の押す→離すが完了した後、次のマーカー位置へ独立したタップを送ります。位置間を押し続けてなぞりません。
- 同じ画素内の小さな認識位置の揺れでは、タッパーを作り直しません。
- 最速設定の1ms押下・1ms間隔要求は維持し、固定の待ち時間やランダムな位置変更を追加しません。実効速度は端末・Android・ゲームの入力受付に依存します。

元から独立していたタップの押下／解放を維持し、今回は座標の小数値の揺れを取り除いて入力点を固定しました。複数のマーカーはそれぞれ別の押下として扱います。登録済みのスワイプは連打の変更対象ではありません。

## 引き継ぎ

v1.80のコイン落としの任意CM視聴除外、ポット増加のキャンセル、通常タッパーと強化処理の分離を引き継ぎます。今回のClose・候補切替は標準の広告復帰処理に適用します。独自編集したグラフへの自動上書きは行いません。

上書き後に対象ゲームで「自動開始」を押してください。ユーザー補助が停止した場合はAndroid設定で「マーカー連打 軽量版」をOFF→ONにします。

## 確認した範囲

`AdExitSwitchTest` は、提供されたClose画像、合成した右側配置・縮尺・ウインドウ移動・同時候補・停滞時系列で72項目を検査します。文字欠落、インストール領域の除外、入力直前の消失、古い画像、左右・同じ側の別候補、試行上限、他画面への回数混入を含みます。

`DiscreteTapPositionTest` は15項目で、整数点への確定、境界内の位置、押下中の位置固定、解放後の次タップ、最速要求への余分な待ち時間がないことを検査します。入力ドライバーは非同期の模擬デバイスです。

既存core検査、コインのCM除外77項目、ポットキャンセル200項目も実行します。検査対象は配布APKと同じ縮小済みJavaランタイムです。APKの署名、旧版との署名一致、DEX・アセット・4種類のCPU向けライブラリ・16KB配置を検査します。

**F-52Aへの実入力と、この広告が実機で閉じることは未検証です。** 合成した時系列を実機の成功率としては扱いません。旧4録画のfull検査は別途フィクスチャを必要とします。
