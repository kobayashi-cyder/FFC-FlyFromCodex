# MarkerTap v1.151 — virtual lane isolation / preview lifetime candidate

Status: **source changes and host tests only; not a signed update**.
Base: v1.150 draft branch; APK shipping baseline remains the original pinned signed v1.144 until a new build is actually completed. Read `markertap/v1.145-physical-return/build.py` for strict SHA-256 input validation.

## Changes shipped in this candidate source
1. `VirtualFrameQueue` now holds up to **two in-flight screenshot requests** with one request per (generation, display ID). Global Android screenshot issue pacing remains 400ms. One callback can stall without blocking another display's **issuance** for the full original 2.5s timeout.
2. Late success/failure cannot finalize a removed or expired request; no image may be attributed to the other display or an earlier run generation.
3. A one-display removal clears only that display's queue entry. The existing backend-fatal policy remains intact: a genuinely removed virtual display still triggers the previous full-session safety stop. This change does not covertly relax owner-death cleanup.
4. `VirtualPreviewVisibilityBridge` transforms `View.GONE` into `View.INVISIBLE` when hiding the **phone-side** virtual preview. This retains measured view layout; it does not release or recreate the VirtualDisplay, ImageReader, input target or automation state. It is a mitigation experiment for the reported collapse/offline correlation, **not a verified network fix**.
5. The DEX integration patcher replaces the baseline `VirtualFrameQueue` (including `$Request`), redirects the virtual preview visibility call, and checks the original ABI and final bytecode against the exact overlay. It fails closed if the baseline methods or hooks differ.
6. `build.py`, `sign-release.py` and `release-local.py` have v1.151/versionCode154 and preserve the original update certificate and existing SHA safeguards.

## Validation
- `python3 markertap/v1.145-physical-return/run-tests.py` includes 30 screenshot-lane checks + 3 preview checks, as well as the inherited v1.150 suite.
- New CI workflow performs host tests, Java DEX patcher compilation and script syntax checks, **not** an Android device test or a signed release.
- Runtime integration requires exact v1.144 APK bytes (SHA-256 `f62e8d6020a3cacb2ea9a9085be235ea48da12f03c5de2f4e3ae80b801b6e970`), SDK35, JADX1.5.3 and the original private keystore. Never upload the key to GitHub.

## Remaining blockers / acceptance
- Compile the integrated APK from pinned baseline and verify changed DEX methods and original certificate; publish only the verified v1.151 **signed** asset.
- On Pixel 10 / Android17: test both 1 and 2 virtual displays, both physical and virtual controls, and each display's screenshot age/input counter; force one screenshot callback to stall and verify the second display still publishes.
- Collapse and expand **each** virtual preview while the game is online. Distinguish an app-side offline banner from a lost ADB/Shizuku binder and a stale or black frame. Verify the games keep progressing and rewarded actions are confirmed.
- Measure process memory/HardwareBuffer pressure. In-flight screenshot concurrency can increase peak memory and must be disabled or reduced for low-memory devices if it regresses stability. If Android screenshot throttling is hit, tune cadence rather than blindly shortening delays.
- Do not claim fully autonomous gameplay or a network fix without the above on-device evidence.
