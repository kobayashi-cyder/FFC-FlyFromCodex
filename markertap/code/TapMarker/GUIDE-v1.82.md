# MarkerTap v1.82 — F-52A向けの押下・解放と、離散した場所のランダム連打

パッケージ `jp.tapmarker.lite` / versionName `1.82` / versionCode `85`。
`MarkerTap-v1.82-f52a-input.apk` を上書きインストールしてください。v1.81と同じ署名です。アプリの削除は不要です。

## 場所は決めた点からランダムに選択

通常連打の各マーカーについて、**中央・左・右・上・下の5点**を作ります。周囲の点は中央から6dp離れた位置です。仮想画面ではその画面の密度に合わせて間隔を縮尺します。画面端では範囲内へ収め、同じマーカーの重複点を除きます。

タップするたびに、この有限個の点からランダムに1点を選びます。固定した順番や、5点を一周する順序は設けません。各回を独立に選ぶため、同じ点が続くこともあります。複数マーカーの場合は、それぞれの候補を合わせた集合から選びます。

選んだ点は整数画素へ確定し、**押している間は固定**します。解放してから次の点を選び、点の間を押したまま移動しません。連続値の座標をランダムに生成して散らす方式ではありません。保存済みのマーカー座標は書き換えません。

設定の「連打の場所」は、既定が「5点からランダム」です。「中央の1点に固定」も選べます。場所の選択は押下時間の設定から独立しています。

キャンセル・Close・強化などの1回のボタン操作と、記録済みスワイプには周辺点を追加しません。画面から確認した操作位置を使用します。

## F-52Aの押す時間と離す時間

「タップの押し方」は次の3種類です。

| 設定 | 動作 |
| --- | --- |
| 自動 | F-52Aでは離散入力。他機種は従来の最短入力。 |
| 離散入力 | 画面更新周期をもとに、押下と解放の時間をそれぞれ確保。 |
| 最短入力 | 従来どおり1ms押下を要求し、完了後すぐ次を送信。 |

60Hzでは、離散入力は**押下17ms以上＋解放17ms以上**、最小間隔34msです。最短入力より速度を抑え、短すぎる接触と解放時間ゼロを避けます。1ms設定のまま速度が変わったように見えないよう、操作パネルと「状況」に実際の選択方式・押下時間・解放時間・最小間隔を表示します。60msなどの長いボタン押下や、500msなどの遅い間隔指定は維持します。

間隔の「最速」は、選んだ押し方の処理が完了した時点で次を送る指定です。離散入力でも1ms間隔でゲームが受け付けるという意味ではありません。画面更新周期はゲーム内部の更新周期とは別で、ゲームの受付や効果を保証する値ではありません。

本体画面・仮想画面の通常連打へ適用します。判定エンジンとタッパーの分離、通常画面での継続連打、別イベントでの保留を引き継ぎます。

## 入力の待ちっぱなしと解除を修正

Androidの入力完了通知が欠落すると、従来は入力中のまま待機し続ける経路がありました。今回は、操作の長さ＋1秒、最低1.5秒の期限で通知待ちを終了し、失敗として画面を再確認します。遷移の成功としては扱いません。遅れて届く通知・重複通知は、その後の操作や状態を進めません。

ユーザー補助の入力は全体で1つずつ送ります。離散入力の解放時間も含めて順番を管理し、別のジェスチャーが前の入力を中断することを防ぎます。タイムアウト後は既存の入力失敗時の再確認・再試行を使います。

仮想画面のタップは、指の種別を明示したDOWNと、圧力0のUPを送ります。押下中に停止された場合はCANCELで解除し、その操作を完了したクリックとして数えません。停止状態は最大8ms刻みの待ちで再確認します。Android 11/12向けの対象画面・アプリ確認は維持します。

実行部の改修を確実に反映するため、実行部のリビジョンを85へ更新しました。通信の引数形式は変えていません。Shizuku方式は更新版の実行部を起動します。端末内接続・ADB方式で旧実行部と表示された場合は「端末だけで接続」から接続し直してください。

## 更新後の操作

1. APKを上書きインストールします。
2. アプリを開き、「タップの押し方」を「自動」、「連打の場所」を「5点からランダム」にします。これが既定値です。
3. 「タップが届くか10回確認」を開き、「10回送って確認」を押すと、このアプリの検査領域に入力し、実際に受信した押下・解放の回数を表示します。画面を離れると検査を中断します。ゲームの成功数ではありません。
4. 対象ゲームに戻り「自動開始」を押します。設定変更や受信確認では、自動実行はいったん停止します。

ユーザー補助が更新後に停止した場合は、Android設定で「マーカー連打 軽量版」をOFF→ONにしてください。仮想画面は端末内接続またはShizuku接続で開き直します。自動画像判定・仮想画面はAndroid 11以降が対象です。

コイン落としの任意CM視聴除外、ポット増加のキャンセル、左右のClose認識と終了候補の切替を維持します。

## 検証と限界

配布APKと同じ縮小済みJavaランタイムでcore検査を実行し、通過しました。新しい検査は次の内容です。

- `RandomTapTargetsTest`：再現可能な乱数で、有限点から毎回選ぶこと、固定順序にならないこと、押下中の位置固定、CMでの停止を確認。
- `DiscreteTapTargetsTest`：5点の位置、画面端の処理、複数マーカー、ウインドウ移動、座標範囲、ボタン1点の維持を確認。
- `F52AContactTest`：60/90/120Hzの模擬受信側で、押下と解放の両方が画面更新時に観測されることを各17通りの位相で確認。実ゲームのモデルではありません。
- `GestureDispatchGuardTest`：通知欠落・期限超過・遅延・重複・中断と、複数入力の競合を確認。
- `DiscreteTouchTest`：DOWN/UPの順序、遅い受付後の押下時間、停止・例外時のCANCEL、入力拒否を確認。

既存の広告終了、CM除外、キャンセル、Android 11/12形式の入力先確認の検査も通過しました。APKの署名と旧版との一致、DEX・アセット、4種類のCPU用ライブラリ、16KB配置も確認しました。

**F-52A実機は接続されていないため、この版の実機入力・ゲームでの反応・広告終了の成功率は未検証です。** 新しい受信確認画面の実機表示と受信も、この環境では検証していません。旧4録画を使うfull検査は別途フィクスチャが必要です。
