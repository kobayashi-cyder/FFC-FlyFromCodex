# MarkerTap v1.103：増えうさぎのミッション位置検出

`jp.tapmarker.lite` / versionName `1.103` / versionCode `106`

## 更新

1. 旧版で「全停止」を押します。仮想画面を利用中の場合は閉じます。
2. `MarkerTap-v1.103-mission-fix.apk` を上書きインストールします。
3. 対象アプリを開き直し、「自動開始」を押します。

v1.102と同じアプリ識別子と署名証明書で更新します。

## 原因と修正

録画6750.mp4の画像とv1.102の認識用見本を使って調べたところ、主画面を認識していても、ミッションボタンの位置が取得できないことを再現しました。

ミッションの見本には白いボタンの外の青空も含まれていました。ステージの進行で背景が緑や多数のうさぎに変わると、外側の色の差が照合に影響します。通常プレイをミッションのために保留していても、押下座標が取得できず、送信できない経路がありました。

- 増えうさぎのミッション位置は、白いボタン内の炎アイコンと中立色の文字の両方で確認します。外周の背景は照合から除外します。
- 主画面の位置補正後、ボタン付近の小さな範囲で現在の見え方を確認してから、従来の画面全体の探索へ進みます。
- ボタン自体が別位置へ移動する場合に備え、従来の輪郭を含む見本での探索も残します。どちらの探索でも炎と文字の確認を必要とします。
- 縮小表示で生じる文字の平均化と、16×16の見本での1セルの位置差を考慮します。
- 座標は画像ごとに取得します。ボタンが消えた際に、以前の座標を使い続けません。

入力直前の再撮影、主画面の確認、送信後のミッション画面の確認、開かなかった場合の再試行は既存の経路を使用します。今回の検査はそれらの経路まで通して行います。Androidの入力完了通知だけでミッションが開いたとは判断しません。

## 検証

`Video6750ReplayTest` は190項目を検査します。録画から27枚を抽出し、今回の録画で認識用見本を作り直すことなく、既存の見本で検証します。v1.102の実行クラスを使用すると、実際のミッションボタンの座標を取得する検査で失敗します。

検査内容は、録画のゲーム画面・広告・確認ダイアログ・ミッション画面、最小限の押下前再確認、模擬した入力完了後の確認状態、ゲーム画面が変化しない際の再試行です。ボタン・炎・文字の除去、縮小と補間、選択ウインドウの位置移動は合成条件です。

最終APKと一致する縮小済み実行クラスでの回帰結果、署名、APK内の内容、認識用見本の同一性は `VALIDATION-v1.103.json` と `tests-v1.103.log` に記録します。

Android実機は接続していません。端末上での実タップ配送、広告後の長時間稼働、報酬獲得は未確認です。録画による認識検査と実機での操作成功は区別してください。

## 再ビルド

Java 17、Android SDK platform 35 / build-tools 35.0.0、Python3、ripgrep、C/C++コンパイラを使用します。署名鍵は別途必要です。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE=/path/to/original-key.jks \
bash build.sh

ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

テスト用画像の再抽出は `python3 tests/prepare-video6750.py /path/to/6750.mp4` です。
