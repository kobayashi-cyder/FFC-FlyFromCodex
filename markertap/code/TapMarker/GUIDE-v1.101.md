# MarkerTap v1.101

`jp.tapmarker.lite` · versionCode `104` · 更新対象：v1.100

## 更新する

1. 旧版で「全停止」を押し、仮想画面を閉じます。
2. `MarkerTap-v1.101-stable-ui.apk`を上書きインストールします。
3. ユーザー補助と端末内接続を確認し、対象アプリを選んで仮想画面を開き直します。
4. 「自動開始」を押します。

配布APKはv1.100と同じ証明書で署名します。アプリの識別子は同じで、設定の初期化は行いません。

## 動作の修正

| 場面 | 修正内容 |
| --- | --- |
| ストアなどが自然に閉じ、対象ゲームへ戻った | 復帰要求の成功通知がなくても、異なる新しい画像2枚と表示アプリを確認して待機を解除。画像の間隔は500ms以上とし、解除後にゲーム画面を再判定する |
| 復帰要求が失敗した後、手動またはAndroid側でゲームへ戻った | 試行上限に達した画面も同じ確認で再判定へ戻る。失敗回数は実際の入力成功まで保持する |
| 一瞬だけ別アプリのシートが出た | 新しい画像で750ms以上の継続を確認してから表示変更による復帰待ちへ入る。実際の入力直前の対象アプリ確認は継続する |
| ポイポイ・買い物・コインでミッション回収中に復帰した | 通常プレイ用の判定へ一律に戻さず、回収中の経路を保持する。ゲーム別の状態と試行回数は独立させる |

解除時に直ちに連打を始めるわけではありません。既存の画像条件で主画面と操作先を確認してから入力します。独自編集と学習済みのオートマトンは、元の状態を保って再観察します。

## UI

- アプリを「ホーム・設定・作成」の3画面へ整理。長い説明と設定を開始操作の下へ連続表示する構成を変更しました。
- ホームには、実行状態・各画面の状態・対象アプリを表示します。「自動開始／自動停止」「全停止」「操作パネル」を配置しました。
- 操作パネルは上部の状況をドラッグして移動できます。位置を保存します。初回は画面下側へ配置し、仮想画面の初期配置ではパネル用の余白を確保します。
- 「対象・画面・詳細」を常時表示し、学習・マーカー・接続・編集の操作は「詳細」内でスクロールできます。開始操作と全停止はスクロールの外にあります。
- 小窓の見出しはアプリ名と状態を2行に分離。タップするとその画面の状況を開きます。
- 狭い縮小表示は短いアプリ名を使い、閉じるボタンを見出しの状況画面へ移します。100%・75%・50%・35%・最小表示を維持します。
- 配置方式は端末内接続・接続済み仮想画面・PCを先に表示し、従来の追加方式は「その他の表示方式」から開きます。端末側の仮想画面は2つを上限に起動します。

## 検証

- `RecoveryContinuityTest`：29項目。旧版v1.100のクラスに差し替えると、自然復帰後に待機を解除できない条件で失敗することを確認しました。
- 既存の検査を含む108組のJVM検査と、8件の模擬ADBシナリオが合格しました。
- UIの最終調整後、配布対象ランタイムで復帰・録画6745・縮小座標・自律開始・農園フィーバーの関連検査を再実行して合格しました。
- Android実機は未接続です。UIの実機表示、実タップ、広告からの連続復帰成功率は未確認です。録画画像の検査と実機での成功は区別してください。

詳細な実行結果は`VALIDATION-v1.101.json`と`tests-v1.101.log`を参照してください。

## 再ビルド

Java 17、Android SDK platform 35 / build-tools 35.0.0、Python3、ripgrepを使用します。署名鍵は別途必要で、ソースには含めません。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk \
TAPMARKER_KEYSTORE=/path/to/original-key.jks \
bash build.sh

ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```
