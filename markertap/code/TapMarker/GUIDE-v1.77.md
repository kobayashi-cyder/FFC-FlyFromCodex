# MarkerTap v1.77 — タッパー分離・最速連打

パッケージ `jp.tapmarker.lite` / versionName `1.77` / versionCode `80`。
`MarkerTap-v1.77-separated-fast-tapper.apk` を上書きインストールしてください。署名はv1.76と同じです。アプリ別のマーカー、学習済みグラフ、BANC設定を引き継ぎます。仮想実行部の通信プロトコルは75を維持します。

## 使い方

1. 上書き後に実行パネルが出ない場合は、Androidのユーザー補助で「マーカー連打 軽量版」をOFF→ONにします。
2. 対象ゲームを表示します。パネルの「展開」→「間隔」を押し、表示を「最速」にします。旧設定の3msは最速として読み替えます。50/100/250/500/1000msの保存済み設定は維持します。
3. 通常運用は「自動開始」です。ロジカルエンジンが画面を判定し、連打の開始・停止・位置の更新を指示します。
4. 「全停止」で判断処理とタッパーを停止します。

F-52AのAndroid 11/12で複数ゲームを動かす場合は、既存の仮想画面方式を使用します。「既に表示したウインドウで開始」はAndroid 14以降の方式です。

## タッパーと判断処理の分離

| 部分 | 担当 |
| --- | --- |
| ロジカルエンジン・MarkerTapLogic | 画面認識、状態遷移、操作先・位置・開始・停止・指示期限の決定 |
| Tapper | 指示された位置への連続入力、入力完了を待つ制御、入力中断の再試行、停止指示と期限切れの処理 |
| AndroidTapDriver | Androidへの実入力、本体・仮想画面の入力先確認、入力結果の返送 |

Tapper本体はAndroid、PhaseEngine、画像処理に依存しません。通常連打の1回ごとに画面認識を呼び出す構造を外しました。本体の通常連打と、複数・仮想画面の通常連打で同じTapperを使用します。学習済みの単発操作・スワイプは、既存の操作順序・操作後確認に従います。

## 最速の意味

- 通常連打の押下要求は1ms、設定上の間隔下限は1msです。F-52A向けの旧32ms下限と、画像処理の負荷設定による速度制限を通常連打から外しました。
- Androidが前の入力を完了したら、追加の固定待機を入れずに次を送ります。同じ画面でDOWN/UPを重ねて送信しません。
- 実際の間隔はAndroidの入力処理、画面数、端末負荷、対象ゲームによって決まります。1msという要求値から実際の受付速度は確定できません。
- 「状況」に、タッパーごとの直近の送信完了回数／秒を表示します。連続実行が1秒続くと更新されます。この数値はAndroid・入力実行部の送信完了であり、ゲームの得点・報酬・内部受付回数ではありません。
- パネルが入力先に重なる場合は、透過切替の待ち時間が必要です。パネルを入力先から離すと、その待ちを避けられます。

自動運用ではCM・ダイアログ・状態遷移の検出時に判断側が連打指示を取り消します。判定画像が1.5秒以上古くなった場合も指示が切れます。新しい画像で通常プレイを確認すると再開します。

## タップしない場合の切り分け

本体画面のパネルに、次の2つの操作を追加しました。

- **タップ確認**：対象アプリに置いた最初のマーカーへ、60msのタップを1回だけ送信します。画面認識の一致を必要とせず、入力経路・座標を確認します。自動運用を停止して実行します。
- **連打のみ**：判断処理を停止し、登録したマーカーを独立したタッパーで連打します。通常プレイやCMの画像判定は行いません。入力だけの確認に使い、「全停止」または再度「連打のみ」で止めます。対象アプリが変わった場合や保護対象の表示では入力を保留します。

マーカーがない場合は「追加」で押したい位置に1個置き、「完了」を押してから確認します。仮想画面の単発入力は、展開したプレビューの押したい場所を直接タップします。仮想画面の自律運用は「自動開始」を使用します。

「状況」では、通常画面の認識待ち、画像が古い、操作結果待ち、対象アプリ待ち、Androidへの要求・完了・中断・拒否を区別できます。「コピー」で状況を取得できます。

60msの単発確認は反応するが最速連打には反応しない場合は、ゲーム側の押下時間条件を追加調査する必要があります。送信完了だけでゲームの操作成功と扱いません。

## 再試行と停止

一時的な入力中断・送信拒否では、250/500/1000msの待機で最大3回再試行します。対象アプリ・画面範囲が変わった場合は古い位置へ再試行しません。期限・停止・位置変更後の遅延コールバックは、新しい指示を進めません。継続できない場合は状況に理由を残します。

## 検証範囲

- 配布APKに変換する縮小済みJavaランタイムで既定の回帰検査を実行。
- TapperTest：非同期の模擬入力装置で、最速送信、遅い入力装置の完了待ち、設定間隔、指示更新、期限切れ、CM停止、古いコールバック、座標更新、重複コールバック、再試行上限、単発操作、画面別の分離を確認。
- TapInputPolicyTest：端末・画像負荷設定から独立した入力時間、明示的な低速設定、再試行、認識待ちの診断を確認。
- 既存の通常連打・CM・復帰・録画・BANC・暗号・模擬ADBの回帰検査を実行。
- APKの署名、バージョン、DEXとビルドの一致、アセット、4種類のCPU向けライブラリ、16KB配置を検証。

F-52Aを含むAndroid実機のタップ受付・画面操作・実効速度は未検証です。模擬入力装置の時間をAndroid実機のベンチマークとしては扱いません。過去4録画のfull検査は、従来通り別途の大容量フィクスチャが必要です。

## 再ビルド

Java17、SDK platform35、build-tools35.0.0。

```bash
ANDROID_SDK_ROOT=/path/to/android-sdk TAPMARKER_KEYSTORE=signing/lite-development.jks bash build.sh
ANDROID_SDK_ROOT=/path/to/android-sdk bash run-tests.sh
```

成果物と検証記録：`tests-v1.77.log`、`VALIDATION-v1.77.json`、`apk-verification-v1.77.log`。
