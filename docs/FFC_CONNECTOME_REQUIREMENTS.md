## 今回の処理

意味分類・技能検索・診断アダプタ → 権限で候補を絞る → 工学的入力対応 → BANC集約有向回路で再帰伝播 → 工学的出力対応 → ツール実行 → 観測報酬 → 選択出力の上流辺を局所更新。

伝達物質からの符号はCPFの仮定を継承する。抑制性活動も絶対値で読み出す。この読み出し、漏れ、tanh、報酬則は工学的モデルであり、ハエの実測生理ではない。候補ごとに独立して伝播し、候補の列挙順や直前候補の活動が結果に混入しない。

専門分類・獲得スキルが候補を1つだけ提示する経路では、回路は実行ゲートになる。候補が複数ある経路では活動が順位を決める。これだけで汎用認知や意味理解の主体が全て生物回路へ移ったとは言えない。今後は適切な複数提案と回路内記憶を増やし、分類器を固定した比較で効果を検証する。

回路が未ロード・切断されて出力がない場合、代理人は実行を停止する。旧HTMLのToolBus候補選択も同じ回路へ接続する。手動で直接ツールを呼ぶUIと低水準実行APIは身体インターフェースであり、この選択器の対象外。

## 「AIに負けない」の受入条件

まず評価課題、対象AIの版、データ分割、許容誤差、端末、計算予算を決める。課題成功率が比較対象に対して事前に決めた許容差以内で、さらに学習例数・外部呼出数・遅延または電力の少なくとも1項目で優位を示すことを候補条件とする。乱数seedを変えた複数試行と信頼区間を報告する。

評価中は学習を停止する。切断・接続シャッフル・学習なし・旧スカラー選択・外部AIのみを比較し、性能改善が接続構造に由来するか分離する。活動が出ることと課題に正答することは別である。本変更はAI超越の実証ではない。

## 起動処理の改善

Android統合検査の初期化失敗を調査し、デモ画像生成・教師リスト生成・演算体の事前コンパイル・自己テストが起動時に重なる問題を確認した。生成や自己テストは既存のユーザー操作・ツール要求で実行し、起動時は軽量なUIと保存状態の復元を行う。

CPUを6倍に制限したローカルChromiumで、同じ読み込み手順が約18秒から約1.6秒になった（単一試行の診断値。実機の性能保証ではない）。実ブラウザーで計算2+3=5、回路trace、2回の成功からの獲得スキル再利用を確認した。

CIでは外側タイムアウトを120秒にし、ADB終了コードに加えてinstrumentationの明示的な成功要約を必須にした。これにより以前の検査が見逃していたassertion failureも失敗として報告する。
